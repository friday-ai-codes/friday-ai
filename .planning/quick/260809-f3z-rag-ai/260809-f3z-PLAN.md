# Quick Task 260809-f3z — 建仓自动入队：索引 / AI 描述 / 章程

## 背景（已核实，勿重新调研）

### 现状缺口

| 路径 | 现状 | 文件 |
|------|------|------|
| `_acreate_repository_core` | 建仓成功后**只** `enqueue_repo_summary`，且**无** `initiated_by_user_id` | `server/repositories/views.py` ~531–537 |
| 注释 | 写着「AI 描述 + PageIndex 索引」，实际未入队代码索引 | 同上 |
| 代码/RAG 索引 | `durable_index` → `run_index` → `clone_and_index_repository`；图谱由 indexer 内 `_should_build_graph` + `auto_after_index` 内联触发 | `durable/tasks.py`、`tasks_impl.py`、`services/indexer.py` |
| AI 描述 | `enqueue_repo_summary` → `durable_repo_summary` → `dispatch_repo_summary`；完成回写 `_update_repository_on_summary_complete` | `summary_service.py`、`subagent/api/callbacks.py` |
| 章程 | 仅手动 `POST .../charter/draft/` → `adraft_charter`；依赖 summary/facets 证据质量 | `charter_service.py`、`charter_views.py` |
| AgentSession 归因 | `dispatch_repo_summary` 创建 `AgentSession` **未设** `user` → `_resolve_initiated_user` 对 repo_summary 恒为 `system` | `summary_service.py`、`callbacks.py` |

### 目标流水线（设计已定）

```text
Create Repository (fast, transactional)
  ├─ durable_index (RAG；图谱仅当 ENABLE_CODEGRAPH ∧ auto_build_graph_enabled → auto_after_index)
  └─ durable_repo_summary (AI 描述)
         └─ (callback 成功 asave 后) durable_charter_draft → adraft_charter
```

### 执行期硬约束

1. **建仓保持快**：入队 best-effort，失败不抛、不回滚已创建的 Repository。
2. **禁止**在建仓或 summary callback 内直接调用 LLM / `adraft_charter`（callback 只 `defer`）。
3. **禁止**建仓时额外 `defer("durable_graph")`——避免与 indexer `auto_after_index` 双跑。
4. **禁止**为「保证有图谱」强开 `ENABLE_CODEGRAPH` 或改写 `_should_build_graph` 语义。
5. **保留未提交改动**：尤其 `charter_service` release-link、`RepoCharterSection` UI（`260809-3kc` / `260809-charter-release-link`）。本任务只**追加**入队/任务壳，不 revert、不重写 `_agenerate_draft` / prompt / UI。
6. **不 commit**（用户明确要求）；不改 ROADMAP。

### Claude's Discretion（实现选型，已定）

- 新建 `enqueue_repo_index` / `enqueue_charter_draft` 薄 helper（镜像 `enqueue_repo_summary`），避免继续在 `views.py` 堆 defer 样板。
- 新队列 `QUEUE_CHARTER = "charter"` + 任务名 `durable_charter_draft`；并发用 `charter-slot-{n}`，默认并发 **4**，复用或镜像 `CONCURRENCY_SUMMARY_MAX` 读取模式（可新增 `SettingKeys.CONCURRENCY_CHARTER_MAX`，缺省回退 4——不必迁移种子）。
- IndexHistory `trigger_type=TriggerType.MANUAL`，durable payload `trigger="create"`（可观测建仓来源；`run_index` 本来也不转发 trigger）。
- Summary → Charter 归因：在 `dispatch_repo_summary` 把合法 `initiated_by_user_id` 写入 `AgentSession.user_id`；callback 用已有 `_resolve_initiated_user(session)` 传入 charter 入队（绝不信任 runner 可改的 `last_output` 用户字段）。

## 任务

### Task 1 — 建仓：入队 full index + AI summary（含创建者归因）

**files:**  
`server/repositories/index_enqueue.py`（新建）、  
`server/repositories/summary_service.py`、  
`server/repositories/views.py`、  
`server/durable/tasks_impl.py`（仅 `run_repo_summary` → 透传 `initiated_by_user_id` 给 dispatch，若签名扩展）

**action:**

1. **新建** `enqueue_repo_index(repository_id: str, *, initiated_by_user_id: str | None = None, trigger: str = "create") -> str | None`：
   - 仓库不存在 / 已 `INDEXING` → 跳过并打采样/info 日志，返回 `None`。
   - 否则：`IndexHistory` RUNNING（`TriggerType.MANUAL`）+ `aupdate` 仓库 `index_status=INDEXING`、清空 error/进度计数（对齐 `_schedule_index` / reindex-all 最小集合，勿复制默认分支滚动那套 stale 逻辑）。
   - `DurableTaskService.defer("durable_index", {repository_id, history_id, branch: None, trigger}, queue=QUEUE_INDEX, idempotency_key=f"index:{repo_id}", lock=await aindex_lock(repo_id), initiated_by_user_id=...)`。
   - 整段 try/except：失败 `enqueue_repo_index_failed`（`category=caller`，`component=repositories`，`error=redact_secrets_in_text`），返回 `None`，**不抛**。
2. **扩展** `enqueue_repo_summary(repository_id, *, initiated_by_user_id: str | None = None)`：defer payload / `initiated_by_user_id=` 传入；保留 `idempotency_key=f"summary:{repo_id}"` + `asummary_lock`；失败仍 swallow。
3. **扩展** `dispatch_repo_summary(repository, *, initiated_by_user_id: str | None = None)`：创建 `AgentSession` 时若 `initiated_by_user_id` 可解析为存在的 User PK，则设 `user_id=`；非法/空 → 不设（worker 仍 bind system）。`run_repo_summary` 把 durable payload 中的 `initiated_by_user_id` 原样传给 dispatch。
4. **改** `_acreate_repository_core`（`views.py`）：事务性建仓逻辑不动；成功后：
   - `actor_id = str(getattr(actor, "id", "") or "") or None`
   - 并行语义上先后 `await enqueue_repo_index(..., initiated_by_user_id=actor_id)` 与（既有条件）`await enqueue_repo_summary(..., initiated_by_user_id=actor_id)`。
   - 观测：`repo_create_pipeline_enqueued`（`category=caller`，`component=repositories`，字段：`repository_id`、`initiated_by_user_id`、`index_job`/`summary_job` 是否非空、`duration_ms`）。**禁止**单独 `durable_graph`。
5. 更新注释：删掉误导性「PageIndex 索引」措辞，改为「代码索引(RAG+条件图谱) + AI 描述」。
6. 既有测试里 `patch("repositories.summary_service.enqueue_repo_summary")` 的 batch/token 用例：若 create 路径新增 `enqueue_repo_index`，同步 patch `repositories.index_enqueue.enqueue_repo_index`（或 views 导入路径），避免测试真入队。

### Task 2 — durable_charter_draft 任务 + summary 成功回调串联

（**只调用**既有 `adraft_charter`；⛔ 不改 `charter_service` 蒸馏/release-link/UI 逻辑）

**action:**

1. **队列**：`QUEUE_CHARTER = "charter"` 加入 `ALL_QUEUES` + `__all__`。
2. **并发**：`DEFAULT_CHARTER_CONCURRENCY = 4`、`charter_slot_lock` / `acharacter_lock`（命名可用 `acharacter_lock` 或 `acharacter_draft_lock`，与现有 `asummary_lock` 同构）；setting key 自定，缺省 4。
3. **任务壳**：
   - `durable/tasks.py`：`@app.task(name="durable_charter_draft", queue=QUEUE_CHARTER)` → `run_charter_draft(...)`。
   - `handlers.py`：`register_handler("durable_charter_draft", _charter_draft)`（`**payload` 展开）。
   - `tasks_impl.run_charter_draft(*, repository_id, initiated_by_user_id=None)`：
     - `bind_task_context(user_id=..., source="durable", component="charter_service")`。
     - 调 `adraft_charter(repository_id, initiated_by_user_id=initiated_by_user_id or "system")`。
     - `DoesNotExist` → `{"status":"skipped","reason":"not_found"}`；返回 `None`（LLM 不可用）→ `skipped/llm_unavailable`（**完成 job，勿无限重试**）；`CharterPersistError` → 记 failed 后 **re-raise** 或返回 failed 供 stalled 可见（二选一写清并测）；其它异常脱敏 warning + 返回 failed，**恒不把明文凭证写入日志**。
     - 生命周期事件：`charter_draft_job_started/completed/failed`，`category=caller`，带 `duration_ms`、`repository_id`、`initiated_by_user_id`（业务细节已有 `charter_draft_*` 可并存，勿删 service 内事件）。
4. **入队 helper** `enqueue_charter_draft(repository_id, *, initiated_by_user_id: str | None = None) -> str | None`：
   - `idempotency_key=f"charter:{repository_id}"`，`lock=await acharacter_lock(...)`，`queue=QUEUE_CHARTER`。
   - best-effort：失败 swallow + `enqueue_charter_draft_failed`。
5. **回调串联**：在 `_update_repository_on_summary_complete` 于 `await repo.asave(...)` **成功之后**（已写 `ai_summary_status=completed`）：
   - `initiated = await _resolve_initiated_user(session)`。
   - best-effort `await enqueue_charter_draft(str(repo_id), initiated_by_user_id=initiated)`。
   - 观测：`repo_summary_charter_enqueued`（`category=caller`，`component=repositories` 或 `charter_service`，含 `repository_id`、`initiated_by_user_id`、是否拿到 job id）。
   - **禁止**在 callback 内 `await adraft_charter`；异常吞掉，不改变回调 200 / 主回写。
6. 失败回写路径 `_update_repository_on_summary_fail`：**不**入队 charter。

## 威胁模型（简）

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-f3z-01 | Elevation | callback → charter enqueue 用户归因 | mitigate | 仅用 `_resolve_initiated_user` / `AgentSession.user`；不采信 `last_output` 用户字段 |
| T-f3z-02 | DoS | 建仓洪峰 LLM/索引 | mitigate | 既有 index/summary/charter slot lock + idempotency_key |
| T-f3z-03 | Info disclosure | 入队/job 日志 | mitigate | `redact_secrets_in_text`；payload 仅 id，无 token |
| T-f3z-04 | Tampering | human_confirmed 章程 | mitigate | 只走 `adraft_charter`（P11 只写 `draft_content`） |

## 成功标准

- [ ] 新建仓库后 durable 可见 `index:{id}` 与 `summary:{id}` 在途/完成任务，且 payload 含创建者 `initiated_by_user_id`
- [ ] 无独立 `durable_graph` 建仓入队；图谱关闭设置下索引完成不强制建图
- [ ] summary 成功回写后出现 `charter:{id}` 任务；callback 延迟不因 LLM 拉长
- [ ] 人工确认章程后自动起草不覆盖正式字段
- [ ] 工作区既有 charter UI / release-link 未提交改动保持完好
- [ ] 未产生 git commit（本 quick 规划与执行均按用户要求不提交，除非用户后续另行要求）

## 非目标

- 不改前端；不改 ROADMAP；不做历史仓回填；不把 PageIndex/corpus 全量树重建绑到建仓关键路径（summary 回调里既有 tree 后处理保持原样即可）。
