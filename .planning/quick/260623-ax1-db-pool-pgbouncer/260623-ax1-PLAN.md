# Quick Task 260623-ax1：数据库连接池 + PgBouncer

## 背景

Django async ORM 默认 `sync_to_async(thread_sensitive=True)` 把全进程 ORM 串行到一根
线程；叠加「无连接池」在高并发重活下会接口假死（见 `graph_writer.py` 线上事故修复）。
Django 6.0 官方 async 指引：async 模式应禁用持久连接（`CONN_MAX_AGE`），改用数据库
后端自带连接池。

本任务落地 **Phase A（连接池）** 并补齐 **PgBouncer 支持**。进程角色分离
（server/worker/scheduler）此前已完成。

## 关键约束（红线）

1. **默认零回归**：SQLite / MySQL 完全不动（dev/pytest 用 SQLite）。未设
   `DATABASE_URL_DIRECT` 时 worker/scheduler 行为与今天字节一致。
2. **worker/scheduler 必须直连 Postgres**：Procrastinate 依赖 `LISTEN/NOTIFY`，
   穿不过 PgBouncer transaction pooling。
3. **PgBouncer opt-in**：compose 走 `profiles: [pgbouncer]`，helm 走
   `pgbouncer.enabled=false`，不强翻现网拓扑。

## 设计

### settings.py（角色感知连接池）
- 仅 PostgreSQL 生效：`CONN_MAX_AGE=0`（pool 与持久连接互斥）。
- `DB_PGBOUNCER=true`（web 置于 PgBouncer 后）：`DISABLE_SERVER_SIDE_CURSORS=True`
  + 不叠加 psycopg 应用层池（由 PgBouncer 复用）。
- 否则（直连）：启用 psycopg3 应用层池 `OPTIONS["pool"]`（Django 5.1+ 原生），
  尺寸 env 可调（`DB_POOL_MIN_SIZE`/`DB_POOL_MAX_SIZE`/`DB_POOL_TIMEOUT`）。

### docker-compose.yaml
- 新增 `pgbouncer` 服务（`profiles: [pgbouncer]`，transaction 模式，
  `max_prepared_statements>0` 兼容 psycopg3 预编译）。
- worker/scheduler 的 DB URL 改 `${DATABASE_URL_DIRECT:-${DATABASE_URL:-<direct>}}`
  —— 未设 `DATABASE_URL_DIRECT` 时与今天完全一致（向后兼容）。
- server 增加 `DB_PGBOUNCER=${DB_PGBOUNCER:-false}`。

### helm
- values 增加 `pgbouncer.enabled=false`（默认 off=零影响）+ 镜像/资源。
- 新增 pgbouncer deployment/service 模板（gated）。
- `_helpers.tpl`：server DB URL（enabled 时指向 pgbouncer）vs worker/scheduler
  DB URL（恒直连 postgres）。

### .env.example
- 文档化连接池 env + PgBouncer 启用步骤（含 worker 直连提醒）。

### 测试
- 单测断言：postgres+直连 → 有 `OPTIONS.pool` 且 `CONN_MAX_AGE==0`；
  postgres+`DB_PGBOUNCER` → `DISABLE_SERVER_SIDE_CURSORS` 且无 pool；
  SQLite → 完全不变。
