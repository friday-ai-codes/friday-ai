# Quick Task 260809-3kc — 仓库章程详情 UI

## 背景（实测结论，勿重新调研）

### 已有后端（Phase 111 / CHARTER-01）

| 端点 | 行为 | 文件 |
|------|------|------|
| `GET /api/repositories/<uuid:repository_id>/charter/` | 读取；无章程 → **404** `{"detail":"章程不存在"}` | `charter_views.RepoCharterDetailView` |
| `POST .../charter/draft/` | AI 三源蒸馏起草；仓库不存在 404；LLM 不可用 503；落库失败 500 | `RepoCharterDraftView` → `adraft_charter` |
| `POST .../charter/confirm/` | 人工确认，body 可选 `{"edits":{...}}`；**章程不存在 → 404** | `RepoCharterConfirmView` → `aconfirm_charter` |

- 模型：`RepoCharter`（OneToOne `Repository`），字段 `positioning` / `owned_domains` / `boundaries` / `placement_preferences` / `audience` / `form` / `evolution` / `draft_content` / `source` / `version` / `confirmed_by`。
- 写入纪律（INV-6）：唯一 writer 白名单 = `charter_service.py` + `charter_draft_writeback.py`；视图禁止直接 `RepoCharter.objects.create/save`。
- 序列化：`RepoCharterSerializer` **全字段 read_only**；状态只经 service 变更。
- 观测（已有）：`charter_draft_started/completed/failed`、`charter_confirmed`（`category=caller`，`component=charter_service`）。

### 缺口（本任务要补）

1. **无「从零人手创建」写路径**：`aconfirm_charter` 在 charter 不存在时 `raise ValueError` → API 404。新仓若 AI 起草失败（503）或用户想跳过 AI，**无法**维护章程。
2. **前端无详情面**：仅有 `getRepositoryCharter`（引用预览用，失败恒 `null`）与 `CitationCharterPreview.vue`；`pages/repositories/[id]/index.vue` 无章程分区。
3. **建仓后无章程引导**：`CreateRepositoryModal` 成功后 `router.push(/repositories/${id})`，无 `#charter` 锚点。

### 执行期约束（必守）

- **禁止覆盖**工作区未提交改动：`server/repositories/services/charter_service.py` 当前有未提交 diff（上线记录进 prompt、关联状态扩到 `confirmed/verifying/verified/rejected`、`acquire_llm_slot` 等，属 `260809-charter-release-link`）。本任务只**追加**「无行时按 edits 创建」逻辑与观测字段，**不要** revert / 重写 `_agenerate_draft` / `_build_prompt` / `_load_associations`。
- 同样勿动 `mcp/`、`skills/`、`.planning/quick/260809-charter-release-link/` 等未提交产物。
- 不改 ROADMAP；完成后更新 STATE.md「Quick Tasks Completed」表即可（由 executor 做）。

### Claude's Discretion（实现选型，已定）

- **不新开第四端点**：扩展既有 `POST .../charter/confirm/` + `aconfirm_charter`——当 charter 不存在且 `edits` 为非空 dict 时，经 `normalize_charter_draft(edits)` 直接 `create(source=human_confirmed, version=1, confirmed_by=user, …)`；无 edits 的空确认仍 404（保持 `test_confirm_no_charter_404` 语义：空 body 不创建）。
- UI 落在详情「基本信息」区、`AISummarySection` **下方**（与意图面/摘要并列），AnchorNav 新增 `charter` 项。
- 列表字段（owned_domains / boundaries / placement_preferences）用简易可编辑行（domain/rule/target + 可选 note），形状对齐 `normalize_charter_draft` 白名单；非法 evolution 由后端回退，前端用 select：`active` | `maintenance_only` | `deprecated`。

## 任务

### Task 1 — 后端：confirm 支持「无章程 + edits → 人手创建」

**files:** `server/repositories/services/charter_service.py`, `server/repositories/charter_views.py`（仅 docstring/注释若需对齐）, `server/tests/repositories/test_charter_service.py`, `server/tests/repositories/test_charter_api.py`

**action:**

1. 在 `aconfirm_charter` 的 `_confirm()` 事务内（`select_for_update` 之后）：
   - 若 `charter is None`：
     - `edits` 非 dict 或空 dict → 仍 `raise ValueError("章程不存在，请先生成草案")`（API 继续 404）。
     - 否则：校验仓库存在（`Repository.objects.filter(pk=repository_id).exists()`，不存在同样 ValueError/404）；`normalized = normalize_charter_draft(edits)`；`RepoCharter.objects.create(repository_id=..., source=HUMAN_CONFIRMED, version=1, confirmed_by=user, draft_content={}, **白名单字段)`；返回该行。
   - 若 charter 已存在：保持现有「提升 draft_content → 套 edits → version+1 → HUMAN_CONFIRMED → 清 draft」逻辑不动。
2. 观测（遵守 `.cursor/rules/observability-logging.mdc`）：
   - 成功路径：现有 `charter_confirmed` 增加字段 `created`（bool，区分新建 vs 确认既有）与 `duration_ms`（函数入口记 `started`）；`category="caller"`，`component="charter_service"`，`initiated_by_user_id=str(user.id)`，`repository_id=`。
   - 失败路径（best-effort，不反噬）：捕获非预期异常时记 `charter_confirm_failed`（`category=caller`，脱敏用 `redact_secrets_in_text`），再 re-raise；ValueError「不存在」不必当 failed 刷屏。
   - **不要**把 edits 全文或凭证写入日志。
3. 视图层：`RepoCharterConfirmView` 行为可不变（仍委托 service）；更新模块 docstring，写明「无行 + 非空 edits → 创建 human_confirmed」。
4. **禁止**在 view 里 `RepoCharter.objects.create`（INV-6 扫描会红）。
5. 测试：
   - service：`test_confirm_creates_when_missing_with_edits`（断言 source/version/confirmed_by/字段）；`test_confirm_missing_without_edits_raises`。
   - API：`test_confirm_creates_charter_with_edits_when_absent`（200，`source==human_confirmed`，`version==1`）；保留并继续通过 `test_confirm_no_charter_404`（空 body）。
   - 既有 draft→confirm、AI 不覆盖人工用例不得被破坏。

**verify:**

```bash
cd server && uv run pytest tests/repositories/test_charter_service.py tests/repositories/test_charter_api.py -x -q
```

**done:** 无章程仓可用 `POST .../confirm/` + `edits` 一次落成 `human_confirmed`；空 confirm 仍 404；观测含 `created`/`duration_ms`；INV-6 测试仍绿。

### Task 2 — 前端：API 封装 + `RepoCharterSection` 可见可编可确认

   - 保留 `getRepositoryCharter` 的「恒不抛 → null」语义（引用预览依赖）。
   - 新增显式错误抛出的写方法（详情页要用 toast）：
     - `draftRepositoryCharter(repositoryId)` → `POST /repositories/${id}/charter/draft/`
     - `confirmRepositoryCharter(repositoryId, edits?)` → `POST /repositories/${id}/charter/confirm/`，body `{ edits }`（有 edits 时）

   - 加载：`fetchRepositoryCharter`；404/空 → 空态文案「尚未建立仓库章程」+ 两个动作：「AI 起草」「手动填写」。
   - 只读展示：`positioning`、owned_domains、boundaries、placement_preferences、audience、form、evolution、`source`/`version`/`confirmed_by`；若 `draft_content` 非空，单独区块「待确认修订草案」对比展示。
