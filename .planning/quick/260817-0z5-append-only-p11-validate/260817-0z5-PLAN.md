## Claude's Discretion (locked for this plan — checker-hardened)

### Fingerprint persistence (blocker 1)

- After **every successful automated gated handling**, persist `baseline_fingerprint = observed_fingerprint`, including when classify yields an **empty delta**.
- On first gated touch of a legacy row (`baseline_locked_at is NULL`), also set `baseline_locked_at=now` without rewriting formal body (D-06).
- When observed fingerprint **equals** stored: skip appendices/proposals growth; still allowed to no-op-save fingerprint (idempotent) and set `locked_at` if NULL; emit `charter_material_change_skipped`.
- Callback/durable paths pass the fingerprint computed from current overview/tree/facets. Manual draft and blueprint writeback paths that omit it compute the same fingerprint from the current `Repository`; if evidence is unavailable, they preserve any stored non-empty fingerprint and never replace it with `""`.
- Regression required: repeated identical fingerprint → appendices/proposals length unchanged; fingerprint column remains the observed value.

### Classification rules on existing row (blockers 2 + 5) — no ambiguity

Automation on an **existing** `RepoCharter` row:

| Incoming delta | Destination | Forbidden |
|----------------|-------------|-----------|
| New list key (`domain` / `rule` / `(kind,target)` not in baseline) | `appendices` only | formal fields, `draft_content` |
| Citation-only evidence on an **existing** list key (other fields byte-equal; only `citations` gains new entries) | `appendices` only (evidence side-channel) | formal fields, `draft_content` |
| Scalar change (`positioning` / `audience` / `form` / `evolution`) | `change_proposals` only | formal fields, `draft_content` |
| List item removal | `change_proposals` only | formal fields, `draft_content` |
| Same-key **semantic** change (status/note/rule text/kind/target/domain text differs beyond citations) | `change_proposals` only | formal fields, `draft_content` |

- **Automation never writes formal fields or `draft_content`** once a row exists (ai_draft and human_confirmed alike).
- **Formal mutation only** via human `aconfirm_charter` (`edits` and/or `approve_proposal_ids`). Rejecting proposals never mutates formal fields.
- Creating the **first** row (no baseline yet) is the sole automated path that may set formal fields (baseline create).

### Callback decision tree (blocker 3) — deterministic

After computing `observed_fingerprint` from overview + tree paths/node_ids + facets:

1. **Equal** to stored `baseline_fingerprint` (row exists) → skip apply/enqueue body work; persist fingerprint / maybe `locked_at`; log skip. Stop.
2. **Changed** (or no stored fingerprint) **and** `payload.charter` is dict → `aapply_charter_from_runner` (create baseline if no row; else classify → appendices/proposals); persist observed fingerprint. Do **not** enqueue overwrite LLM.
3. **No row** and **no charter** → `enqueue_charter_draft(..., mode="bootstrap")` once.
4. **Existing row** and **no charter** → `enqueue_charter_draft(..., mode="supplement")`; durable supplement writer must **classify-only** (appendices/proposals) and **persist observed fingerprint**; never formal/`draft_content`.

No other branches. Remove prior ambiguous “OR apply empty / optional path” language.

### Confirm-gate / P11 tests (blocker 4)

- Update `test_blueprint_confirm_gate.py` comment at MJ-07 (`asubmit_charter_draft` 对 ai_draft 正式字段就地生效) to state: existing-row automation only writes appendices/proposals; formal unchanged until human confirm/approve.
- Rewrite writeback / charter_service / charter_api assertions that expect AI → `draft_content` or ai_draft in-place formal merge: assert **formal bytes unchanged** + side-channel (`appendices` / `change_proposals`) instead.
