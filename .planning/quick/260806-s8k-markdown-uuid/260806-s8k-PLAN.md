# Quick Task 260806-s8k：蓝图 markdown 渲染器把仓库显示成 UUID

## 问题

`services/process_runtime/blueprint_render.py` 的四个段落直接把 `repository_id` 当文本渲染，
导出物与界面上就出现「仓库 5b650e1a-2939-4aa9-90a1-1297c0aaead9」这种 UUID：

| 段落 | 行 | 现状 |
|------|----|------|
| 现状分析（三级标题） | `:275` | `### 仓库 {repository_id}` |
| 实现概述 · 功能模块「涉及仓库」 | `:305` | `_join_ids(repository_ids)` |
| 实现概述 · 实现项「仓库」 | `:319` | `_cell(item["repository_id"])` |
| API 契约「归属仓库」 | `:357` | `_cell(contract["repository_id"])` |
| 影响范围 · 受影响功能「涉及仓库」 | `:386` | `_join_ids(repository_ids)` |

同一个渲染器供三个面消费，所以三处一起坏：

1. 飞书导出（`delivery/api/blueprint_export_views.py:299`）
2. 项目工作台资料面板的方案预览（`ArtifactTimelineSerializer.current_version_markdown`
   → `web/src/components/delivery/ArtifactTimeline.vue:277`）
3. MCP `get_technical_blueprint`（`mcp_tools/views.py:4639`）

实测蓝图 `5b650e1a-2939-4aa9-90a1-1297c0aaead9`（v10）：导出 markdown 有 **39 行**漏出仓库 UUID。

前端 SFC 侧不受影响 —— `[id].vue:418` 的 `repoNames` 已从 `repo_associations` 解析仓名。

## 根因

仓名的权威位置 `repo_associations[].repository_name` 就在 content 里（实测该蓝图四个仓
全部有名：`frontend/onion-practice` / `backend/study-course` / `frontend/onion-learning` /
`backend/study-user-status`），但渲染器从没读过它 —— 只有「仓库关联」那一段用了
`repository_name`，其余段落各写各的，全部直出 id。

## 方案

在渲染器内部用 `content["repo_associations"]` 建 `{repository_id: 仓名}` 映射，四个段落改用它。

⛔ **不给 `render_blueprint_markdown` 加参数**：`test_blueprint_render.py:151` 有一条
`inspect.signature` 断言，参数名集合必须**恰为** `{content, blueprint_status}`（那是「未经确认」
标注不可关闭的唯一机器验形式）。映射从 content 自身派生，既守住签名，也让渲染器保持纯函数
（⛔ 不查 DB）。

仓名缺失时回落 id —— 与前端各 section 的 `repoNames[id] || id` 同口径，⛔ 不留白。
