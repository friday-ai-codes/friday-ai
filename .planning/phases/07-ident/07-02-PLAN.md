<objective>
Perform the surgical core of the auth-base refactor in a SINGLE atomic plan: change `AccessTokenAuthentication` to return the token owner as `request.user`, add the `friday_pat_` prefix gate, implement `authenticate_header`, and reorder `DEFAULT_AUTHENTICATION_CLASSES` to put the PAT class first.

These two changes MUST ship together: reordering the global auth classes WITHOUT `authenticate_header` would silently downgrade every site-wide unauthenticated response from 401 to 403 (RESEARCH Pitfall 2), breaking `test_auth.py` / `test_auth_e2e.py`. Splitting them would create a broken intermediate state.

After this plan: 07-01's `test_valid_token_passes` and `test_pat_identity.py` owner/coexistence assertions turn GREEN; `test_auth.py` / `test_auth_e2e.py` 401 assertions stay GREEN; `test_access_tokens.py::test_revoked_expired_denied_and_logged` stays GREEN (IDENT-05 untouched).

Purpose: Make "valid token = owner identity + owner RBAC" the authenticated reality without breaking JWT, audit, or 401 semantics.
Output: Refactored `authentication.py` + reordered `REST_FRAMEWORK` in `settings.py`.
</objective>
