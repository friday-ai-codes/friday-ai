<objective>
建立 REPO-01 的数据与解析地基：新增按 GitLab host 维度集中存储的实例级 Git 凭证模型 `GitInstanceCredential`（host 唯一、Fernet 加密 token），并提供单一凭证解析器 `resolve_git_token_sync(repo)` / `aresolve_git_token(repo)`——优先 per-repo token（向后兼容），其次按仓库 URL 的 host 命中实例凭证池，都无则返回 None。

Purpose: 让同一 GitLab 实例的多仓复用一份凭证，且既有部署的 per-repo token 升级后行为不回退（D-01/D-02 锁定）。本 plan 只做模型 + 解析器 + 单测；接线（Wave 2 三个 plan）直接引用此解析器，不得各自另写取 token 逻辑。
Output: GitInstanceCredential 模型、迁移 0036、`services/git_credentials.py` 解析器、解析器单测。
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DB ↔ 解析器 | 实例/仓库 token 以 Fernet 密文存库，解析器是唯一解密出口 |
| 解析器 ↔ 日志 | token 明文绝不可进结构化日志 |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-01 | Information Disclosure | GitInstanceCredential.encrypted_token | mitigate | 仅存 encrypt_value 密文；模型无明文字段；__str__ 不含 token |
| T-26-02 | Information Disclosure | services/git_credentials.py 日志 | mitigate | 解析器禁记 token，仅记 has_token/source 布尔；Test F 守护 |
| T-26-03 | Spoofing | host 匹配 | mitigate | host unique=True + SSH/HTTPS 归一一致，避免错配他 host 凭证 |
| T-26-04 | Tampering | 迁移 | accept | 仅建表无回填，不触碰既有 GitCredential 数据 |
