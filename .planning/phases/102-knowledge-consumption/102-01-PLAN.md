   配置项，沿用 django-environ 既有范式（env 可覆盖）：
   - `PROCESS_RECALL_ENTITY_KINDS = env.list("PROCESS_RECALL_ENTITY_KINDS", default=["work_item", "tech_plan", "code_change", "document", "learning_case"])`
     （新 kinds 默认开，locked）。

   - 配上中文注释说明用途与 KNOW-04 出处。

2. `server/services/process_runtime/recall_adapter.py` 改造 `recall()`：
   - 保留模块级 `RECALL_ENTITY_KINDS` 作为**默认值常量**（值更新为 5 kinds 的
     `EntityKind` 列表，docstring 注明「默认值，运行时以 settings 为准」），`__all__` 不变。
   - kinds 与 limits 在 **recall() 调用时**经 `django.conf.settings` 读取（
     `getattr(settings, "PROCESS_RECALL_ENTITY_KINDS", ...)` / `PROCESS_RECALL_KIND_LIMITS`，
     fallback 到模块默认），保证 `override_settings` 可测、部署改 env 即生效。
   - **取舍已定（Claude's Discretion 落定）：单查后按 kind 截断**，不分 kind 多次查询——
     每次 `search_similar` 是 embedding + Qdrant 的完整成本，5 kinds 分查 5 倍成本且跨查
     score 不可比（排序一致性差）；单查所有 score 出自同一 RRF 排序。在 recall() docstring
     写明该取舍理由。
   - 具体逻辑：`limits = {kind: 该 kind 配置上限（缺省 3）}`；
     `search_similar(query, user=user, top_k=sum(limits[k] for k in kinds) * 2, entity_kinds=kinds, repository_ids=..., include_document_kind=("document" in kinds))`
     ——top_k 超采样 2 倍给截断留余量；`include_document_kind` 必须按 kinds 是否含
     document 动态传（vector_recall 严格交集过滤，不传 flag 则 document 永远召不回）。
   - 结果按 kind 分桶截断：遍历 score 降序的 hits（search_similar 返回已按融合分排序），
     每 kind 保留至多 limits[kind] 条（未知 kind 上限用 3 兜底），合并后保持原 score
     降序输出。返回结构 `{hits, query, kinds}` 外形不变（hits 单条外形
     {entity_id, kind, title, score} 不变，`_map_hit` 复用）。
   - `self.top_k` 构造参数保留但语义调整为「上限兜底」：最终 hits 总数不超过
     max(top_k, sum(limits))——不破坏既有构造方调用（entrypoint.py L91 无参构造）。
   - 空 query 短路 / created_by fail-closed / 异常空召回三条既有语义逐字保留。
  </action>
