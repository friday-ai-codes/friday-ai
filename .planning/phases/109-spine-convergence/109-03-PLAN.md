    定义 `class PlanProjectionError(Exception)`，带一个 `code: str` 属性（供端点映射成稳定机器码）。至少两个取值：`"artifact_version_not_found"`（来源不存在或 `content` 非 dict）与 `"projection_requires_chat_entrypoint"`（编排会话无 conversation）。

    定义 `class PlanProjectionService`（无状态，服务层类方法/实例方法，不持有状态），核心方法：

    ```
    async def aproject(self, *, artifact_version_id: str, initiated_by_user_id: str = "system") -> tuple[CodingPlan, bool]
    ```

    实现要点（逐条不可省）：
    1. **conversation 解析只走 chat 入口（裁决 D-3）**：`ArtifactVersion.produced_by_session_id` → `ConvergenceSession.conversation_id` → `Conversation`。三者任一为空/不存在 → 抛 `PlanProjectionError(code="projection_requires_chat_entrypoint")`。**不建合成会话、不按 repository 反查 space**（`ConvergenceSession` 无 space FK，反查有歧义 —— 109-RESEARCH Open Q1 已建议限定范围规避）。把这条边界写进方法 docstring。
    2. **签名不得只有 `artifact_version_id` 一个参数**（Pitfall 4 的警示信号）：显式带 `initiated_by_user_id`，供后台调用方绑定触发用户；无触发用户记 `"system"`。
       > 前瞻提示（不在本 task 交付）：本 task 阶段 service 内**不含**归属判定，唯一调用方是 Task 3 的端点、其视图内有 owner gate，因此当前形态安全。plan **109-05** 会让 chat `@tool` 成为第二个调用方，届时该参数被改为**必填**的 `actor_user_id` 并在 service 内落归属判定（机器码 `artifact_version_forbidden`），视图 gate 降为纵深。本 task 不要提前实现，但也不要把「归属由调用方保证」写成 docstring 里的长期契约。
    3. **幂等三件套齐备**：`CodingPlan.objects.aget_or_create(source_artifact_version_id=str(av.id), defaults={...})` + 外层 `except IntegrityError:` 重新 `aget(source_artifact_version_id=...)` 并置 `created=False`（照抄 `coding_session_service` 的降级模式）。DB 约束由 plan 109-02 提供，是**无条件**的单列 `UniqueConstraint`（带 `condition` 会在 MySQL 上被 `_unique_supported()` 静默跳过 ⇒ 本 task 的 `except IntegrityError` 分支永不触发、并发下会产生重复行；109-02 Task 1 有 `get_constraints` 存在性断言兜住这一点）。三者缺一不可（`aget_or_create` 单独不安全、`UniqueConstraint` 单独会抛 500 给用户）。

    6. **async ORM 纪律**：`*_id` 标量 / `.values()` / `afirst` / `aget`，绝不裸访问同步 lazy-FK；需要事务块时用 `@sync_to_async` + `transaction.atomic()`。
    7. **观测埋点**（`structlog.get_logger(__name__)`，全部 `category="caller"` + `component="chat"`，全部包在 best-effort 里不反噬业务）：
       - `plan_projection_started`：`artifact_version_id`, `initiated_by_user_id`
       - `plan_projection_completed`：`duration_ms`, `coding_plan_id`, `created`, `repo_count`, `provenance`
       - `plan_projection_failed`：`duration_ms`, `reason`, `artifact_version_id`。`reason` 若来自异常文本，先过 `common.logging.redact_secrets_in_text`

       a. 请求体反序列化（`raise_exception=True`）。
       b. 调 `PlanProjectionService().aproject(artifact_version_id=..., initiated_by_user_id=str(request.user.id))`。
       c. **owner gate 置于响应序列化之前**：拿到 plan 后按 `plan.conversation.created_by_id != user.id → 404`（用 `created_by_id` 标量避免 async 惰性 FK；**无 superuser bypass**；措辞与 `CodingPlanDetailView` 的 404 一致，不泄漏存在性）。为避免「先投影再拒绝」留下垃圾对象，优先在调 service 之前用 `ConvergenceSession`/`Conversation` 的 `created_by_id` 做一次前置 owner 校验；service 之后再复核一次作为纵深。
       d. `PlanProjectionError` 映射：`code == "artifact_version_not_found"` → 404，响应体 `{"code": <code>, "detail": ...}`；`code == "projection_requires_chat_entrypoint"` → 400，响应体同形。**响应必须带稳定 `code` 字段**（UI-SPEC 后端契约要求第 4 条同一纪律：前端按 `code` 分支，绝不按 `detail` 文案匹配）。
       e. 成功 → 200，响应体由 `ProjectPlanToCodingResponseSerializer` 组装，`created` 取 service 返回的布尔值。
       f. 加 `@extend_schema`（summary / request / responses 200|400|404 / `tags=["CodingPlan"]`），与同文件既有视图风格一致。
    3. `server/chat/urls.py` 注册 `path("coding-plans/from-artifact-version/", CodingPlanProjectFromArtifactVersionView.as_view(), name="coding-plan-project-from-artifact-version")`。**必须放在 `coding-plans/<uuid:plan_id>/` 之前或确认不冲突**（`from-artifact-version` 不是合法 UUID，Django 的 `uuid` 转换器不会匹配，但仍在注释里点明这一点）。

       - 422/400：`artifact_version_id` 非 UUID → DRF 校验 400。
