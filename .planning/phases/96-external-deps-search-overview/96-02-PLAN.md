<objective>
交付 KDEP-02 后端：让 `/knowledge` 搜索命中工件时携带足够元数据，供前端标注工件类型徽标、标注所属项目、一键跳查看。两步：①让 document-kind 工件实体进入搜索召回；②检索结果 DTO/序列化补全工件专有元数据（类型名/载体/url/artifact_id/所属项目 id+名称），跨项目按 `access_scope` 过滤。

Purpose: 现有 `KnowledgeSearchView` 默认 `include_document_kind=False` → 工件（kind=document）根本不进搜索结果；且序列化仅暴露 title/kind/score/provenance，前端无从判定工件类型与查看入口。本 plan 打通「工件可被搜到 + 结果自带类型与查看所需元数据」，权限沿用既有 `resolve_allowed_project_ids` 收口。
Output: `EntityMetadata` 扩展 + 批量 hydrate 工件元数据 + 搜索序列化补字段 + 搜索视图启用 document 召回 + API 测试。
</objective>
