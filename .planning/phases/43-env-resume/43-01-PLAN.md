<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server → runner/container | dispatch metadata（含 git token）经 WebSocket 下传 runner，再注入容器环境变量 |
| server → 日志/trace sink | dispatch 事件日志可能流向集中日志 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-INFO | Information Disclosure | `_run_repo_coding` dispatch 日志 | mitigate | token 仅进 dispatch payload；日志只记 `has_git_token` 布尔；`redact_credentials` structlog processor 兜底。Task 1 `no_token_leak` 测试守护 |
| T-43-TAMPER-URL | Tampering | SSH→HTTPS repo_url 改写 | accept | `repository.git_url` 来自服务端 DB（非 runner 输入），改写正则锚定 `git@host:path`，无注入面（RESEARCH Security Domain） |
| T-43-CRED | Cryptography/Info | git token 解析 | mitigate | 复用 `aresolve_git_token`（Fernet 解密在解析器内），绝不内联 decrypt（Don't Hand-Roll） |
</threat_model>
