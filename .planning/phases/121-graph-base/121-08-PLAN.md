<objective>
把 `GraphService` 从「一个 LRU 容器」变成「取图入口」：async 外壳 + 取图时签名复校 + 半新图防护 + 装配前准入与降级 + per-key single-flight。这是 GRAPH-01/02/03 三条需求在同一个函数里收口的地方。

Purpose: 「取图时水位复校」是与 `GalaxyGraphCache` 的显式差异点——Galaxy 只在读时比签名，本服务额外要看边构建是否在途，这是 GRAPH-02「绝不返回半新图」的直接落点。而并发正确性在本仓有硬约束：进程内同时存在三类 event loop，`asyncio.Event` 跨 loop 无法 await；持 `threading` 锁时 `await` 会同步阻塞整个 loop 线程甚至死锁。唯一稳妥的形态是把整段临界区做成同步函数、由一次 `sync_to_async` 包裹，让两者物理上不可能重叠。
Output: `async def get_graph(...)` 全链路 + 五条并发/失效回归用例。
</objective>

在 `_get_graph_sync` 的构建路径外层加 per-key single-flight。数据结构：`self._inflight: dict[tuple[str, str], _InFlight]`，`_InFlight` 含 `event: threading.Event`、`result: CodeGraph | None`、`error: BaseException | None`。锁粒度：`self._lock`（`RLock`）只保护 `_inflight` 与 `_cache` 两个 map 本身，**不在持锁期间执行装配**。

流程：
① 持锁检查 `_inflight`：不存在 → 建 `_InFlight()` 放入、标记自己是**领头**、释放锁；已存在 → 取到该对象、释放锁、走等待分支。
② 领头：锁外执行装配；`finally` 里持锁把结果或异常写进 `_InFlight`、从 `_inflight` 弹出、`event.set()` 唤醒全部等待者。成功时按 Task 2 的规则决定是否 `_put` 进缓存。
③ 等待者：`done = inflight.event.wait(timeout)`，`timeout` 取 `settings.CODE_GRAPH_BUILD_WAIT_TIMEOUT_SECONDS`。超时 → 抛 `GraphBuildTimeout`（**超时是必需的，不是可选**：领头请求若被 kill，例如 ASGI 断连取消，等待者不能永久挂起）。唤醒后若 `error` 非空 → 抛 `GraphBuildFailed`（包上原异常做 `__cause__`）；否则返回 `result`。
🚨 **失败不缓存**（不做失败缓存避免毒化）：`_inflight` 弹出后不留任何失败痕迹，下一个请求会重新尝试构建。

🚨 D-06-4 / Pitfall 8：等待信号必须是 **`threading.Event`**（loop 无关）。⛔ 绝不用 `asyncio.Event`——本仓同时存在 ASGI 主循环、`background_runner` 常驻 daemon 线程循环、workflow engine `_run_in_thread` 循环三类 loop，`asyncio.Event` 绑定创建它的 loop，跨 loop await 会 `RuntimeError`。
🚨 Pitfall 7：这里的 `event.wait()` 是阻塞调用，但它运行在 `sync_to_async` 派发的执行器线程上、不在 event loop 线程上，所以不阻塞 loop。在代码注释里写死这条前提，并补一句：若将来有人要从协程里直接等待占位，必须走 `await asyncio.to_thread(ev.wait, timeout)`，⛔ 不得在协程里直接 `ev.wait()`。

失败埋点：`logger.warning(_EVENT_BUILD_FAILED, component="code_graph", category="sampling", repository_id=..., branch=..., error=redact_secrets_in_text(str(exc))[:500], error_type=type(exc).__name__, duration_ms=..., waiters=<等待者数>, initiated_by_user_id=...)`。
