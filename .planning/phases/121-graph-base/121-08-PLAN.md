<objective>
把 `GraphService` 从「一个 LRU 容器」变成「取图入口」：async 外壳 + 取图时签名复校 + 半新图防护 + 装配前准入与降级 + per-key single-flight。这是 GRAPH-01/02/03 三条需求在同一个函数里收口的地方。

Purpose: 「取图时水位复校」是与 `GalaxyGraphCache` 的显式差异点——Galaxy 只在读时比签名，本服务额外要看边构建是否在途，这是 GRAPH-02「绝不返回半新图」的直接落点。而并发正确性在本仓有硬约束：进程内同时存在三类 event loop，`asyncio.Event` 跨 loop 无法 await；持 `threading` 锁时 `await` 会同步阻塞整个 loop 线程甚至死锁。唯一稳妥的形态是把整段临界区做成同步函数、由一次 `sync_to_async` 包裹，让两者物理上不可能重叠。
Output: `async def get_graph(...)` 全链路 + 七条并发/失效/闸门位置回归用例。
</objective>

实现 `async def get_graph(self, repository_id: str, branch: str = "", *, user: Any | None = None, include_low_confidence: bool = False, seed_symbol_ids: Sequence[str] | None = None, depth: int | None = None) -> CodeGraph`：
① `await ensure_repository_readable(user, repository_id)` —— 🚨 **每次调用都跑，绝不因缓存命中而跳过**（这是缓存键跨仓/跨分支串图与 ACL 撤销滞后的唯一防线）。在代码注释里写死这条，防后人为了「命中更快」把它挪进 miss 分支。
② `return await sync_to_async(self._get_graph_sync)(repository_id, branch, include_low_confidence, seed_symbol_ids, depth, user_id)` —— **唯一**的 async/sync 边界。不传 `thread_sensitive`（用默认 `True`，与全仓 ORM 调用一致）。
   docstring 里如实记录代价：`thread_sensitive=True` 意味着所有此类调用共享同一执行器线程，一次 2–4 秒的大图装配会阻塞该执行器上的其他 ORM 工作；三层缓解是 single-flight（同 key 只建一次）、LRU（建过不重建）、超预算走按需子图（大仓的真正防线）。

实现同步主体 `def _get_graph_sync(...) -> CodeGraph`，docstring 首句写「全同步：锁、ORM、networkx 装配都在这里，不存在 await-under-lock 的可能」。**步骤顺序是本任务的核心契约，按 ③→⑦ 逐条落地，顺序不可调整**：

③ `matcher, exclusion_fingerprint = build_matcher_and_fingerprint(repository_id)`（fail-closed，异常向上冒成 `GraphAccessDenied`）。
   🚨 **本次调用内只解析这一次**，随后把 `matcher` 与 `exclusion_fingerprint` 作为**关键字参数注入** `loader.load_graph(...)` / `loader.load_subgraph(...)`。⛔ 绝不让 loader 自己再调一次 `build_matcher_and_fingerprint`——它内部会走 `_resolve_effective_specs` 的 DB 读，再在 `ExclusionMatcher.__init__`（`server/services/exclusion.py:157–207`）里把该仓全部 glob/regex 重新编译一遍；一次调用做两遍纯属浪费，而且这条路径**不经过** `build_matcher_for_repo` 的 60s `_matcher_cache`，省不掉。跨调用的复用由 `access.py` 自带的 TTL memo（Plan 121-03）负责，本层只需保证「一次调用一次解析」。
④ `current_sig = compute_signature(repository_id, branch, exclusion_fingerprint=exclusion_fingerprint)`。
⑤ 🚨 `in_flight, in_flight_reason = detect_edge_build_in_flight(repository_id, branch)` —— **必须在命中返回之前执行**。理由（写进代码注释，防后人为了「命中更快」把它挪进 miss 分支）：半新图防护要挡的恰恰是「签名分量尚未推进、但边正在写入」这一窗口——此时签名会**恰好一致**，若先返回命中就永远走不到 in-flight 判定，GRAPH-02 的保证等于零。签名比对与 in-flight 判定是两道**独立**的闸，不是同一道闸的两种写法。
⑥ 持 `self._lock` 取条目：
   - 存在 且 `entry.built_signature == current_sig` 且 **`not in_flight`** → `move_to_end` + `code_graph_cache_hit`（DEBUG）→ 返回 `entry.graph`。
   - 存在 且 签名一致 但 `in_flight` 为真 → **绕过缓存**走构建路径（Task 2 的 partial 分支）。此处**只绕过、不驱逐**：该条目本身没被证伪，边构建完成后签名自然会推进并触发正常替换，驱逐只会白白丢掉一份可能仍可用的图。
⑦ 签名不一致 → 从 map 移除该条目并扣减 `_total_bytes`，发 `logger.info(_EVENT_STALE_WATERMARK, component="code_graph", category="sampling", repository_id=..., branch=..., cached_signature=<前 12 位>, current_signature=<前 12 位>, reason="signature_mismatch")`（低频，INFO 可接受；⛔ 只记签名前缀，不记全量分量明文），然后走构建路径。

🚨 子图路径（`seed_symbol_ids` 非空）**不进缓存也不查缓存**，直接走 Task 2 的降级分支——子图内容依赖种子与深度，缓存键无法表达。

在 `_get_graph_sync` 的构建路径外层加 per-key single-flight。数据结构：`self._inflight: dict[tuple[str, str], _InFlight]`，`_InFlight` 含 `event: threading.Event`、`result: CodeGraph | None`、`error: BaseException | None`。锁粒度：`self._lock`（`RLock`）只保护 `_inflight` 与 `_cache` 两个 map 本身，**不在持锁期间执行装配**。

流程：
① 持锁检查 `_inflight`：不存在 → 建 `_InFlight()` 放入、标记自己是**领头**、释放锁；已存在 → 取到该对象、释放锁、走等待分支。

③ 等待者：`done = inflight.event.wait(timeout)`，`timeout` 取 `settings.CODE_GRAPH_BUILD_WAIT_TIMEOUT_SECONDS`。超时 → 抛 `GraphBuildTimeout`（**超时是必需的，不是可选**：领头请求若被 kill，例如 ASGI 断连取消，等待者不能永久挂起）。唤醒后若 `error` 非空 → 抛 `GraphBuildFailed`（包上原异常做 `__cause__`）；否则返回 `result`。
