每个拒绝出口前发一条 `logger.warning(_EVENT_ACCESS_DENIED, component="code_graph", category="sampling", repository_id=..., reason=<denied 原因短码>, initiated_by_user_id=<user id 或 "system">)`。埋点用 try/except 包住、异常吞掉（观测 best-effort，绝不反噬主流程）。

实现 `def build_matcher_and_fingerprint(repository_id: str) -> tuple[ExclusionMatcher, str]`（**同步**，因为 loader 全程在 `sync_to_async` 包裹的同步上下文内，无需 async 的 `build_matcher_for_repo`）：
① lazy import `from services.exclusion import ExclusionMatcher, _resolve_effective_specs`。
② `specs = _resolve_effective_specs(repository_id)`。
③ 指纹：对 specs 做 `sorted((s.rule_type, s.pattern, bool(s.enabled), s.source) for s in specs)` → `json.dumps(canonical, ensure_ascii=False)` → `hashlib.sha256(...).hexdigest()[:16]`。
   ⛔ **不要**用 `RepoExclusionRule` 的 `count + MAX(updated_at)` 当指纹——那会漏掉 `SystemSetting` 全局 JSON 与 `BUILTIN_GLOBAL_DEFAULTS` 的代码变更（Pitfall 9）。⛔ 也不要拿 `_matcher_cache` 的 60s TTL 当版本号——TTL 只控制何时重建 matcher，不产生任何可比对的版本标识，且 `_matcher_cache` 是无锁裸模块字典。注释里把这两条否决理由写清。
④ 构造 `ExclusionMatcher(specs, repository_id=repository_id)`；任何异常（含构造期 `InvalidExclusionRuleError`）→ 发 `logger.warning(_EVENT_MATCHER_FAILED, component="code_graph", category="sampling", repository_id=..., error=redact_secrets_in_text(str(exc))[:500], error_type=type(exc).__name__)` + 调 `log_exclusion_blocked(surface="code_graph", repository_id=..., rel_path="<repository>")` + **抛 `GraphAccessDenied`**（整仓拒绝）。🚨 绝不 `except: pass` 降级成「不过滤」。

实现 `def make_path_exclusion_memo(matcher: ExclusionMatcher) -> Callable[[str], bool]`：返回一个闭包，内部持 `dict[str, bool]` 按 `file_path` 记忆化 `matcher.is_excluded(...)` 结果。理由写进 docstring：`is_excluded` 是每节点一次的热路径调用（10 万级），内部对每条 dir/glob/regex 规则跑一遍匹配；符号数远大于文件数，按 file_path 去重通常省 90% 以上调用。
🚨 该闭包内**不得**每次调用都打 `log_exclusion_blocked`（它是 INFO 级，10 万级循环内会刷屏，直接违反 `.cursor/rules/observability-logging.mdc` 的级别纪律）。约定：闭包对**每个新的被排除 file_path** 至多调一次 `log_exclusion_blocked`，命中记忆化时不再打点。闭包另外暴露 `excluded_files` 只读集合供 loader 汇总计数。
