<objective>
补全容器侧 token 链路（RATE-02 核心难点）：**整条链当前是断的**——`task/core/executor.py::_write_usage_data` 只写 `/workspace/.friday/usage.json`（无人读取），`CallbackClient` 没有 token-usage 发送方法，runner 仅在 task 发送时才转发，故容器 LLM token **从不到达 server**。本 plan 端到端闭合该链：task 侧新增 `CallbackClient.report_token_usage` 并在 executor 主动发出回调（四类容器全覆盖、保留 usage.json 向后兼容），server 侧在既有 `_handle_token_usage` 里把容器 token 桥接落一行 `ModelUsageRecord`（统一 TPS 源），`call_source` 由 `SubAgentSession` 服务端权威派生四类容器，复用 72-02 的 `arecord_llm_usage`（可空 `run`）+ `CallSource` 枚举。

Purpose: TPS 要"全量不漏容器"。容器 token 是唯一游离在 server 进程外的 LLM 来源，且链路在 **task→回调** 处断裂（不止 callback→ModelUsageRecord）。修复必须 task + server 双侧：task 主动 emit（此前缺失），server 桥接入 TPS（保留 `TokenUsage` 给成本归因既有消费方，不复制语义）。call_source / user 由服务端权威派生，不信任 runner 可篡改字段。
Output: `task/integrations/callback.py`（report_token_usage）、`task/core/executor.py`（主动 emit + usage 富化）、`server/subagent/api/serializers.py`（可选字段）、`server/subagent/api/callbacks.py`（桥接 + call_source 派生）、task + server 双侧守护测试。

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 容器/runner → server 回调 | 半可信容器经 token_usage 回调上报 token/字段（CONTAINER_CALLBACK_TOKEN 鉴权，但 payload 字段可被篡改） |
| token_usage payload → ModelUsageRecord | 容器自报字段写入统一 TPS 源 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-72-03-TAMPER | Tampering | runner 篡改 call_source / user 归因 | mitigate | call_source 优先服务端 `_derive_container_call_source(session)`（task_type/last_output.source 权威派生）；user_id 取服务端 main_session.metadata/node_execution，**绝不**取 runner 可篡改的 last_output 任意键作归因用户（对齐 cross_repo_relevance 权威字段范式） |
| T-72-03-01 | Information Disclosure | 容器 token 桥接/emit 泄漏 prompt/凭证 | mitigate | report_token_usage 与桥接只承载 token 计数 + provider/model/status 元数据，**绝不**落/发 prompt/completion 文本；standalone 日志仅记 model/计数；容器回调原始留痕已在 71-05 经脱敏处理 |
| T-72-03-02 | Spoofing | 无效容器伪造 token_usage 灌数据 | accept | 既有 `CONTAINER_CALLBACK_TOKEN` 校验为唯一关卡（report_token_usage 复用 self.config.callback_token），本 plan 不放大信任面 |
| T-72-03-03 | Denial of Service | 桥接/emit 写库/网络失败拖垮回调或任务 | mitigate | emit best-effort（httpx 异常吞 + return False）；executor 整段 try/except swallow；server 桥接独立 try/except，失败仅 warning，回调仍 200；arecord_llm_usage 内部 best-effort |
| T-72-03-SC | Tampering | npm/pip/cargo 安装 | accept | 本 plan 不新增依赖（task 复用既有 httpx；server 复用 72-02 helper + 既有 DRF） |
