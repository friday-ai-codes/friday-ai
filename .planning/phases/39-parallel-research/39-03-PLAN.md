  <files>server/services/plan_orchestration/research_adapter.py, server/services/plan_orchestration/__init__.py</files>
  <action>
  新建 `research_adapter.py`（zh-CN docstring 引 RESEARCH-01 + filter_then_container 决策，
  ruff line 100）。`class ResearchDispatchAdapter`（满足 ResearchProtocol：`async def
  dispatch(self, session) -> dict`），构造参数 `deep_confidence: set[str] = {"high","medium"}`
  （阈值可配，per CONTEXT Claude's Discretion 默认 high+medium 起容器）。镜像
  RepoRouterV2Adapter/recall_adapter 的「只接线、不重造」风格。

  `dispatch(session)` 流程：
  1. **filter**：取 `candidates = (session.routing or {}).get("candidates", [])`。按 confidence 分流：
     - `confidence in deep_confidence`（high/medium）→ deep_repos。
     - 否则（low / 缺失）→ light_repos。
     无 candidates → 返回 `{"dispatched": [], "light": [], "skipped": "no_candidates"}`（不抛、不起容器）。
  2. **runner 在线检查**（mirror deep_analysis，仅当存在 deep_repos 时）：查
     `Runner.objects.filter(status="online", last_heartbeat__gte=now-120s).acount()`；
     **不重试循环**（编排是后台推进，非交互 chat；无 runner → deep_repos 全部降级为 light
     处理并在返回 dict 标 `runner_offline=True`，不阻断编排——轻量 partial 仍产出）。
  3. **deep fan-out**（每仓上下文隔离）：经
     `ResearchService.create_tasks_for_session(session, deep_repos)` 建 RepoResearchTask；
     对每个 task：
     - 建 AgentSession + SubAgentSession(task_type=TaskType.PLAN, status=PENDING,
       last_output={"source":"plan_research","plan_session_id":str(session.id),
       "research_task_id":str(task.id),"repository_id":...})（mirror deep_analysis 建会话；
       source 标记供 39-04 callback 路由）。
     - 构 `_build_research_prompt(session, repo, task)`：注入该仓 routing 上下文（confidence/
       repo_name）+ session.recall_context（Phase 38 召回精简命中）+ decomposition.requirement_text +
       「请产出结构化 PartialPlan，字段：research_summary / proposed_changes / candidate_files /
       api_contracts_exposed / dependencies_on_other_repos（§7），以 JSON 输出」decomposition 要求。
     - 解析 git 凭证 + claude code runtime config（复用 deep_analysis 的 aresolve_git_token +
       aget_claude_code_runtime_config + env_metadata 构造，task_mode="plan"/"explore" 只读语义）。
     - `get_dispatcher().dispatch(DispatchTask(task_type="plan", ...))` fire-and-forget。
     - `ResearchService.mark_running(task, subagent_session)` 回填。
     - emit `repo.research.started`（payload `{repo_id, task_id, focus}`）经
       `session_service._emit_event` 钩子（注入 PlanSessionService 实例，best-effort）。
  4. **light path**（low/降级仓）：本 plan 仅**占位合成轻量 PartialPlan**——为每个 light repo
     建 RepoResearchTask 后 `ResearchService.record_partial(task, {repository_id,
     research_summary: 由 recall_context/routing 摘要合成, proposed_changes: [], candidate_files: [],
     api_contracts_exposed: [], dependencies_on_other_repos: []})`（不起容器，省资源；done 即终态）。
     轻量摘要合成是纯函数 `_synthesize_light_partial(session, repo)`，不调 LLM/容器。
  5. return `{"dispatched": [task_id...], "light": [task_id...], "runner_offline": bool}`。

  **ORM/async**：所有 ORM 写经 ResearchService（已 sync_to_async 内部桥接）；adapter 内直接
  ORM 读（runner count / repo 取数 / AgentSession+SubAgentSession 建会话）用 async ORM
  （acount/aget/acreate），凭证解析复用既有 async helper。adapter 持有可注入
  `session_service`（默认 PlanSessionService()）+ `research_service`（默认 ResearchService()）
  便于 39-04/测试注入与事件钩子。

  curated re-export：`plan_orchestration/__init__.py` 加 `ResearchDispatchAdapter` import + __all__。
  </action>

    <automated>cd server &amp;&amp; uv run python -c "from services.plan_orchestration import ResearchDispatchAdapter;print('ok')"</automated>
  </verify>
  <done>ResearchDispatchAdapter 实现 filter（high/medium→容器, low→轻量）+ fan-out（建 task + dispatch SubAgentSession PLAN 容器 + 回填 running + emit started）+ 轻量合成；只经 ResearchService 写表 + 复用 DispatchTask/get_dispatcher。</done>
