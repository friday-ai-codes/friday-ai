<objective>
KDEP-07：为 ragable 文字工件在摄取/更新时建立「工件↔仓库/能力/关键词」结构化关联。在 Phase 96 已收口的工件摄取单一写入路径上挂一个 best-effort 后置步骤——取工件正文调 `RepoRouterV2.route()` 得 matched 仓库 + `matched_node_paths` + 关键词，对每个命中仓库落 `KnowledgeEdge(RELATES_TO, artifact→repo)`，边 `metadata` 承载 `{source:"artifact", artifact_id, node_paths, keywords, score}`。关键词/能力**不建独立实体表**，全部用边 metadata 承载（research §2.4 锁定）。

Purpose: 补齐 research §1.5 缺口「工件↔仓库无边、工件↔能力/关键词零关联」，使工件与代码仓库/业务能力在交付知识图谱里可导航、可反查（供 Phase 99 可视化与 98-03 查询消费）。全程复用既有路由（RepoRouterV2）+ 图谱写入收口（EdgeSpec/graph_store），单一写入入口、幂等 upsert、fail-soft 绝不反噬摄取主流程。

Output: `graph_store.update_edge_metadata`（活跃边 metadata 就地覆盖原语）+ `apply_edge_specs` 实体边 metadata upsert 语义 + 工件 normalizer 的路由建边后置步骤。
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 工件正文 → LLM 路由 | 外部文档正文（飞书 doc/表格/md/repo_file，未受信内容）跨界喂给 RepoRouterV2 的 LLM 树推理 |
| call_source 维度标签 | 路由 LLM 调用来源标签作为指标/筛选维度，基数必须受控 |
| 边 metadata | 路由结果（node_paths/keywords/score）写入 KnowledgeEdge.metadata，随后被查询暴露 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-98-01-01 | Tampering | 路由 LLM call_source 基数 | mitigate | 复用受控枚举 `CallSource.AUX_REPO_ROUTER`（不新增值，基数零增长）；`CallSource.normalize` 对任意非法字符串回退 `unknown`（既有机制，自动兜底） |
| T-98-01-02 | Information Disclosure | 工件正文入 LLM / 日志 | mitigate | 正文入图前经 `redact_secrets_in_text` 脱敏（Phase 96 既有）；路由异常文本经 `redact_secrets_in_text`；结构化日志仅记长度/命中计数/router_version，绝不回显正文 |
| T-98-01-03 | Denial of Service | 超大工件正文塞爆 LLM 上下文 | mitigate | query 截断到模块级字符预算常量（对齐 repo_association `_QUERY_CHAR_BUDGET`）；候选范围收窄到 space 仓库（非全库） |
| T-98-01-04 | Denial of Service | 路由失败/超时反噬摄取 | mitigate | RepoRouterV2 自带降级链（LLM 失败→Stage0、无命中→v1）；后置步骤整体 try/except 吞掉，附加边为空，摄取主流程零阻断（best-effort） |
| T-98-01-SC | Tampering | npm/pip/cargo installs | mitigate | 本 plan 不安装任何新包（纯仓内复用 RepoRouterV2 / graph_store / EdgeSpec），无供应链面 |
</threat_model>
