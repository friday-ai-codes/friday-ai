<objective>
KDEP-08：把项目已确认的仓库关联（`RepoAssociation status=verified`）单向派生为项目↔仓库的知识图谱边。扩展 `ProjectKnowledgeGraphService`（wire up 既有未被调用的 `link_repository` + 新增 `unlink_repository` + 扩展 `sync_relations_from_operational`），并在 `RepoAssociationService` 状态流转到/离开 verified 的收口处挂一个单一 best-effort 同步 hook：verified → 派生项目→仓库 `RELATES_TO` 边（metadata 标注 `source:"repo_association", association_id, score, confidence, matched_node_paths`）；离开 verified → 失效对应派生边。

Purpose: 补齐 research §1.5 缺口「`link_repository` 有方法但未被业务调用」，让 verified 选仓结果进入统一可查询/可视化图层（供 Phase 99 星图与 98-03 查询消费）。硬约束：`RepoAssociation` 保持**唯一真相源**，图谱边**单向派生**（真相变则边随之增删），**不新建重复真相表**；幂等、fail-soft 绝不反噬状态流转主流程。

Output: `link_repository`（带 metadata upsert）+ `unlink_repository`（失效派生边）+ `sync_relations_from_operational` 扩展 + `RepoAssociationService` 单一同步 hook。
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 真相源 ↔ 派生图层 | RepoAssociation（唯一真相源）单向派生 KnowledgeEdge；派生方向不可反向写回真相源 |
| verified 状态流转 hook | 图谱同步挂在关联状态机收口，失败不得反噬业务状态流转 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-98-02-01 | Tampering | 真相源双写 | mitigate | 图谱边**单向派生**：本 phase 只读 RepoAssociation、只写 KnowledgeEdge；`sync_relations_from_operational` 迭代 verified 关联派生边，绝不写回 RepoAssociation（不新建重复真相表，INV-6 收口不变） |
| T-98-02-02 | Repudiation / 一致性 | verified 离开后残留派生边 | mitigate | 单一 hook 覆盖 verified↔非 verified 双向：离开 verified（mismatch/reopen）→ `unlink_repository` 失效置位派生边，图谱与真相源最终一致 |
| T-98-02-03 | Denial of Service | 图谱同步失败反噬状态流转 | mitigate | hook 整体 try/except 吞掉 + failed 观测事件；verdict 落库/状态更新为先、图谱派生为后置 best-effort，主流程零阻断 |
| T-98-02-04 | Information Disclosure | 同步异常文本泄漏 | mitigate | 异常 reason 经 `redact_secrets_in_text`；日志仅记 repo_id/verified 布尔/计数，不回显 verdict 正文 |
| T-98-02-SC | Tampering | npm/pip/cargo installs | mitigate | 本 plan 不安装任何新包（纯仓内扩展既有 service + graph_store），无供应链面 |
</threat_model>
