    新建 `server/initiatives/services/artifact_associations.py`：`ArtifactAssociationQueryService`（无状态 async，只读，查询走 `graph_store` 收口，per KDEP-09）。定义 metadata 键常量（与 98-01 契约一致：`_SOURCE_ARTIFACT="artifact"`）。方法：
    - `related_for_artifact(self, artifact_id: str, *, user) -> dict`：`aid = generate_entity_id(EntityKind.DOCUMENT,"artifact",artifact_id)`；`edges = await graph_store.neighbors(aid, relations=[EdgeRelation.RELATES_TO], direction="out")`；筛 `metadata.source=="artifact"`。对每条：target 为 repo 节点，`sync_to_async` 批量 hydrate KnowledgeEntity 得 `repository_id`（=节点 source_id）+ title；access_scope：`allowed_repos = await resolve_allowed_repository_ids(user)`，越权 repo 剔除（fail-closed）。返回 `{"repos":[{repository_id, repo_name, node_paths, keywords, score}], "capabilities": <所有 node_paths 去重并集>, "keywords": <所有 keywords 去重并集>}`。
    - `artifacts_for_repo(self, repo_id: str, *, user) -> list[dict]`：`rid = repository_node_id(repo_id)`；`edges = await graph_store.neighbors(rid, relations=[EdgeRelation.RELATES_TO], direction="in")`；筛 `metadata.source=="artifact"`。source 为 artifact 节点，hydrate 得 artifact 实体（source_id=artifact_id、space_id）；access_scope：`allowed_spaces = await resolve_allowed_project_ids(user)`，仅保留 `entity.space_id in allowed_spaces`（对齐 artifact_overview 的 space 过滤语义）。返回 `[{artifact_id, title, node_paths, keywords, score}]`。
    - `artifacts_for_term(self, term: str, *, user) -> list[dict]`：能力/关键词反查（关键词/能力非实体，按边 metadata 过滤，per research §2.4）。`sync_to_async` 查询活跃 `KnowledgeEdge`（relation=RELATES_TO, invalid_at IS NULL, expired_at IS NULL, metadata source=artifact）——ORM 查询（**非 raw SQL**，不触碰 graph_store 的递归 CTE 收口）；Python 内过滤 `term in metadata.keywords or term in metadata.node_paths`（跨后端安全，避免 SQLite JSON 谓词坑）；bounded（`select_related` + 上限常量如 500）。hydrate source artifact 实体 + access_scope（同上按 space 过滤）。返回同 `artifacts_for_repo` 形态。
    - 全部方法：`user is None` → 返回空（fail-closed）；结构化事件 `artifact_associations_queried`（component=knowledge, category=caller, + kind + result_count + duration_ms）；只读不写。async ORM 一律 `sync_to_async`。
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API 只读查询 | 未受信用户请求任意 artifact_id / repo_id / term，必须经 access_scope fail-closed 过滤，禁止越权可见他项目工件/仓库 |
| 边 metadata 读取 | metadata 是内部派生数据；查询只读，不回写 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-98-09 | Information Disclosure | 跨项目关联查询越权 | mitigate | 三向查询强制 `resolve_allowed_project_ids`（可见 Space）/ `resolve_allowed_repository_ids`（可见仓库）过滤，越权 target/source 剔除；`user=None` → 空（fail-closed，对齐 access_scope 语义） |
| T-98-10 | Denial of Service | term 反查全表扫描 | mitigate | `artifacts_for_term` ORM 查询限定活跃 RELATES_TO + source=artifact，`select_related` + 结果上限常量（如 500）；Python 内 metadata 过滤，避免跨后端 JSON 谓词坑；端点 best-effort 不 500 |
| T-98-11 | Tampering | 绕过图访问收口 | mitigate | 关联遍历走 `graph_store.neighbors`（不写裸递归 CTE SQL，遵循 graph_store 收口纪律）；term 反查用 ORM 简单过滤（非递归 raw SQL），不违反 raw-SQL 收口约束 |
| T-98-12 | Denial of Service | 查询/观测反噬 | mitigate | 端点异常 best-effort 捕获返回空结构不 500；服务层观测 best-effort |
| T-98-SC | Tampering | npm/pip/cargo installs | accept | 本 plan 不安装任何包（纯仓内 Python：service + adrf view + url），无供应链面 |
</threat_model>
