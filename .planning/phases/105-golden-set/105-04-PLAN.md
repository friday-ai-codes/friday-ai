<objective>
建立 golden set 回归门禁（ROUTE-08，CONTEXT §golden set 与 CI 门禁）：版本库内 JSON fixture（含真实事故用例与跨组样本）+ 离线纯函数评估 harness（零网络、全量 < 5s）+ 进默认 pytest suite 的门禁测试（随 `.github/workflows/ci.yaml` server-ci job 自动跑，不单开 job）。此后每一次排序改动（含本 phase 后续 plan 与 Phase 106 公式重构）都能被客观判定为改进还是退化。

**定位**：回归门禁而非优化目标（ROUTING-RANKING §7.2：10–50 条只能检出大幅退化）。**注意**：Phase 105 不修复尺寸偏置（pivoted normalization 归 Phase 106），「高三提分专项」用例在 Phase 105 baseline 下 Top-1 可能仍是 study-app——这是预期基线，不是失败；机制断言只锁本 phase 已成立的性质（分解恒等/排序稳定/确定性），「breadth 偏置消除」断言留给 Phase 106 翻转（其 SC-1 明确此事）。

Purpose: 解决「每次排序改动靠人肉判断」。
Output: harness 模块 + 三个 fixture 文件 + 门禁测试。
</objective>

    - case 输入形状（与 fixture 对齐）：`{"id": str, "query": str, "label_source": "human"|"weak", "cross_group": bool, "expected_repos": [repo_id...], "node_hits": [同 Stage 0 hit 形状]}`。
    - `evaluate_cases(cases, *, theta_abs, theta_margin, theta_med) -> EvalReport`：逐 case 调 `aggregate_and_score(case["node_hits"])` 得排序候选 → 计算 per-case：`recall_at_5 = |expected ∩ top5_ids| / |expected|`、`mrr_at_10 = 1/rank(首个 expected in top10)`（未进 top10 → 0）、`top1_correct = top1 ∈ expected`、`confidence = derive_confidence(降序分数, θ...)`。汇总：均值 Recall@5 / MRR@10、Top-1 正确数、**误自动选中率** `count(conf=="high" and not top1_correct) / count(conf=="high")`（分母 0 → 0.0）；human/weak 标签来源分开统计（per CONTEXT）。`EvalReport` dataclass 含汇总指标 + `per_case: list[CaseResult]`（CaseResult 含 candidate 排序、首位 breakdown、confidence），并可 `to_dict()`（供 baseline JSON 序列化）。
    - `bootstrap_ci(per_case_values, *, b=1000, seed=42)`：`random.Random(seed)` 有放回重采样 B=1000，返回 (p2.5, p97.5)。**禁止引入 numpy/scipy**（RESEARCH 明示）。
    - `diff_reports(baseline_dict, current_report) -> str`：输出逐例 diff——improved（变好 case id 列表）、regressed（变坏列表），regressed 每条附「baseline 首位 vs 当前首位 + 两版 breakdown 对照」；格式化为多行字符串供 pytest 失败消息直接输出。
  </action>
