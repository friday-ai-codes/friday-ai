4. `class CompletionWritebackService`，核心方法：

```
async def awrite_back(
    *,
    feishu_project_key: str,
    work_item_type: str,
    work_item_id: int | None,
    title: str,
    results: list[RepoResult],
    space=None,                      # projects.models.Space；None 时经 feishu_project_key 反查
    feishu_document_id: str = "",
    doc_markdown: str = "",          # 非空且有 document_id 才 append
    initiated_by_user_id: str | None = None,
) -> tuple[dict[str, Any], dict[str, Any]]
```

语义（严格镜像现 `_write_results_back` 的条件与返回形状）：
- 两个返回 dict 初值均 `{"status": "skipped"}`。
- space 解析：入参 space 优先；否则 `await Space.objects.filter(feishu_project_key=feishu_project_key).afirst()`（lazy import `projects.models.Space`）。
- **守门（P3）**：三元组任一缺失（project_key 空 / work_item_id None / work_item_type 空）或 space 解析不到 → 记 `writeback_skipped` 事件（kv：`reason`、`feishu_project_key`、`work_item_id`、`category="caller"`、`component="delivery"`、`initiated_by_user_id=initiated_by_user_id or "system"`）后直接返回双 skipped，**不抛异常**。
- 文档 append：space 且 feishu_document_id 且 doc_markdown 非空时，`create_feishu_doc_client_for_project(space)` → `append_markdown`；成功 `{"status": "appended", **result}`，异常捕获（`ValueError`/`FeishuDocAPIError`/宽 `Exception`，镜像现分支）→ `{"status": "error", "error": str(exc)}`。
- 评论：space 存在时 `create_feishu_client_for_project(space)` → `add_comment(feishu_project_key, work_item_id, work_item_type, render_comment_lines(...))`；ok→`{"status": "written"}`，否则/异常→`{"status": "error", "error": ...}`（错误文案 "Feishu 工作项评论写入失败" 保留）。
- 收尾事件：任一为 error → `logger.warning("writeback_failed", document_status=..., comment_status=..., error=..., duration_ms=..., category="caller", component="delivery", initiated_by_user_id=...)`；全成功/部分写入 → `logger.info("writeback_completed", ...)` 同 kv 集。**绝不重试、绝不上抛**（整个方法体外层兜底 try/except 记 `writeback_failed` 后返回 error 状态 dict——观测与回写都不反噬调用方）。
- 异常文本仅入内部日志，不写进飞书评论正文（评论正文只用结构化 RepoResult 字段——Security Mistakes 表「回写内容把上游异常文本原样写进飞书评论」）。
