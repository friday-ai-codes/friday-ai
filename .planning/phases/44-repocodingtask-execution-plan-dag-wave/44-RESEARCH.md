## Summary

本 phase 是纯后端、纯内部代码工作：在 `delivery` app 立一个新模型 `RepoCodingTask`（逐项镜像现有 `RepoResearchTask` 形状），配一个单一写入入口 service `RepoCodingTaskService`（镜像 `ResearchService` 的 INV-6 范式 + grep 守护），然后改造 `AICodingNode` 把当前「一把梭全并行 dispatch + 一次性 resume」改成「按拓扑 wave 分批 dispatch，wave N 全终态才推 wave N+1」，**复用 Phase 43 已闭环的 callback 驱动 resume 通路**（`_schedule_workflow_resume` → `_continue_after_node` → 节点重入），不另造调度循环。无任何新第三方依赖，无新外部服务，全部能力在现栈内闭环（Django 5.1+ / Python 3.14 / adrf 异步）。

最关键的已核实事实：**`execution_plan[].dependencies` 引用的是其他 execution_plan 项的 `id`（task id），不是 `repository_id`**——`workflows/schemas/technical_plan.py` 的 dataclass 注释与 JSON Schema 描述均逐字写明「Task IDs this task depends on」，且 `plan_validator._check_acyclic` 已按 task id 建图检测环。因此 service 必须先按 task id 建任务级 DAG，再投影/折叠为仓级 `depends_on` 边（同仓多 task 取依赖层级最大值作为该仓 wave），最后按 Kahn 分层。另一关键事实：环检测**已有现成可复用纯函数** `plan_validator.validate_plan`（check 名 `dependency_cycle`，三色 DFS + 显式栈防 DoS），不要重写。

向后兼容是零回归命门：当 `execution_plan` 全部 `dependencies` 为空时，拓扑分层必须退化为单 wave（wave 0）全并行，逐字保留当前 `AICodingNode` 的 `asyncio.gather(..., return_exceptions=True)` 行为。失败语义按 CONTEXT 锁定：单仓失败隔离（同 wave 兄弟不受影响）、wave gate 用「全终态」（done|failed）而非「全 done」、下游 `depends_on` 链遇上游 failed 标 `failed` + `error={reason: "upstream_failed"}` 不 dispatch、**不做自动回滚**（已成功仓正常出 MR，`rollback_plan` 仅人工指引）。

**Primary recommendation:** 新建 `delivery/models/repo_coding_task.py`（镜像 `research_task.py`）+ `delivery/services/repo_coding_task_service.py`（镜像 `research_service.py`）+ `services/plan_orchestration/` 下一个入口无关的 wave 编排 helper（镜像 `resume.py` / `research_aggregation.py`），AICodingNode 仅做「读 RepoCodingTask 行 → 判当前 wave → dispatch 当前 wave pending 仓 → waiting_event；resume 时回填终态 → 推下一 wave 或收尾」的薄接线。迁移序号 `0017`。复用 `plan_validator.validate_plan` 做环检测；复用 `_schedule_workflow_resume` 不改其契约。

### Pattern 1: 模型逐项镜像 RepoResearchTask（同 app 姊妹模型）
**What:** `RepoCodingTask` 字段形状逐项对齐 `RepoResearchTask`（UUID pk、跨 app FK 字符串前向引用、`subagent_session SET_NULL`、`attempt`、`error JSONField`、`db_table` + 中文 verbose_name + indexes、模型层零业务方法）。

```python
# Source: 镜像 server/delivery/models/research_task.py（已核实范式）
import uuid
from django.db import models


class RepoCodingTaskStatus(models.TextChoices):
    """RepoCodingTask 子任务级状态枚举（4 态，逐字对齐 DOMAIN §14；不含 stale）。"""
    PENDING = "pending", "待派发"
    RUNNING = "running", "编码中"
    DONE = "done", "已完成"
    FAILED = "failed", "失败"


class RepoCodingTask(models.Model):
    """每仓 wave 编码子任务（操作态脊柱 + 拓扑调度，DOMAIN §6/§14）。"""
    id = models.UUIDField(primary_key=True, default=uuid.uuid4, editable=False)
    # 真实 FK 指向 PlanVersion（v0.7 已建表，同 app 无迁移耦合；区别于 PlanSession 软引用）
    plan_version = models.ForeignKey(
        "delivery.PlanVersion", on_delete=models.CASCADE, related_name="coding_tasks",
    )
    repository = models.ForeignKey(
        "repositories.Repository", on_delete=models.CASCADE, related_name="+",
    )
    wave = models.IntegerField(default=0)  # 拓扑层级，0-based；service 写入
    depends_on = models.ManyToManyField(
        "self", symmetrical=False, blank=True, related_name="dependents",
    )
    status = models.CharField(
        max_length=16, choices=RepoCodingTaskStatus.choices,
        default=RepoCodingTaskStatus.PENDING,
    )
    produced_artifacts = models.JSONField(default=dict, blank=True)  # 本 phase 仅立字段
    follow_openspec = models.BooleanField(default=False)  # SDD 扩展点，本 phase 不消费
    subagent_session = models.ForeignKey(
        "subagent.SubAgentSession", on_delete=models.SET_NULL,
        null=True, blank=True, related_name="+",
    )
    attempt = models.IntegerField(default=0)
    error = models.JSONField(default=dict, blank=True)
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        db_table = "delivery_repo_coding_task"
        verbose_name = "仓库编码子任务"
        verbose_name_plural = "仓库编码子任务"
        indexes = [
            models.Index(fields=["plan_version", "wave", "status"]),
            models.Index(fields=["repository"]),
        ]

    def __str__(self) -> str:
        return f"RepoCodingTask({self.id}, w{self.wave}, {self.status})"
```

### Pattern 3: 入口无关 wave 推进 helper（镜像 resume.py「不造两套」）
**What:** 把「回填终态 → wave gate → 阻断下游 → dispatch 下一 wave / 收尾」抽成入口无关函数，AICodingNode 与（未来）chat 编码入口共用。状态只经 service，幂等（status guard），fail-soft。
**When to use:** WAVE-02 推进逻辑。
**Example:**
```python
# Source: 镜像 services/plan_orchestration/resume.py + research_aggregation.amaybe_complete_research
async def aadvance_coding_waves(plan_version_id, *, service=None) -> dict:
    """回填当前 wave 终态 → 若全终态则阻断下游 + 返回下一 wave 待 dispatch 仓；幂等。"""
    # 1. 读本 plan_version 全 RepoCodingTask（按 *_id 标量 / async for，绝不裸访问 lazy-FK）
    # 2. running 任务按 SubAgentSession.status 回填 done/failed（经 service.mark_*）
    # 3. 当前 wave（= min wave with pending/running）全终态？否 → 返回 {"waiting": True}
    # 4. 有 failed 上游 → 其 depends_on 链下游标 blocked（service.mark_blocked）
    # 5. 下一 wave 有 pending 且 depends_on 全 done → 返回待 dispatch task 列表
```

### Anti-Patterns to Avoid
- **新建调度循环 / 轮询 / 定时器：** CONTEXT 硬约束。wave 推进必须由容器回调 `_schedule_workflow_resume` 触发节点重入自驱。
- **在模型层写 create/save/状态变更方法：** 违反 INV-6，grep 守护会 fail。
- **在 async 上下文裸访问 lazy-FK（`task.repository` / `task.subagent_session`）：** 触发 `SynchronousOnlyOperation`。用 `task.repository_id` 标量 / `afirst`/`aget`/`async for`。
- **把 `dependencies` 当 `repository_id` 解析：** 它是 task id（见 User Constraints + Code Examples）。误解直接导致 wave 分层全错。
- **wave gate 用「全 done」而非「全终态」：** 失败仓永远不会 done，会让整条流程无限挂起。必须 `done|failed` 都算终态。
- **自动回滚 / 删已成功仓分支：** v0.8 显式非目标。部分成功照常出 MR。

## Common Pitfalls

### Pitfall 1: `dependencies` 引用语义误判（task id vs repository_id）
**What goes wrong:** 把 `execution_plan[].dependencies` 当成 repository_id 列表去建仓级边，wave 分层全错。
**Why it happens:** 字段名 `dependencies` 不带后缀，凭直觉易误判。
**How to avoid:** 已核实——`dependencies` 是**其他 execution_plan 项的 `id`（task id）**。service 须：(1) 用 task id 建任务级 DAG；(2) 把每个 task 映射到其 `repository_id`；(3) 任务边 `taskA → taskB`（A 依赖 B）投影为仓边 `repo(A) → repo(B)`（去自环：同仓内部依赖不产生仓级边）；(4) 仓的 wave = 该仓所有 task 在任务级 DAG 中层级的最大值（保证所有依赖满足）。
**Warning signs:** 同仓多 task 时 wave 计算分歧；依赖跨仓但被当成同仓。
**Source:** [VERIFIED: workflows/schemas/technical_plan.py:34 `dependencies: list[str]  # Task IDs this depends on` + JSON Schema:161 + plan_validator.py:216-225 按 task id 建图]

### Pitfall 2: 向后兼容退化单 wave 不彻底（零回归命门）
**What goes wrong:** 改造后空依赖场景行为与当前 `AICodingNode` 全并行不一致（如多了一次 resume 往返、dispatch 顺序变化）。
**Why it happens:** 引入 wave 抽象后，wave 0 单层的 dispatch 路径若不等价于原 `asyncio.gather` 全发，就有回归。
**How to avoid:** 全部 `dependencies` 空/缺失 → 所有仓 wave=0 → 一次性 dispatch 全部（等价现 `coding_tasks = [...]; await asyncio.gather(*)`），单 wave 完成即收尾，**不引入额外 resume 轮次**。建测试断言空依赖路径与现行为字节级一致（succeeded/failed 分离、MR 创建、卡片）。
**Warning signs:** 空依赖集成测试的 dispatch 次数 / resume 次数与现状不符。

### Pitfall 3: async 上下文裸访问 lazy-FK → SynchronousOnlyOperation
**What goes wrong:** wave 推进时写 `task.repository.name` / `task.subagent_session.status` 抛 `SynchronousOnlyOperation`。
**How to avoid:** 用 `*_id` 标量（`task.repository_id` / `task.subagent_session_id`）、`afirst`/`aget`/`aexists`/`async for`，或在 service 内 `@sync_to_async` 同步块里访问。M2M `depends_on` 反查也须 `async for task.depends_on.all()` 或 service 同步块。
**Source:** [VERIFIED: coding.py:875-893 注释明确此约束；CONTEXT Established Patterns]

### Pitfall 4: wave 推进副作用让回调主流程 5xx
**What goes wrong:** wave dispatch 失败/异常上抛，让 `_handle_completed`/`_handle_failed` 回调返回 5xx，runner 重试风暴。
**How to avoid:** wave 推进逻辑全程独立 try/except swallow + `logger.warning` 降级（对齐 `_handle_research_completion` / `cross_repo_relevance` 钩子范式）。`_schedule_workflow_resume` 本身是 fire-and-forget（`loop.create_task`），节点重入异常不回灌回调响应——保持此边界。

### Pitfall 5: 接通 `coding.wave.*` 事件触发覆盖性守护测试 fail
**What goes wrong:** 若本 phase emit `coding.wave.started/completed`，需把两常量从 `RESERVED_EVENTS` 移入 `ALL_EVENTS`；但 event_taxonomy 守护测试断言「`ALL_EVENTS` 每个事件至少被一个 emit 点产出」——只移常量不接 emit 点会 fail，反之 emit 了未移也 fail。
**How to avoid:** 接通事件时**同步**：(1) 常量从 RESERVED 移到 ALL_EVENTS，(2) 在 wave 推进 helper 里真实 emit（经 `PlanSessionService._emit_event` 或对应 plan_version 事件通道——注意 RepoCodingTask 挂 `plan_version` 非 `PlanSession`，须确认 `_emit_event` 的归属对象，可能需经 plan_version→plan→work_item 或新事件通道）。CONTEXT 标此为 Discretion（倾向接通但低优先）。**最安全默认：本 phase 不 emit，保持 RESERVED 不动**，留 Phase 45/46 接。若接，须配套改守护测试。
**Source:** [VERIFIED: event_taxonomy.py:11-13 注释「coding.wave.* 属 v0.8 OUT OF SCOPE」+ ALL_EVENTS 覆盖语义]

### 拓扑分层：task-id DAG → 仓级 wave（Kahn，纯函数）
```python
# Source: 基于 plan_validator._check_acyclic 建图语义 + graphlib（stdlib）
from graphlib import TopologicalSorter, CycleError


def build_repo_waves(execution_plan: list[dict]) -> tuple[dict[str, int], dict | None]:
    """把 execution_plan 折叠为 {repository_id: wave_int}；有环返回 (部分, cycle_report)。

    dependencies 引用其他 execution_plan 项的 id（task id），非 repository_id。
    """
    task_repo = {t["id"]: t.get("repository_id", "") for t in execution_plan if t.get("id")}
    # 任务级 DAG：task → 它依赖的 task（仅保留有效引用）
    task_deps = {
        t["id"]: [d for d in (t.get("dependencies") or []) if d in task_repo]
        for t in execution_plan if t.get("id")
    }
    # 复用 plan_validator 做权威环检测（fail-fast，结构化 cycle）
    from services.plan_orchestration.plan_validator import validate_plan
    report = validate_plan({"execution_plan": execution_plan})
    cycle_errs = [e for e in report["errors"] if e["check"] == "dependency_cycle"]
    if cycle_errs:
        return {}, {"reason": "dependency_cycle", "detail": cycle_errs}

    # Kahn 分层：TopologicalSorter 边方向 = node -> predecessors（依赖先行）
    ts = TopologicalSorter(task_deps)
    ts.prepare()
    task_wave: dict[str, int] = {}
    layer = 0
    while ts.is_active():
        ready = list(ts.get_ready())  # 同层（依赖已满足）
        for tid in ready:
            task_wave[tid] = layer
            ts.done(tid)
        layer += 1
    # 仓 wave = 该仓所有 task 层级最大值（保证依赖满足）；空依赖 → 全 wave 0
    repo_wave: dict[str, int] = {}
    for tid, w in task_wave.items():
        rid = task_repo[tid]
        if rid:
            repo_wave[rid] = max(repo_wave.get(rid, 0), w)
    return repo_wave, None
```

### 仓级 depends_on 边投影（去同仓自环）
```python
def build_repo_dep_edges(execution_plan: list[dict]) -> dict[str, list[str]]:
    """taskA 依赖 taskB → repo(A) 依赖 repo(B)（跨仓才成边，同仓忽略）。"""
    task_repo = {t["id"]: t.get("repository_id", "") for t in execution_plan if t.get("id")}
    edges: dict[str, set[str]] = {}
    for t in execution_plan:
        ra = t.get("repository_id", "")
        for dep in (t.get("dependencies") or []):
            rb = task_repo.get(dep, "")
            if ra and rb and ra != rb:  # 仅跨仓成边
                edges.setdefault(ra, set()).add(rb)
    return {k: sorted(v) for k, v in edges.items()}
```
