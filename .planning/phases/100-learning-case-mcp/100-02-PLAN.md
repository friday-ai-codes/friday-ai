新建 normalizer 模块（中文 docstring，标注 Phase 100 / KNOW-01，模式说明照抄 `mcp_plan.py` 风格）。
`async def normalize(request: IngestionRequest) -> list[IngestionEvent]`：

1. 惰性 import `mcp_tools.models.McpLearningCase`，`select_related("context", "technical_plan")` 按 `id=request.source_id` 查询；源缺失 → `knowledge_normalize_source_missing` warning + 返回 `[]`（mcp_plan.py 同款）。
2. **learning_case 主事件**：
   - `kind=EntityKind.LEARNING_CASE`、`origin=EntityOrigin.MCP`、`source_kind="learning_case"`、`source_id=str(case.id)`（natural key 规则表 100-01 已定版）。
   - `title=case.title`；`content` 取 `case.embedding_text`（向量文本主料，字段已有）——为空时回退 markdown 组装（Claude's Discretion）：`# {title}\n\n## 问题\n{problem}\n\n## 根因\n{root_cause}\n\n## 解法\n{solution}\n\n## 结果\n{outcome}` + repositories/files/tests 列表拼接。
   - `payload` 摘要（不复制全文）：`work_item_type`、`work_item_id`、`outcome`、`repositories`、`files`、`symbols`、`mr_urls`、`technical_plan_id`（str 或 ""）。
   - `space_id`：`case.context.space_id` 优先，缺则 `case.technical_plan.space_id`，皆缺为 None（str 化）；`repository_id=None`（案例跨仓，不绑单仓）；`event_time=case.created_at`。
   - 出边：`case.technical_plan_id` 非空时挂 `EdgeSpec(relation=EdgeRelation.REFERENCES, target_entity_id=generate_entity_id("tech_plan", "mcp_technical_plan", str(case.technical_plan_id)))`（REQUIREMENTS KNOW-01 指定 REFERENCES 关联 tech_plan；目标实体由 mcp_plan.py normalizer 负责入图，边阶段幂等，目标未入图前边写入撞不存在实体由 graph_store 容忍——沿用 task_result.py 同款「先建边后补实体」语义，若 graph_store.add_edge 有 FK 强约束则本 EdgeSpec 挂在事件上等待阶段 B 统一处理即可，两端实体不齐时该边写入失败仅 warning 不 raise）。
3. **work_item 锚双事件**（锚料判定：`case.context` 非 None 且 `context.feishu_project_key`、`case.work_item_type`、`case.work_item_id` 三者齐备）：
   - 照抄 `mcp_plan.py` L74-101：`kind=EntityKind.WORK_ITEM`、`origin=EntityOrigin.MCP`、`source_kind="feishu_work_item"`、`source_id=f"{context.feishu_project_key}:{case.work_item_type}:{case.work_item_id}"`（禁止自造锚格式）、title/content 取 context.name/description 轻量锚、payload 同款字段。
   - 锚事件出边：`EdgeSpec(relation=EdgeRelation.RELATES_TO, target_entity_id=generate_entity_id("learning_case", "learning_case", str(case.id)))`——**不用 exclusive**（一个 work_item 可关联多条案例，与 HAS_PLAN 单方案语义不同）。
   - 返回 `[work_item_event, learning_case_event]`（锚在前，mcp_plan.py 事件顺序约定）。
   - 锚料任一缺失 → `knowledge_normalize_anchor_context_missing` warning + 返回 `[learning_case_event]` 单事件降级。
结构化日志走 `structlog.get_logger(__name__)`，事件名沿用 knowledge_normalize_* 前缀，kv 字段含 source_kind/source_id/trigger。
