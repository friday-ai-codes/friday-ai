1. **`async def notify_channels(event, channels: list[str]) -> dict[str, str]`**（单一分发出口）：
   - 入参 `event` 为 74-01 `AlertEvent` 实例，`channels` 为 rule.channels 子集（来自 74-02）。
   - 模块顶部 `started = time.perf_counter()`；逐通道独立 try/except：
     - `"email" in channels` → `email_status = await _send_email(event)`（返回 `sent`/`skipped`/`failed`）。
     - `"feishu" in channels` → `feishu_ok = await _send_feishu(event)`（bool）。
     - `"webhook" in channels` → `webhook_ok = await _send_webhook(event)`（bool）。
   - 汇总 `notified = [成功通道名]`；`event.email_sent = email_status`（未选 email 则保留 `pending`→可置 `"—"`/不变，按 74-01 默认 pending；选了才回写）；`event.notified_channels = notified`；`await event.asave(update_fields=["email_sent","notified_channels"])`（**整段 try/except** 回写失败仅 warning 不反噬）。
   - `logger.info("alert_notified", category="caller", component="alerting", source="scheduler", event_id=event.id, severity=event.severity, channels=channels, notified=notified, email_status=email_status, duration_ms=int((perf_counter()-started)*1000))`（started/completed 语义；失败分通道在各 helper 内 warning）。
   - 返回 `{"email": email_status, "feishu": "sent" if feishu_ok else "skipped/failed", "webhook": ...}`（供测试断言）。
   - **整函数最外层 try/except** 兜底：任何意外异常 warning `alert_notify_failed` 返回空 dict，绝不抛回评估器（最高优先级：通知绝不反噬评估）。
2. **`async def _send_email(event) -> str`**（EMAIL，返回 sent/skipped/failed）：
   - 读开关 `enabled = await aget_bool_setting(SettingKeys.ALERT_EMAIL_ENABLED, False)`；`from django.conf import settings`；`host = getattr(settings, "EMAIL_HOST", "")`。`not enabled or not host` → 返回 `"skipped"`（SMTP 未配置/未开启不算失败，绝不反噬）。
   - 收件人：`raw = await aget_setting(SettingKeys.ALERT_EMAIL_RECIPIENTS, "")`；解析为列表（兼容逗号分隔与 JSON 列表，逐项 strip 去空）；空 → `"skipped"`。
   - 主题/正文：subject = `f"[{event.severity}] {event.title_zh or '系统告警'}"`；body = 纯文本（per 74-CONTEXT Claude's Discretion 倾向简洁纯文本）拼 `title_zh` + `rule_info.expr` + `started_at` + 当前值；**正文经 `redact_secrets_in_text(body)` 脱敏**（即便 rule_info 已是元数据，纵深防御）。
   - 发送：`from django.core.mail import send_mail`；`await sync_to_async(send_mail, thread_sensitive=True)(subject, redacted_body, settings.DEFAULT_FROM_EMAIL, recipients, fail_silently=False)`，整段 try/except——成功返回 `"sent"`，异常 warning `alert_email_failed`(仅记 event_id/severity/收件人数，**不记收件人明文地址/不记异常含凭证文本** → `error=redact_secrets_in_text(str(exc))`) 返回 `"failed"`（绝不反噬）。
3. **`async def _send_feishu(event) -> bool`**（复用 FeishuIMService idiom）：
   - 读 `chat_id = await aget_setting(SettingKeys.ALERT_FEISHU_CHAT_ID, "")`；空 → False（未配置，跳过）。
   - `from services.feishu_im import FeishuIMService`；`im = await FeishuIMService.create(None)`（系统默认飞书凭证，project=None）；构造红/橙卡片（按 severity 取 header template：P0=red/P1=orange/P2=blue），`content = redact_secrets_in_text(标题 + rule_info.expr + 持续/当前值)`（lark_md）；`await im.send_card(receive_id=chat_id, receive_id_type="chat_id", card=card)`。整段 try/except 异常 warning `alert_feishu_failed`(error=redact_secrets_in_text(str(exc))) 返回 False（绝不反噬）。
   - 卡片构造镜像 `AlertRuleHook._send_feishu` 的 card dict 结构（config.wide_screen_mode + header.template + elements markdown），不引新依赖。

   - `async with httpx.AsyncClient(timeout=10) as client: resp = await client.post(url, content=redacted)`；`resp.status_code>=400` → warning 返回 False；否则 True。整段 try/except 异常 warning `alert_webhook_failed`(error=redact_secrets_in_text(str(exc))) 返回 False（绝不反噬）。
