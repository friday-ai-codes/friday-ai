Output: `ingest_orchestrator` 服务 + dispatch/status 端点 + 后端守护测试。
本 plan 是**编排既有能力**，绝不新建底层摄取/检索机制。

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /delivery/ingest/ | 不可信 board_url/mr_url 进入编排 |
| 编排 → 飞书 / git platform | 仅经项目加密凭证 client + 匹配 Repository 的 git platform client（不抓取任意用户 URL） |
| 编排 → IngestRun.steps/error | 上游响应/异常文本可能夹带凭证，落库前须脱敏 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-01 | Tampering / SSRF | `ingest_from_urls` 步 1/3 | mitigate | board → 仅解析三元组后经项目加密凭证 `create_feishu_client_for_project`；MR → 必须 `aresolve_repo_and_mr` 命中已落库 Repository 才走其 git platform client；解析不出/不匹配 → skipped，绝不 fetch 原始 URL |
| T-32-02 | Information Disclosure | `IngestRun.error` / `steps[*].error` | mitigate | 步级/编排级 error 落库前复用 `_redact_secrets` + 截断（抹 Bearer/键值凭证），diff 原文/响应 body 绝不入 steps；payload 仅摘要（archive_id/commit_sha/统计） |
| T-32-03 | Spoofing / Elevation | dispatch/status 端点 | mitigate | 两端点 `IsAuthenticated`；状态端点按 run_id 只读，不旁路触发摄取 |
| T-32-04 | DoS | 后台编排 | accept | 经 `run_in_background` 脱离请求生命周期，单 run 三步有界（archive 既有 MAX_* 上限）；批量/限流非本 phase 范围 |

无新增 npm/pip/cargo 依赖 → 供应链门（T-32-SC）不适用。
</threat_model>
