<objective>
为 VIS-01 实现后端「截图 → 多模态 LLM 提语义 → 文本 query → 召回需求」编排与最小 REST。

链路：上传截图（瞬态 bytes）→ 经既有 provider 解析选 vision 能力模型（`ProviderConfigService` + `model_modalities`）→ 调多模态 LLM 提取「文字 / UI 元素 / 业务意图」结构化语义 → 拼文本 query → 喂**既有**交付知识检索 `DeliveryKnowledgeSearchService.search_similar(entity_kinds=["work_item"])` 召回 work_item 类需求 → 结构化返回。

Purpose: 立起 VIS-01 标准 1（vision 提语义）+ 标准 2（文本 query 召回需求）+ 标准 3（不建图片向量库）的可自动验证后端，对齐 35-UI-SPEC 的 `POST /delivery/screenshot-recall/` 契约，供前端面板消费。
Output: `screenshot_recall.py` 服务 + `multimodal.validate_image_bytes` 复用 helper + `ScreenshotRecallView` REST + 守护测试。
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | 已登录用户经 multipart 上传不可信图片字节（大小/类型/内容均不可信） |
| service→LLM provider | 截图 bytes → base64 inline 送多模态 LLM（凭证经既有加密解析） |
| service→检索面 | 提取的文本 query 喂既有交付知识检索（read-only 向量召回） |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-01 | Denial of Service | ScreenshotRecallView 上传 | mitigate | 后端权威 validate_image_bytes 双校验 ≤10MB + MIME sniff，超限/非图片即 400，不进 LLM |
| T-35-02 | Tampering / Info Disclosure | 原图处理 | mitigate | 仅瞬态 bytes → base64 inline；绝不写盘/不持久化原图/不建图片向量库（VIS-01 标准 3） |
| T-35-03 | Information Disclosure | recall_from_screenshot 召回 | mitigate | search_similar 经 resolve_allowed_project_ids(request.user) 访问域 + IsAuthenticated；不跨用户泄漏 work_item |
| T-35-04 | Information Disclosure | degraded_reason / 日志 | mitigate | 降级文案为固定中文串；异常仅记 error_type 不记 str(exc)（防回显图片/密钥），凭证经既有加密解析零 env |
| T-35-05 | Spoofing (prompt injection) | 截图内容影响召回 | accept | 召回为 read-only 向量检索、不触发任何写/动作；query 仅文本，影响面限于检索结果排序 |

> 无 npm/pip/cargo 新依赖安装（复用既有栈）→ 无供应链 T-35-SC / 无 Package Legitimacy Gate 适用。
> 无新模型 / 无 migration（截图瞬态、召回复用既有面）。
</threat_model>
