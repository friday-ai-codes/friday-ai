<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 浏览器路由守卫 → 后端 status 接口 | getSetupStatus() fetch 结果决定是否进向导 |
| 路由守卫 → 状态缓存（authStore） | needsSetup 读取错误会导致 fail-open 或 fail-closed |
| setup.vue POST → 后端 init 接口 | 提交管理员信息，403 响应处理不当影响用户体验 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-04 | Tampering | router.beforeEach — status fetch 失败时 fail-open 误导已有实例进向导 | mitigate | catch 块显式设置 authStore.needsSetup = false（fail-safe per D-C 决策）；宁可不进向导，不误导已有生产实例 |
| T-1-05 | Spoofing | setup.vue POST 通过 api/client.ts 的 post() 触发全局 auth:forbidden 事件跳转 /403 | mitigate | setup.vue POST 保持原始 fetch 调用（不通过 api/client.ts post()），避免 403 触发全局重定向（per D-D 决策 + PATTERNS.md 警告） |
| T-1-06 | Tampering | router.beforeEach 中 setup 分支在 initAuth() 之后执行导致 /me 401 无限重置循环 | mitigate | setup 分支代码（含 return next('/setup')）必须在 "if (!authStore.isInitialized) { await authStore.initAuth() }" 之前；全新部署未初始化时跳过 initAuth（per RESEARCH.md Pitfall 2） |
| T-1-SC | Tampering | 无新包安装 | accept | Phase 1 前端无新外部依赖，无需 slopcheck |
</threat_model>
