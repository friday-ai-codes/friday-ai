    新建命令（BaseCommand，骨架照搬 verify_payload_consistency；中文 docstring 注明 INGEST-06/07 与失败恢复矩阵兜底职责）：
    - `add_arguments`：`--fix`（action="store_true"，默认 dry-run）、`--limit`（int，默认 0=全量，抽检上限）。
    - `handle` 内 `asyncio.run(self._run(...))`（verify_payload_consistency 的 _dispatch_and_drain 同款形态）。
    - 五检查项按 RESEARCH 表实现：
      1. 每个 `is_latest=True` 版本：`client.retrieve(collection_name=DELIVERY_KNOWLEDGE_COLLECTION, ids=version.qdrant_point_ids, with_payload=["is_latest","version"])` 批量取——缺点或 payload is_latest!=true / version 不匹配 → 计 missing/wrong；--fix → `await revectorize_version(version)`（重嵌入 upsert，不重走版本翻转）。
      2. 每个 `is_latest=False` 版本（限有 qdrant_point_ids 者）：点要么不存在、要么 payload is_latest=false——仍 true → 计 stale_latest；--fix → `tombstone_points` + `delete_points`。
      3. Qdrant `client.scroll` filter is_latest=true：按 entity_id 聚合，多 version 命中 → 计 multi_latest；--fix → 按 DB 真值 tombstone 非 latest 的点。
      4. 孤儿点：scroll 结果 payload 的 version_id 不在 PG → 计 orphan；--fix → `delete_points`。
      5. DB 不变量抽检（report-only，恒不 fix）：单实体多 latest（约束兜底理论恒 0）、`invalid_at <= valid_at`、`vector_synced=False` 的 latest 计数。
    - 每 entity/version 检查体 try/except：异常 → skip 计数 + `logger.warning("knowledge_reconcile_item_skipped", ...)`，不崩整命令。
    - 输出：每检查项一行计数 + 末行 `Summary: checked=N missing=N stale_latest=N multi_latest=N orphans=N db_anomalies=N skipped=N fixed=N`（test_reconcile 断言锚点）。
