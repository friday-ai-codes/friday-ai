  <action>
新建 `server/delivery/services/sdd_spec_service.py`，class `SddSpecService`：
- async `create_draft(self, *, plan_version_id, repository, work_item, content, change_kind="proposal")` -> SddSpec：
  1. 先 `document = await DocumentService().create_internal_spec(work_item=work_item, repository_label=getattr(repository, "name", str(repository)), content=content)`（落 Document(sdd_spec)）。
  2. `@sync_to_async` 包裹的 `_get_or_create_locked` 在 `transaction.atomic` 内：`SddSpec.objects.select_for_update().get_or_create(plan_version_id=plan_version_id, repository=repository, defaults={"document": document, "work_item": work_item, "status": SddSpecStatus.DRAFT, "change_kind": change_kind})`。
     - **幂等**（D-49-3）：已存在（同 plan_version_id+repository）则**不重复建**，直接返回既有 SddSpec（created=False 分支）。注意：幂等命中时上一步已经多落了一份 Document——这是可接受的（DocumentService 忠实落文档，SddSpec 层去重），但为减少孤儿文档，**推荐**：先在锁内 `SddSpec.objects.filter(plan_version_id=..., repository=...).select_for_update().first()` 命中则直接返回（跳过建 Document）；未命中再落 Document + 建 SddSpec。**采用此「先查后落」顺序**以避免每次重产都产生孤儿 Document（见开放点说明）。
  3. 返回 SddSpec 实例。
- **async ORM 防裸 lazy-FK**：用 `repository`（已是实例入参，OK）、`plan_version_id`/`work_item` 标量或实例入参；锁内同步上下文可正常访问。
- **INV-6**：SddSpec 所有写收口本方法；模块 docstring 标注「SddSpec 单一写入入口（INV-6）」。
- 状态流转/评审写入方法**不实现**（Phase 50），可留 docstring 注明「Phase 50 扩展位」但不留空方法存根。
在 `delivery/services/__init__.py` re-export `SddSpecService` 进 import + `__all__`。
