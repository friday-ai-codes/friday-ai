<interfaces>
反查链路（全部经既有接口，方向语义已核对）：
- `find_chunk_at(repository_id, file_path, line, *, branch_name="") -> list[dict]`：fail-closed 解析覆盖该行的 chunk(s)，被排除文件返回 `[]`。每项含 `chunk_id/file_path/line_start/line_end/chunk_index`。
- `graph_store.chunk_in_edges(chunk_id: uuid.UUID, *, as_of=None) -> list[EdgeRecord]`：取指向该 chunk 的入边；`as_of=None` **默认只返回当前有效边**（`invalid_at IS NULL AND expired_at IS NULL`），过期 MODIFIES_CHUNK 边天然排除。`EdgeRecord.source_id` = `code_change` 实体 id，`relation` = `MODIFIES_CHUNK`。
- `graph_store.neighbors(entity_id, *, relations=None, direction="out", as_of=None) -> list[EdgeRecord]`：`direction="in"` 取 `target_entity_id=entity_id` 的边（对端在 `source_id`）；`direction="out"` 取 `source_entity_id=entity_id` 的边（对端在 `target_id`）。
- `EdgeRelation`：`HAS_PLAN`(work_item→tech_plan)、`IMPLEMENTED_BY`(tech_plan→code_change)、`REFERENCES`(work_item→document)、`MODIFIES_CHUNK`(code_change→chunk)。
- `KnowledgeEntity` 字段：`id/kind/title/source_kind/source_id/project_id`。

反向多跳方向（核对方向后唯一正确写法）：
- code_change ← `IMPLEMENTED_BY` tech_plan：`neighbors(code_change_id, relations=[IMPLEMENTED_BY], direction="in")` → 边 `source_id` = tech_plan。
- tech_plan ← `HAS_PLAN` work_item：`neighbors(tech_plan_id, relations=[HAS_PLAN], direction="in")` → 边 `source_id` = work_item。
- work_item → `REFERENCES` document：`neighbors(work_item_id, relations=[REFERENCES], direction="out")` → 边 `target_id` = document。

结构化返回契约（REST 与 MCP 同形）：
`{"chunks": [{chunk_id,file_path,line_start,line_end,chunk_index}], "related_work_items": [{entity_id,title,source_kind,source_id,project_id}], "related_documents": [{entity_id,title,source_kind,source_id}], "paths": [{chunk_id,code_change_id,tech_plan_id,work_item_id,document_id?,relations:[...]}]}`
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client/agent → REST/MCP 反查 | 未受信入参 (repository_id, file_path, line, chunk_id) 跨入；可能探测被排除文件的存在性/关联需求 |
| 反查 service → 图谱/ChunkRegistry | 只读图谱投影；历史失效边（invalid_at）不得污染当前反查 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34A-01 | Information Disclosure | reverse_lookup (file_path/line 入参) | mitigate | 经 `find_chunk_at` 复用 Phase 22 单一匹配器 fail-closed：被排除文件返回空 chunks/related，不暴露 chunk/行/关联实体（Task 1 guard ②，专测） |
| T-34A-02 | Information Disclosure | reverse_lookup (chunk_id 直接入参) | mitigate | chunk_id 入参先由 ChunkRegistry 解析 file_path 再经排除匹配器 fail-closed 复判，绕过 find_chunk_at 也不放行（Task 1，专测） |
| T-34A-03 | Information Disclosure | chunk_in_edges 历史边 | mitigate | 默认 as_of=None 当前视图，过期 MODIFIES_CHUNK 边（invalid_at 已置）天然排除，不暴露已失效关联（Task 1 guard ③，专测） |
| T-34A-04 | Elevation of Privilege | REST/MCP 端点 | mitigate | REST `IsAuthenticated`；MCP 复用 McpToolView 的 AccessToken/CookieJWT + IsAuthenticated；未认证 401/403（Task 2/3 专测） |
| T-34A-05 | Tampering | 反查 service | mitigate | 纯读：service 不调任何写接口（add_edge/invalidate/save/upsert），测试以 must_haves truth + 代码审查守护 |
| T-34A-06 | Denial of Service | 多跳遍历 fanout | accept | 复用 graph_store neighbors（单跳 ORM，无递归 CTE）+ 有界 chunk/code_change 集合；反查为低频读，风险低 |
</threat_model>
