模块级常量：`CANDIDATE_LIMIT: Final[int] = 20`（理由写进注释：生产 1.2% 的名字对应 >20 个符号，20 条已能覆盖绝大多数消歧场景，超出时给 `total_candidates` 让 agent 知道自己看到的不是全部）；事件常量 `_EVENT_SYMBOL_AMBIGUOUS: Final[str] = "code_graph_symbol_ambiguous"`。

两个 `@dataclass(frozen=True, slots=True)` 值对象：
- `SymbolCandidate`：`symbol_id: str` / `name: str` / `symbol_type: str` / `file_path: str` / `start_line: int` / `signature: str`。`signature` 的字段注释必须写明它在图内**恒为空串**、由壳层 ORM 补取的理由（见 read_first 的 `loader.py:354-356`），否则下一个读代码的人会以为解析器坏了。
- `SymbolResolution`：`resolved: str | None` / `candidates: tuple[SymbolCandidate, ...]` / `total_candidates: int` / `truncated: bool` / `query: str`。

公开函数 `resolve_symbol_in_graph(graph, *, symbol_id=None, name=None, file_path=None, symbol_type=None) -> SymbolResolution`：
① `symbol_id` 非空 ⇒ **uid 优先**：在 `graph` 里就直接 `resolved=symbol_id`、`candidates=()`、`total_candidates=1`；不在图里则 `resolved=None`、`candidates=()`、`total_candidates=0`（让壳层区分「不存在」与「被 exclusion 挡掉 / 不在子图内」）。此分支**绝不**退化去按名字搜。
② 否则按 `name` 精确匹配节点属性 `name`（大小写敏感），再用可选的 `file_path`（相等或作为后缀匹配，兼容调用方给相对路径片段）与 `symbol_type`（大小写不敏感）收窄——两个收窄参数是 Pitfall 2 §4 要求的「一次收敛，不要往返两轮」。
③ 命中恰 1 个 ⇒ `resolved` 置该 id。命中 0 个 ⇒ 三项全空。命中 ≥2 个 ⇒ `resolved=None`，按 `(file_path, start_line, symbol_id)` 稳定排序后取前 `CANDIDATE_LIMIT` 条，`total_candidates` 记**未截断前**的总数，`truncated = total_candidates > CANDIDATE_LIMIT`，并调一个独立埋点函数 `_log_symbol_ambiguous(...)`（DEBUG，`component="code_graph"`、`category="sampling"`、只记 `name` 长度与候选数，⛔ 不记符号名本身与文件路径）。

`__all__` 恰四项字母序：`["CANDIDATE_LIMIT", "SymbolCandidate", "SymbolResolution", "resolve_symbol_in_graph"]`。

⛔ 不要写共享的 `_emit()` 日志 helper —— AST 契约要求事件名在**该调用点**静态可解析，包一层就不可解析（Phase 121 有四个 plan 各踩过一次）。
