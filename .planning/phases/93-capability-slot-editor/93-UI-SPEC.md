## Spacing Scale

沿用 Tailwind 4 默认 4px 基准刻度（既有编辑器全程用 `gap-1/2`、`p-3`、`px-2.5` 等）。

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Handle 间距、行内图标-文字间隙（`gap-1`）、圆点-标签 |
| sm | 8px | 紧凑元素间距（`gap-2`）、工具栏按钮内边距 |
| md | 16px | 节点卡内边距（`p-3`≈12px 为既有节点密度例外，见下）、面板分区 |
| lg | 24px | 侧栏分区垂直间距（`space-y-5`≈20px 既有，归入此档） |
| xl | 32px | 布局列间隙 |
| 2xl | 48px | 主区块分隔 |
| 3xl | 64px | 页面级留白 |

**Exceptions（画布密度专属，沿用既有，不得改动以免回归）:**
- 节点卡内边距 `p-3`（12px）、分支行间距 `space-y-1`（4px）—— 画布节点需高密度，沿用 `BaseWorkflowNode.vue` 既有值。
- 附着子节点编组内边距用 `8px`（sm），与父卡 `12px` 区分出"被包含"层级感。
- Handle "+" 追加菜单偏移 `-left-7 / -right-7`（28px）—— 既有热区，磁吸高亮半径与此对齐。

## Typography

沿用既有编辑器字号阶（节点卡为高密度场景，含 sub-12 微标）。

## SLOT-03 — 形状磁吸（连接合法性 + 高亮 + 吸附）

**判定来源（前端权威）:** `useNodeTypesStore` 的 `NodePort` 增 `shape?: string`（消费 Phase 92 经 `/api/node-types/` 暴露的 shape 字段）。`useConnectionValidator` 在既有「防自连 + 四元组重复 + BFS 防环」后追加第 4 条「契约兼容」：
- 解析 `connection.sourceHandle`/`targetHandle` → 源 output port / 目标 input port → 各自 `shape`。
- **空契约通配**：任一端 `shape` 为空（含未声明 / `default` / `error` 通用端口）→ 放行（零回归命门，与后端 `_validate_port_shapes` 同口径）。
- 双端非空且不等 → 拒绝，返回禁止原因文案（`incompatibleBody`，带中文 shape 名）。

**拖拽期视觉态机（三态，prescriptive）:**

| 态 | 触发 | 视觉 |
|----|------|------|
| idle | 未拖拽 | Handle 既有 teal 圆点（10px）/ typed shape 端口着 shape 色（见 Color） |
| compatible-highlight | 拖拽连线中，对所有"形状兼容的目标 input handle" | emerald 光环 `box-shadow: 0 0 0 4px hsl(142 71% 45% / 0.25)` + 圆点放大至 14px；不兼容 handle 降至 `opacity: 0.3` |
| snap-locked | 指针进入兼容 handle 的吸附半径内 | 连接端点吸附到 handle 中心 + handle 放大至 16px + emerald 脉冲（`animate-pulse`） |
| forbidden | 指针悬于不兼容 handle | `cursor: not-allowed` + 该 handle red `hsl(0 72% 51%)` 光环（短暂），不可落点 |

**吸附阈值（prescriptive）:**
- `PORT_SNAP_THRESHOLD = 28px`（屏幕像素，与既有 "+" 热区 `-7`=28px 对齐；按 viewport.zoom 换算到 flow 坐标后比距）。
- 复用 `useAlignmentGuides` 的"距离阈值吸附"思路（既有节点对齐 `SNAP_THRESHOLD=5` 不改），端口吸附为独立常量，新建 composable `usePortSnap.ts`（不污染节点对齐逻辑）。
- 吸附只改"拖拽连接线视觉端点"，落点仍经 `isValidConnection` + `getValidationError` 双重校验（吸附不绕过合法性）。

**实现落点:**
- `WorkflowCanvas.vue`：`:is-valid-connection="validateConnection"` 已接；新增 `@connect-start`/`@connect-end` 驱动高亮态 + `CustomConnectionLine.vue` 消费吸附端点。
- `BaseWorkflowNode.vue`：Handle 着色由 handle-id 语义色升级为"shape 优先 + id 回退"；拖拽期 handle class 绑定 compatible/forbidden 态。
- 高频拖拽路径：兼容性判定为纯函数 + 预建 `shape` 索引 Map（避免每帧遍历），不打 INFO 日志。

## SLOT-04 — 附着子节点编组（澄清节点 ↔ 方案节点）

**目标:** 澄清节点（`clarification_card`）作为方案节点（`ai_plan_research`）的"附着子节点"——视觉成组/连体表达"生命周期绑定"（澄清随方案节点存在），而非孤立节点 + 普通连线。澄清节点的 `feishu_message` 出口可下接吃 `feishu_message` 的节点（发群/通知）。

**选型权衡（两方案，默认 A，最终 plan-phase 定）:**

| 方案 | 机制 | 优点 | 代价 |
|------|------|------|------|
| **A（默认）Vue Flow parent/child** | 澄清节点 `parentNode=方案节点id` + `extent: 'parent'`，dock 到方案节点 clarify 槽右下方 | 原生包含/联动拖拽/相对定位；删父自动级联子（契合"生命周期绑定"）；Vue Flow 一等支持 | 需保证 nodes 数组 parent 先于 child；store 需存父子关系；坐标转相对 |
| B 视觉编组容器 + 系绳 | 独立节点 + `groupId` data 字段 + 自定义虚线"系绳"overlay + 共享外框 | 不改 vue-flow 节点模型；节点保持独立边语义 | 联动拖拽/级联删除需手写；包围盒手算；易与对齐线冲突 |

**推荐 A 理由:** "删方案节点 → 澄清节点一并移除"是 CONTEXT 锁定的生命周期语义，parent/child 的 `extent:'parent'` + 级联删除天然兑现；B 需自行实现级联，回归面更大。

**编组视觉规格（方案 A，prescriptive）:**
- 编组外观：父方案节点（violet/purple 既有）+ 子澄清节点 dock 在父卡 clarify 输出槽（右侧）下方，二者外包一层**琥珀调编组容器**：`bg-amber-500/[0.04]` + `border border-dashed border-amber-400/40` + `rounded-2xl`，内边距 8px（sm）。琥珀呼应澄清语义（既有 clarify 色）。
- 连体连接：父 clarify 槽（`#f59e0b` 凹槽）→ 子澄清节点 input，用**短实线琥珀连接器**（非普通 bezier 边，视觉上"连体"，长度 ≤ 24px）。
- 子节点徽标：澄清子节点左上角 `附着` 徽标（`Badge` 组件，`bg-amber-500/12 text-amber-600`，`text-[10px]`），hover tooltip = `attachedHint`。
- 拖拽：拖父节点整组移动；子节点 `extent:'parent'` 限制在父包围内不可拖离（解除附着经右键/工具栏显式操作 → `detachTitle` 确认）。
- 下游：子澄清节点的 `feishu_message`（cyan）出口为普通 output handle，可正常拉普通 bezier 边连到发群/通知节点（不在编组容器内）。

**端口形状语义可视化（凹槽/凸点，prescriptive）:**
- typed shape 的 **input**（凹槽，如 `clarify`/`clarification_request`）：渲染为 `4px 圆角方形` 描边 handle（concave 隐喻），着 shape 色。
- typed shape 的 **output**（凸点，如 `resume`/`clarification_answer`/`feishu_message`）：渲染为 `4px 圆角方形` 实心 handle（convex 隐喻），着 shape 色。
- 空契约通用端口（`default`/`error`）：保持既有圆形 handle（不变，零回归）。
- 用"方形=能力槽 / 圆形=通用流"双形状语言，让用户一眼区分"契约插槽"与"普通连线点"。

## 节点能力分类视觉（CONTEXT C/D）

三类节点视觉区分（在既有 `nodeVisuals` 色系基础上叠加"能力affordance"，不推翻既有按组配色）：

| 能力类 | 代表节点 | 视觉区分 |
|--------|---------|---------|
| **触发器 Trigger**（流程起点，无入口、不接澄清） | `manual_trigger`/`webhook_trigger`/`feishu_event_trigger` | 既有 blue；**无左侧 input handle**（既有 `inputPorts` 空则不渲染）；左缘起点标记（保持现状即可） |
| **执行器 Executor**（确定性，不接澄清） | fetch_*/create_*/notify_*/git/数据控制等 | 既有 green/orange/blue；标准 in + out + error；**无 clarify 槽**；其 `default`(成功)/`error`(失败) 出口均可接通知，产物出口（如方案/文档）可接文档能力 |
| **可澄清 AI 操作**（带不确定性） | `ai_plan_research`/`ai_coding`/`ai_coding_dispatcher`（`ai_prompt` 候选，plan 定） | 既有 purple；**额外渲染 `clarify` 凹槽（琥珀方形）+ `resume` 凸点**；可附着澄清子节点（SLOT-04） |

**通知能力（`feishu_message`，cyan）:** 几乎所有节点的成功(`default`)/失败(`error`)出口都可经普通连线接到吃 `feishu_message` 的通知节点（`notify_feishu`/`notify_feishu_im`）。视觉：源出口圆点为语义色（绿/红），目标通知节点 input 为 cyan 方形槽——拖拽时 cyan 槽高亮表示"可接通知"。

**文档能力（`feishu_document`，indigo）:** 产出技术方案/编码指派/AI 编码结果/审批结果的节点（`ai_plan_research`/`ai_coding_dispatcher`/`ai_coding`/`human_approval`）可接 `feishu_doc_create`（indigo 方形 input 槽）；`feishu_doc_create` 产物出口再接通知节点 → 推送到群。

**IM 能力门控（CONTEXT D，prescriptive）:**
- 判定（前端）：工作流图中存在 `create_group_chat` 或 `create_work_item_chat` 节点 → 具备 IM 能力（有 chat_id 源）。
- 缺失时：依赖 chat_id 的发群/通知端口与节点**降级**。
- **呈现选型（默认"禁用"，hide vs disable 最终 plan 定）:**

| 选项 | 机制 | 权衡 |
|------|------|------|
| **禁用（默认）** | IM 依赖 handle/节点 `opacity: 0.4` + `cursor: not-allowed` + 锁形徽标（`icon-[lucide--lock]`）+ tooltip `imGatedHint` | 可发现性强（用户知道"加个建群节点即可解锁"）；引导补全 |
| 隐藏 | 直接不渲染 IM 相关端口 | 画布更干净；但用户不知能力存在、无引导 |

**推荐禁用** —— 缺失能力时给出"如何获得"的引导（`需先添加「创建群聊」节点以提供 chat_id`）比静默隐藏更符合"开箱即用"核心价值。

**Palette 收录:** `clarification_card` 节点（Phase 92 fixture 已含、palette 未收录）需在 `NodePalette.vue` 新增收录使其可见可拖（归入"AI"或新"澄清"分组，plan 定），node-sync 红线（palette ⊆ fixture）保持绿。

## 6-Pillar 设计契约

**1. 布局（Layout）**
- 沿用既有三区：左侧 `NodePalette`（`w-64` 玻璃卡）+ 中央 `@vue-flow` 画布 + 右侧配置面板。L→R 横向流（source=Right / target=Left，既有 0.16 bezier）。
- 附着编组在画布坐标系内成组（方案父 + 澄清子 dock 右下），编组容器不破坏既有自动布局（`useAutoLayout` LR 重排须把 parent/child 视为整体，plan 注意）。

**2. 视觉层级（Hierarchy）**
- 层级：编组容器（琥珀虚线外框，最外）> 节点卡（白玻璃 `bg-card/80`）> 端口槽（shape 色方形 / 通用圆形）> 配置 chip（最内）。
- 磁吸高亮 > 默认 handle：拖拽时兼容槽放大 + 光环把视觉焦点引到"可落点"。
- 能力 shape 色相与品牌 teal、语义绿/红/琥珀分层不抢焦。

**3. 交互状态（States）**
- Handle：idle / compatible-highlight / snap-locked / forbidden（见 SLOT-03 态机）。
- 节点：默认 / hover（`hover:shadow-md` 既有）/ selected（`ring-2 ring-primary` 既有）/ dirty（琥珀点 既有）/ disabled-IM（`opacity-0.4` + 锁徽标）。
- 连接：拖拽连接线（`CustomConnectionLine`）/ 吸附脉冲 / 禁止 `not-allowed`。
- 编组：附着态（虚线框 + 徽标）/ 解除确认（AlertDialog）。

**4. 可达性（Accessibility）**
- 禁止态不可仅靠颜色：禁止用 `cursor: not-allowed` + 形状（不兼容 handle 降透明）+ Toast 文字三重传达；IM 门控用锁图标 + tooltip 文字。
- 兼容/不兼容除绿/红外，附形状语言（方形=契约槽）与文案，满足色盲可达（WCAG 1.4.1 不仅靠颜色）。
- tooltip/徽标提供文本说明（`attachedHint`/`imGatedHint`）；Toast 经既有 `useToast`（aria-live）。
- `prefers-reduced-motion`：磁吸脉冲/光环动画在既有 `@media (prefers-reduced-motion: reduce)` 下降级为静态（main.css 已全局兜底 animation）。
- Handle 命中区 ≥ 既有 10–16px；吸附半径 28px 降低精确点击负担。

**5. 响应（Responsiveness）**
- 画布工具，桌面优先（既有定位）；缩放经 `min-zoom=0.2 / max-zoom=1.5`（不改）。吸附阈值按 `viewport.zoom` 换算保证不同缩放下手感一致。
- 编组容器随缩放整体缩放；徽标/标签用相对节点字号（`text-[10px]`）不随缩放反向放大。

**6. 品牌一致（Brand）**
- 全程复用 Sub2API Teal 主题令牌 + glassmorphism（`bg-card/80 backdrop-blur-sm border-border/50 rounded-2xl`）。
- teal 严守 accent 清单；能力 shape 色板为功能性区分色（amber/cyan/indigo/violet），与既有语义色体系协调不冲突。
- 新增组件（编组容器、shape 方形 handle、IM 锁徽标）沿用既有圆角（`rounded-2xl`/`rounded-lg`）+ 阴影（`shadow-lg`）语言。
