<objective>
实现对账/清理前端（EXCL-06）：在仓库详情页（`pages/repositories/[id]/index.vue`）的 Phase 22 排除规则面板旁挂 `ReconcilePanel.vue`，展示"当前排除规则 vs 已索引内容"差异（命中文件数 + 列表），提供"一键清理（普通）"与显式"敏感清理"两入口（§9.2 不混一个按钮），敏感清理需更强确认（措辞如实：不可逆 + 不承诺 git/备份物理消失），清理派发后刷新对账使差异归零。

对账 `degraded`（匹配器构造失败）时**显式警示"对账不可信"**，不渲染空态/已一致（W3）。清理后台异步执行，故派发后前端调状态端点拉取 `CleanupRun`，**如实回显运行时结果**——尤其敏感清理"哪些操作记录面已清 / 未清(unscrubbed) + caveat"来自后端真实结果而非静态文案（W1/W2）。对齐 23-02 后端契约（`GET /reconcile/` → `ReconcileReport{indexed_count, excluded_paths, match_count, suggested_mode, degraded, error}`；`POST /reconcile/` → 202 + `{mode, match_count, dispatched, run_id}`；`GET /reconcile/status/` → 最近 `CleanupRun{status, mode, match_count, failures, sensitive{...unscrubbed, caveat}, started_at, completed_at, error}`）。复用既有 `web/src/api/` 类型化 client + TanStack Query + reka-ui + `useConfirmDialog` + vue-i18n（默认中文）。

Purpose: 让用户能自助发现"已索引但现命中排除"的残留并安全清理，并对"对账失败"与"清理后未清面"获得诚实可见的反馈——EXCL-06 的可见闭环，没有它对账/清理能力对用户不可达、且无法得知后台清理的真实结果。
Output: `reconcile.ts` API client（含状态查询）、`ReconcilePanel.vue`（含 degraded 警示 + 清理结果回显）、页面挂载、zh-CN 文案、组件守护测试。
</objective>
