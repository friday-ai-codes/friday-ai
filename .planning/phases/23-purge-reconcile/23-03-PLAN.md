<objective>
实现敏感清理（EXCL-05，§9.2/§9.3）的操作记录数据面清理 `services.sensitive_purge.purge_sensitive_planes(repository_id, file_paths)` —— 这是 23-02 `run_cleanup(mode="sensitive")` 在普通清理之后**懒导入并委托**的模块（23-02 已立好该契约：`from services.sensitive_purge import purge_sensitive_planes`）。在普通排除清理（删派生索引面，Wave 1/2）之上，额外清理"可能含正文"的操作记录面。

数据面关联事实（已核实模型）：
- `CodeChangeArchive`（`server/knowledge/models.py` ~356）：`repository` FK + `files` JSON（每项含 `path`）+ `diff_compressed`（zlib）。可 file 级 scrub。
- `TaskResult`（`server/subagent/models.py` ~253）：`session` → `SubAgentSession.repo_url`（非 FK，URL 关联 `Repository.git_url`）；`modified_files` JSON、`raw_output`/`text_output` 含正文。
- `ActionLog`（`server/subagent/models.py` ~442）：`session` 关联；`payload` JSON 可能含文件正文/路径。
- message parts（`server/chat/models.py` `Message.parts` ~127）、prompt snapshot：无精确 file 关联 → 子串脱敏 + 文档化范围（per D-02 / Claude's Discretion）。

边界（§9.1）：敏感清理承诺"Friday 操作记录中该文件正文不可见（尽力而为）"，**不承诺** git object / 备份物理消失；应用层不强保证的面（备份）只文档化 caveat，绝不假装清除。

Purpose: 命中密钥/敏感信息时仅删索引面不够——操作记录里可能残留正文。EXCL-05 补齐这条泄漏面，并兑现 23-02 留好的 sensitive 委托契约。
Output: `server/services/sensitive_purge.py`（新增）+ 敏感面守护测试 + 范围文档化常量。
</objective>
