  <action>
    新建 `server/services/commit_index.py`，实现 `async def index_commits(repository_id: str, repo_path: str) -> dict`。流程：
    (1) 读取 `Repository.commit_index_boundary_sha`（sync_to_async）作为增量下界 `boundary`。
    (2) 经 `asyncio.create_subprocess_exec` 跑 `git log` 取 commit 列表：增量（boundary 非空且在仓库中存在）用 `git log --no-merges --format=<NUL分隔: %H %an %ae %cI %B> {boundary}..HEAD`；首轮（boundary 空或失效）用同 format 但限定 `--max-count=N`（N 默认 500，模块级常量 `COMMIT_INDEX_FIRST_RUN_CAP`，per D-01 默认增量+上限）。用 `\x00` 字段分隔 + 用 `\x1e`（record separator）分隔 commit，避免 message 多行/含特殊字符破坏解析。boundary 不在仓库（force-push/rebase）→ git log 报错 → 回退首轮 bounded 全量。
    (3) 对每个 commit，经 `git diff-tree --no-commit-id --name-only -r <sha>`（或 `git show --name-only`）取变更文件路径列表；用 `build_matcher_for_repo(repository_id)`（预取一次复用）+ `matcher.is_excluded(normalize_rel_path(p))` 剔除被排除文件路径（fail-closed：判定异常视为排除，绝不进摘要，per D-01/D-04）。
    (4) 构建文档文本 = `message` + author(name/email) + committed_at + 过滤后变更文件路径摘要；变更文件摘要经 `truncate_diff_lines(summary_text, MAX)` 截断（MAX 模块级常量）。**摘要只含路径与 commit 元数据，不含被排除文件路径，亦不内联完整 diff 正文**（避免泄漏被排除文件内容，T-25-08）。
    (5) embedding：`EmbeddingService.generate_embeddings_batch(texts)`；若 collection hybrid（`IndexerService(repository_id)._is_hybrid_enabled()` 或等价判定）则同时 `_generate_sparse_vectors`，构建与 `_build_points` 同形的 hybrid vector，否则 dense-only。
    (6) 构建 points：`id = str(uuid5(commit namespace, repo_id + sha))`（确定性，重索引同 sha 命中同 point 不重复），`payload = {"kind": "commit", "commit_sha", "author_name", "author_email", "committed_at", "message"(截断), "changed_files"(过滤后列表), "file_path": f".friday/commits/{sha}", "chunk_index": 0, "content": <doc text>}`。`file_path` 用合成不可被排除路径，使既有 `search_rag` 去重 key `(repo_id, file_path, chunk_index)` 唯一且不误命中排除规则；`kind=commit` 供检索侧区分/过滤（per D-01）。
    (7) `QdrantService.upsert_vectors(repository_id, points)`（sync_to_async）。
    (8) upsert 成功后把 `commit_index_boundary_sha` 推进到 `HEAD`（sync_to_async aupdate）。失败不推进边界（下次重试，绝不丢 commit）。
    (9) 返回 `{"indexed": n, "head": head_sha, "boundary_from": boundary}`。模块级 logger `commit_index_*`；整体异常不抛出致命（由 25-04 best-effort 包裹，但本服务内部对单 commit 解析失败 log warning 继续）。
    路径归一与排除判定务必复用 `services.exclusion`，不另写过滤。
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git 历史 → commit 文档 | commit diff/变更文件可能含被排除文件（密钥/env），摘要不得泄漏 |
| commit 文档 → Qdrant 主 collection | 与代码 chunk 同面，须 kind 区分且 dedup key 不冲突 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-08 | Information Disclosure | 被排除文件路径/内容进入 commit 变更摘要 | mitigate | build_matcher_for_repo + is_excluded 过滤变更文件路径（fail-closed 异常视为排除）；摘要只含路径不内联 diff 正文；守护测试断言被排除文件不出现 |
| T-25-09 | Tampering | 增量边界错误导致漏索引或重复（force-push/rebase 后 boundary 失效） | mitigate | boundary..HEAD 失败回退首轮 bounded；确定性 uuid5 point id（同 sha 不重复）；upsert 成功才推进边界 |
| T-25-10 | Tampering | commit point 与代码 chunk dedup key 冲突致检索面互相覆盖 | mitigate | 合成 file_path `.friday/commits/{sha}` + chunk_index=0 保证 dedup key 唯一；kind=commit 区分 |
| T-25-11 | Denial of Service | 首轮全量索引超大仓库 commit 历史 | mitigate | 首轮 --max-count=COMMIT_INDEX_FIRST_RUN_CAP 上限；--no-merges 减量 |
| T-25-SC | Tampering | npm/pip 安装 | accept | 本 plan 不新增第三方依赖（git 子进程 + 既有 Embedding/Qdrant 服务），无 package install |
</threat_model>
