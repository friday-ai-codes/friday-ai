    权限收口：`allowed = await resolve_allowed_project_ids(request.user)`（返回可见 Space id）；`if not allowed:` 直接返回空结构 `_EMPTY = {"total": 0, "projects": [], "truncated": False}`（fail-closed，零 DB 越权），并记 `artifact_tree_completed`（project_count=0）。

    聚合（sync 函数 `_build_tree(allowed_space_ids)`，经 `sync_to_async` 调用）：`Artifact.objects.filter(project__space_id__in=allowed_space_ids).select_related("type", "project").order_by("project__name", "type__name", "-updated_at")`，用全局硬顶切片 `[:_GLOBAL_FETCH_CAP]`（防病态规模，取 5000）。在 Python 单遍分组为嵌套 `项目 → 类型 → 工件` 有序结构（用 dict 保序 + list 输出）：
    - 顶层项目节点：`{"project_id": str(a.project_id), "project_name": a.project.name, "count": <该项目可见工件真实计数>, "types": [...]}`。
    - 类型节点：`{"type_key": a.type.key, "type_name": a.type.name, "carrier": a.type.carrier, "ragable": a.type.ragable, "count": <该类型工件真实计数>, "artifacts": [...]}`。
    - 叶子：`{"artifact_id": str(a.id), "title": a.title, "carrier": a.carrier, "url": a.url, "updated_at": a.updated_at.isoformat() if a.updated_at else None}`（叶子**不含** project_id —— 前端渲染时 project_id 在外层作用域，避免冗余）。
    - `count` 字段记**桶内真实计数**（随遍历累加），`artifacts`/`types`/`projects` 列表按三级 clamp 截断：`_MAX_PROJECTS=200`、`_MAX_TYPES_PER_PROJECT=50`、`_MAX_ARTIFACTS_PER_TYPE=100`。任一 clamp 触发或命中 `_GLOBAL_FETCH_CAP` 时置 `truncated=True`。
    - `total` = 已纳入项目的工件真实计数之和。

    观测（best-effort，绝不反噬）：入口 `artifact_tree_started`（component="knowledge"、category="caller"）；成功 `artifact_tree_completed`（allowed_space_count/project_count/total/truncated/`duration_ms`）；`_build_tree` 包 `try/except Exception`（`# noqa: BLE001`）→ `artifact_tree_failed` warning + 返回 `dict(_EMPTY)`，绝不 500。用 `structlog.get_logger(__name__)`、`time.perf_counter()`（镜像 overview）。加 `@extend_schema(tags=["knowledge"])`。模块 docstring 说明权限收口与截断口径（中文正文，代码标识保留英文，per doc-writing-zh）。

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → knowledge tree API | 未信任的已认证用户请求跨项目聚合数据，可能试图越权读取他项目/他 Space 的工件 |
| DB 聚合规模 | 跨 Space 聚合工件，规模不受控可能拖垮请求 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-97-01 | Information Disclosure | ArtifactTreeView 跨项目聚合 | mitigate | 强制 `resolve_allowed_project_ids(request.user)` → `project__space_id__in=allowed` 过滤（复用 Phase 96 已核实口径）；空 allowed 直接返回空结构、零 DB 查询（fail-closed），越权 Space 工件不可见 |
| T-97-02 | Denial of Service | 嵌套树聚合查询 | mitigate | 三级 clamp（项目/类型/工件）+ 全局硬顶 `_GLOBAL_FETCH_CAP=5000` 切片 + `select_related` 避免 N+1；超限 `truncated=true` 提示前端缩小范围 |
| T-97-03 | Denial of Service | 聚合/序列化异常 | mitigate | `_build_tree` 包 try/except best-effort，异常回退空结构 + `artifact_tree_failed` warning，绝不 500 反噬主流程 |
| T-97-SC | Tampering | npm/pip/cargo installs | mitigate | 本 plan 不安装任何包（纯仓内新增视图 + 路由 + 测试，无供应链面） |
