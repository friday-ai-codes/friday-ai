    过滤（纯客户端 computed `filteredProjects`，不发请求）：`q = searchQuery.value.trim().toLowerCase()`；q 为空 → 返回全部 projects（原树）。q 非空 → 对每个 project 的每个 type 的 artifacts 按 `title.toLowerCase().includes(q)` 过滤；仅保留有命中叶子的 type，仅保留有命中 type 的 project（空分组不渲染）。命中态下**自动展开命中路径祖先**：搜索非空时渲染用「有效展开」判定——`isProjectOpen(pid)` / `isTypeOpen(pid,tkey)` 返回 `searchQuery 非空 ? true : expandedSet.has(key)`（搜索时全展开命中路径，清空搜索恢复用户手动展开态）。

    命中高亮：叶子标题渲染用高亮 helper——将 `title` 按 q（大小写不敏感）切片，命中子串包 `<mark class="bg-amber-500/20 text-foreground rounded px-0.5">`。用 computed 生成 `{ text, hit }[]` 片段数组渲染（勿用 `v-html` 拼接，避免 XSS——用 `<template v-for>` + `<mark v-if="seg.hit">` 分段渲染纯文本）。

    无匹配空态：`searchQuery` 非空且 `filteredProjects.length === 0` → 展示「无匹配」空态（复用 `CompactEmptyState`，icon `icon-[lucide--search-x]`（若未 safelist 则改用已 safelist 的 `icon-[lucide--file-x]`），title/body 用 i18n）。整树本就为空（total===0）时仍走 97-02 的引导空态（区分「无数据」与「搜过滤无命中」两种空态文案）。

    `zh-CN.json`：在 97-02 建的 `knowledge.tree.docs` 子树下追加 `searchPlaceholder`（如「在交付文档树中搜索工件标题…」）、`noMatch`（`{ title, body }`，如 title「没有匹配的交付文档」/ body「换个关键词，或清空搜索查看全部」）。
