# Plan 05-01 — 入口迁移与向后兼容

## Goal
让容器/集群入口默认不再自动建管理员（改由首启向导承担），保留 `init_superuser` /
`reset_superuser_password` 作运维兜底，同步脚本与文档避免升级回退；向后兼容由 Phase 1 门禁
（`SetupStatusView.is_initialized = exists(is_superuser=True)`）天然保证，本 plan 不新增门禁逻辑。

## Tasks

1. **`server/entrypoint.sh`（COMPAT-01）**
   - 删除 `echo "初始化管理员..."` 与 `python manage.py init_superuser` 两行。
   - 原位置补中文注释块，说明：(a) 不再自动建号——首次部署改由 Web 首启向导创建管理员；
     (b) 运维兜底——如需命令行建号执行 `python manage.py init_superuser`（可配 `FRIDAY_ADMIN_USERNAME`/`FRIDAY_ADMIN_PASSWORD`），重置用 `reset_superuser_password`。
   - 保持 `set -e`、迁移 / `bootstrap_system_settings` / `collectstatic` / `gunicorn` 步骤顺序不变。

2. **`deploy/helm/friday/templates/migration-job.yaml`（COMPAT-01 k8s 等价）**
   - 删除 `echo "初始化管理员..."` 与 `python manage.py init_superuser` 行，保留 `migrate --noinput` 与"迁移完成"。
   - 补中文注释说明同 entrypoint（建号交由向导 / 运维 `kubectl exec ... init_superuser` 兜底）。
   - 删除该 Job 上已失效的 `FRIDAY_ADMIN_USERNAME` / `FRIDAY_ADMIN_PASSWORD` env（命令已移除）。
   - 不动 `configmap.yaml` / `secret.yaml`（server 运行时仍带 `FRIDAY_ADMIN_*`，支撑运维兜底）。

3. **`scripts/verify-runner-e2e.sh`（防断链 + 演示兜底命令）**
   - 在"Server 健康检查通过"之后、"创建 Registration Token"之前，插入步骤：
     `docker exec friday-server python manage.py init_superuser`（env 已传 `FRIDAY_ADMIN_USERNAME=admin`/`FRIDAY_ADMIN_PASSWORD=admin123`），
     带 `log_step`/`log_pass`/`log_fail` 风格日志；失败则 `exit 1`。
   - 保证后续 `User.objects.first()` 能取到管理员（去 entrypoint 自动建号后不再隐式存在）。

4. **`scripts/setup.sh`（提示语同步）**
   - 第 230 行提示"管理员密码（留空则首次启动自动生成）"改为反映新流程，例如：
     "管理员密码（留空则启动后由首启向导设置，或用命令行兜底）"。
   - `# 管理员配置` 注释块补一行说明：这些 env 供 `init_superuser` 命令兜底使用（首启默认走向导）。
   - 仍照常 `write_env FRIDAY_ADMIN_USERNAME/PASSWORD`（保留兜底能力，不破坏既有 .env 结构）。

5. **`.env.example`（注释同步）**
   - 第 101-103 行 `FRIDAY_ADMIN_*` 注释更新：说明首启默认走 Web 向导建号；这些变量仅在手动执行
     `python manage.py init_superuser` 时作为用户名/密码来源（运维兜底），不再触发启动期自动建号。

6. **`docs/guide/quick-start.md`（文档同步）**
   - 第 78 行"配置 FRIDAY_ADMIN_* 则首次启动自动创建管理员，否则 createsuperuser"改为：
     首次启动后访问 Web 进入首启向导自行创建管理员；如需命令行兜底执行
     `docker exec friday-server python manage.py init_superuser`（可配 `FRIDAY_ADMIN_*`）。

7. **`docs/guide/admin.md`（文档同步）**
   - 第 194-195 行 env 表中 `FRIDAY_ADMIN_USERNAME`/`FRIDAY_ADMIN_PASSWORD` 的"首次启动时自动创建"描述
     更新为"由 `init_superuser` 命令读取（运维兜底）；首启默认走 Web 向导，不再自动建号"。

> 命令文件 `init_superuser.py` / `reset_superuser_password.py` **不改动**（COMPAT-02 保留）。
> `docker-compose.yaml` 的 `FRIDAY_ADMIN_*` env **保留**（启动期 inert，支撑 `docker exec` 兜底）。

## Verification
- `grep -n "init_superuser" server/entrypoint.sh` → 仅注释中作说明，无可执行调用行（`^python manage.py init_superuser` 无匹配）。
- `grep -n "init_superuser" deploy/helm/friday/templates/migration-job.yaml` → 同上（无可执行调用）。
- `ls server/accounts/management/commands/init_superuser.py server/accounts/management/commands/reset_superuser_password.py` → 均存在。
- `cd server && uv run python manage.py help 2>&1 | grep -E "init_superuser|reset_superuser_password"` → 两命令均列出。
- `cd server && uv run pytest tests/test_setup_gate.py -q` → 全绿（Phase 1 门禁未回退；已有 superuser → is_initialized=true）。
- `bash -n server/entrypoint.sh` → 语法 OK。
- `grep -rn "自动创建" docs/guide/quick-start.md docs/guide/admin.md` → 无遗留误导文案。

## Risks
- e2e 断链（已在 Task 3 处置）：忘记加 `init_superuser` 会导致 `User.objects.first()` 为 None。
- 误删 `bootstrap_system_settings` 或 migrate：仅删建号两行，逐行确认。
- helm `sh -c` heredoc 缩进：保持原 `|` 块缩进，删除整行而非破坏 YAML 结构。
