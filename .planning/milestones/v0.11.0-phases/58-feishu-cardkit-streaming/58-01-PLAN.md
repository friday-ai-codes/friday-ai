<objective>
建立 Phase 58 的 **CardKit 封装层（Wave 1）**：在 `FeishuIMClient` / `FeishuIMService` 手写 httpx 新增 4 个 CardKit v1 原生流式方法（`create_card_entity` 建实体 → `send_card_entity` interactive 下发 → `stream_card_content` 全量文本 + sequence 增量 → `settle_card_stream` streaming_mode=false 收尾），并在 `bot_cards.py` 新增 schema 2.0 流式卡构造器 `build_streaming_card_v2` 与终态 markdown 拼装 helper `build_answer_markdown`。复用既有 `get_tenant_access_token` + httpx + structlog 基建（D-1），**绝不改** `send_card`/`update_card`/`send_message` 与既有卡片 builder。

Purpose: 兑现 CARD-01 的协议地基——CardKit 4 端点（F-2）形状 100% 正确（端点 URL / payload / sequence 严格递增 / uuid 幂等 / `code!=0` → `FeishuIMError` 降级判定基础），供 Wave 2 的 bot 流式段接线消费。本 plan **不改 bot/service.py**（不接 TEXT_DELTA），纯封装 + 纯形状单测。
Output: `feishu_im.py` 增 4 个 client 方法 + 4 个 service 委托；`bot_cards.py` 增 `build_streaming_card_v2` + `build_answer_markdown`；新建 `test_feishu_cardkit.py`（httpx 形状单测）；扩展 `test_feishu_bot_cards.py`（新 builder 单测）。

> **关键约束**：sequence 计数器（P-2）属 bot 单卡片状态，**留 Wave 2**——本 plan 方法签名只接收 `sequence: int` 透传，单测断言「同一卡多次推送 sequence 必须由调用方严格递增」的形状契约（mock 传 1,2,3 验证 body 透传），不在方法内自增。
</objective>
