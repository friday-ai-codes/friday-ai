<objective>
兑现 TRACE-01 的**用户可见效果**：让流式 `/v1/chat/completions` 在命中 RAG 时，于正文之前可见"正在检索 RAG…"与"检索完成，命中 N 处"两条 `delta.reasoning_content` progress。采用 56-RESEARCH §3 D-1 的 **Option B（b2 元数据驱动）**：检索仍在 `prepare_messages` 完成，但把**非敏感计数元数据**传出，view 据此在首个正文 chunk 前经 `translate_stream` 的 `prelude_texts` 合成 progress chunk（计数来自 F-6 的 `RagSearchResult/HybridSearchResult` 非敏感字段，绝不含 `final_context`/query 原文）。

Purpose: Plan 01 已就位机制（reasoning_content 透出 + helper），但 compat 链路无 tools → 0 progress；本 Plan 接通真实 RAG 检索 → 真正交付 TRACE-01 可见验收（"看得到正在检索 RAG"），同时严守 INV-5（只透出计数语义）与零回归（无命中逐字等价、非流式 content 不变）。
Output: `progress.py` 增 `retrieval_to_progress`；`request_handler.py` 拆 `_prepare` + 加 `prepare_messages_with_meta`（旧 `prepare_messages` 委托保留）；`adapter.py translate_stream` 加 `prelude_texts`；`views.py` 流式分支接线；扩充 `test_progress.py` / `test_adapter.py`。

> **DEVIATION（承接 Plan 01 / 56-RESEARCH D-1）**：CONTEXT 默认假设检索经 TOOL_USE_* 事件流入 adapter。实证：检索是 `prepare_messages` 中 stream 前的同步函数调用、不发任何事件（F-2）。故按研究 Option B(b2) 用元数据驱动 view 层合成 progress，而非事件映射。检索 progress 仅在**命中时**合成（honors 零回归：无命中逐字等价）。
</objective>
