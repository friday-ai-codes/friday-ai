- `bump_revision_round`（**纯函数**）：`deepcopy` → `meta = content.setdefault("meta", {})`（容忍缺段/非 dict）→ 旧值非 int 或 < 0 时按 0 起算 → `meta["revision_round"] = old + 1` → 返回 `(new_content, new_round)`。恒不抛。
- `aapprove_blueprint`：恒定返回键 `{"status": "confirmed"|"blocked"|"conflict"|"invalid", "detail": str, "blueprint_status": str}`。实现：`try: await lifecycle.transition(artifact, BlueprintStatus.CONFIRMED, initiated_by_user_id=..., acting_user=user, session=session)` → `status="confirmed"`；`except ValueError as exc:` → `status="blocked"`，`detail` 取异常文本（**经 `redact_secrets_in_text`**；文案对齐 114-01-SUMMARY 登记的守卫报错）；`except ConcurrentBlueprintTransitionError:` → `status="conflict"`。成功后 `add_reviewer(artifact, user, "review_approve")`（`user` 为 None 时跳过；`transition` 的 `acting_user` 已做 upsert 时此调用幂等无副作用）+ `caller` 日志（`blueprint_review_approved`，含 `artifact_id` / `initiated_by_user_id` / `duration_ms`）。**全程零二次查询**。
- `areject_blueprint`：恒定返回键 `{"status": "rejected"|"unchanged"|"invalid"|"conflict", "version_id": str, "version_no": int, "revision_round": int, "thread_id": str, "detail": str}`。五步：
  1. **重读**最新版本作基线（`ArtifactVersion.objects.filter(artifact_id=...).order_by("-version_no").afirst()`；⚠️ 每次调用都重读，**不接受调用方传入的 content**）；无版本 → `invalid`；
  2. `new_content, new_round = bump_revision_round(base.content)`；
  3. `add_version(artifact, new_content, produced_by_session_id=..., produced_by_ref=f"blueprint_review_reject:{user_id}")`，`try/except ArtifactContentInvalid` → warning（脱敏）+ `invalid`（**不落半合法版本**）；
  4. `transition(artifact, BlueprintStatus.DRAFTING, initiated_by_user_id=..., acting_user=user, session=session)`，`ValueError` → `invalid` / `ConcurrentBlueprintTransitionError` → `conflict`（此时版本已落 —— 在返回体里如实带上 `version_no`，让端点能把「版本已落但状态未转」这一半成功状态告诉用户，绝不静默）；
  5. `comment` 非空 → `open_thread(artifact, kind=ThreadKind.HUMAN_COMMENT, blocking=False, severity="", question=comment, anchor=anchor, created_on_version=new_version, initiated_by_user_id=..., return_stage="drafting")`（划线评论；`severity` 传空 ⇒ 不受 114-01 的 finding 不变式约束）→ `add_reviewer(artifact, user, "review_reject")` → `caller` 日志（`blueprint_review_rejected`，含 `revision_round` / `version_no`；**评论正文绝不进日志**）。
- ⭐ **`aresolve_finding` / `adismiss_finding`（B2）**：恒定返回键 `{"status": "resolved"|"dismissed"|"invalid"|"noop", "thread_id": str, "detail": str}`。
  - `reason` 为**必填 keyword**：`str(reason or "").strip()` 为空 → `{"status": "invalid", "detail": "处置理由不可为空"}`（**不落库**）。理由：处置一条 BLOCKER finding 等于「人工判定 AI 的审查结论不成立或已修复」，无理由的处置在审计上等于凭空放行。
  - 线程 `kind != ThreadKind.AI_REVIEW_FINDING` → `invalid`（本通道只处置审查发现；澄清线程走 answer 端点）。线程已是终态（`resolved` / `dismissed`）→ `noop`（幂等，**不覆盖首次结论**，`resolve_thread` 自身也幂等）。
  - 处置：`await lifecycle.resolve_thread(thread, resolution=f"[{'已修复' if resolve else '误报忽略'}] {reason}（处置人：{user_id}）", initiated_by_user_id=..., dismissed=<False|True>)`。**处置人与理由都进结论文本**（`BlueprintThreadMessage` 无结构化「处置人」字段，结论文本是唯一留痕位）。
  - 成功后 `add_reviewer(artifact, user, "finding_resolve" | "finding_dismiss")`（`user` 为 None 时跳过）+ `caller` 日志（`blueprint_finding_resolved` / `blueprint_finding_dismissed`，含 `thread_id` / `severity` / `initiated_by_user_id` / `duration_ms`；⚠️ **`reason` 正文不进日志**，只记 `reason_len`）。
  - docstring 写明死锁机理（见第五段）+「处置后 `_has_confirm_blockers_sync` 的两条判据对该线程都不再命中 ⇒ approve 可放行；这是超界出口**唯一**的正向解法，另一条只能是驳回重跑」。
- ⭐ **`aremind_clarification_threads`（B4 的提醒执行体，被周期任务调用）**：恒定返回键 `{"scanned": int, "due": int, "reminded": int, "skipped": int}`。
