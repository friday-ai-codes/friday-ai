  <behavior>
    - SDD 仓回填：按 (plan_version_id, repository_id) 命中 SddSpec → 追加 {pr_url, repository_id, linked_at} 到 implementation_prs
    - 转 implemented：命中 spec 当前 status=approved → 经 mark_implemented 语义流转 approved→implemented（单一事务内）
    - 非 SDD no-op：(plan_version_id, repository_id) 无 SddSpec → 直接返回（无写入、无异常、零回归）
    - 去重幂等：同一 pr_url 重复调用不重复追加（按 pr_url 判重），且不重复触发状态流转
    - 非 approved 宽容：spec 当前为 draft/in_review/implemented/archived → 仅记 PR ref，不强转状态，记 warning（如 sdd_spec_pr_link_non_approved），不抛异常
    - 单一事务 + INV-6：append + 状态流转在同一 transaction.atomic；SddSpec 写入只经本 service
  </behavior>
  <action>
    新增 `async def link_implementation_pr(self, *, plan_version_id, repository_id, pr_url) -> None`
    + 配套 `@sync_to_async` 同步核心（镜像本文件既有 _simple_transition / _review_transition
    范式）。同步核心在单一 `transaction.atomic` 内：用 `SddSpec.objects.select_for_update()
    .filter(plan_version_id=plan_version_id, repository_id=repository_id).first()` 取锁定行
    （async 安全：标量 *_id 过滤，不裸访问 lazy-FK）；None → no-op return（非 SDD 仓零回归，
    D-52-5）。命中后读 `spec.implementation_prs or []`，若已含相同 pr_url → 不追加（幂等）；
    否则 append `{"pr_url": pr_url, "repository_id": str(repository_id), "linked_at":
    timezone.now().isoformat()}` 并 `spec.save(update_fields=["implementation_prs",
    "updated_at"])`。状态流转：spec.status == approved → 在同事务内执行 approved→implemented
    条件更新（复用既有 `_LEGAL_TRANSITIONS["mark_implemented"]` 源/目标常量作单一真相，
    避免重复硬编码状态表，对齐 D-52-2「经既有 mark_implemented」）；非 approved → 不流转，
    记 warning 并保留 PR ref（宽容，D-52-2）。日志只记 plan_version_id/repository_id/pr_url/
    spec_id，绝不入 token/凭证。__all__ 与 docstring 同步说明本方法为 spec→PR 唯一写入入口。
    在 test_sdd_spec_pr_link.py 覆盖 behavior 全部 6 类用例（pytest.mark.django_db +
    pytest.mark.asyncio，复用既有 test_sdd_spec_service.py 的 fixture/建模范式：建
    Repository/PlanVersion/WorkItem/SddSpec）。
