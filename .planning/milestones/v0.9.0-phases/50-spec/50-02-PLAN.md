  <behavior>
    - 合法流转表（per D-50-1）：submit_for_review: draft→in_review；approve: in_review→approved；reject: in_review→draft；mark_implemented: approved→implemented；archive: 任意非 archived→archived。
    - 非法流转（当前状态非该 action 合法源）→ 抛 SddSpecTransitionError（消息含 action + 当前状态）。
    - 幂等/防双推进：经条件 `.filter(id=spec_id, status=<from>).update(status=<to>)`，影响行数==0 → 抛 SddSpecTransitionError（并发/已推进 fail-loud，复用 RepoCodingTaskService 条件更新范式）。
    - approve(spec_id, reviewer, comment="")：单一 transaction.atomic 内先 `SddSpecReview.objects.create(spec, reviewer, decision=approve, comment)` 再条件更新 in_review→approved；若更新 0 行则 raise（事务回滚，不留孤儿评审）。
    - reject(spec_id, reviewer, comment)：同 approve，decision=reject，in_review→draft。
    - submit_for_review/mark_implemented/archive：不建评审记录，仅条件更新状态。
    - archive 合法源为「任意非 archived」：实现为 `.filter(id=spec_id).exclude(status=archived).update(status=archived)`，0 行（已 archived 或不存在）→ raise。
    - 所有方法 async，ORM 写经 sync_to_async 桥接（对齐既有 service async 约定）。
  </behavior>
  <action>在 `sdd_spec_service.py` 顶部定义 `class SddSpecTransitionError(Exception)`（模块级，导出到 `__all__`）。在 `SddSpecService` 加 behavior 所述 5 个 async 方法 + 一个内部合法流转表常量（如 `_LEGAL_TRANSITIONS: dict[str, tuple[from_status, to_status]]`，archive 特殊处理）。条件更新与原子评审写法镜像 `RepoCodingTaskService` 的 `.filter(...).update(...)` + 影响行数判定 + `transaction.atomic()` 范式；评审创建用 `SddSpecReview.objects.create(...)`（本 service 是 SddSpecReview 唯一写入点，INV-6）。reviewer 以实例传入（不裸访问 lazy-FK，sync 块内用）。新建 `test_sdd_spec_transitions.py`（`@pytest.mark.django_db(transaction=True)`，async 用例用 `pytest.mark.asyncio`）覆盖：每条合法流转逐一通过、代表性非法流转 raise、重复 approve/已推进 raise（幂等 fail-loud）、approve/reject 原子建评审并驱动状态、reject 后状态回 draft 且评审 decision=reject、模拟更新 0 行时评审被回滚（无孤儿评审）。不得在模型层加写方法；不得绕过条件更新直接 save 状态。`<action>` 内不写实现代码，仅指明契约。</action>
