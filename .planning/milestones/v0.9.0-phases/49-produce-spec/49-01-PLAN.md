在 `DocumentService` 新增 async `create_internal_spec`（守 INV-6：写仍在本文件这个唯一允许 writer 内，test_document_inv6_guard 守护不变）：

签名（对齐 D-49-2，扩一个可选 `document` 形参以支撑 Plan 02 的幂等/版本复用，不改既有 `upsert_from_feishu`）：
`async def create_internal_spec(self, *, work_item: WorkItem | None, repository_label: str, content: str, title: str = "", document: Document | None = None) -> Document`

- 复用既有 `_content_hash`（同算法，单一来源）。
- 新增 `@sync_to_async` 私有 `_create_internal_spec_locked(...)`，`transaction.atomic` 内：
  - `document is None`：`Document.objects.create(document_type=DocumentType.SDD_SPEC, source_kind=DocumentSourceKind.INTERNAL_GENERATED, content_storage=ContentStorage.SNAPSHOT, external_ref="", feishu_tenant="", work_item=work_item)`（internal 文档不派生 feishu_tenant，external_ref="" 豁免飞书唯一约束）。
  - `document` 给定：`Document.objects.select_for_update().get(id=document.id)` 取锁；若 work_item 先前 None 现非空则补连。
  - 版本范式与 `_upsert_locked` 一致：`cur = document.current_version`；`cur.content_hash == new_hash` → 不翻版本（仅 save 必要 mirror 字段）；否则 `DocumentVersion.objects.create(version=cur.version+1 or 1, supersedes=cur, content, content_hash)` + 推进 current_version。
  - `repository_label` 仅用于（可选）落入 Document 标识性字段/日志上下文——内部 spec 无 external_ref，可将 `repository_label` 记入 structlog 日志或忽略入库（不强制持久化，Claude 自行决定是否落 canonical_url 占位；不得用它伪造 external_ref 破坏豁免语义）。
- internal 文档不记 WorkItemSyncState facet（facet 仅 prd/tech_plan）。
- 加中文 docstring：说明这是「内部生成文档（spec 正文）的单一写入入口」，与 `upsert_from_feishu`（external）并列，二者都收口于 DocumentService（INV-6）。
