    - `parse_mr_url(url: str) -> MRRef | None`：识别 GitLab `.../{namespace}/{project}/-/merge_requests/{iid}` 与 GitHub `.../{owner}/{repo}/pull/{iid}`；取 host、project_path（namespace/project 或 owner/repo）、mr_iid（数字串）。不匹配 → None。

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → 一键摄取入口 | 用户提交的 board_url / mr_url 为不可信输入，跨此边界进入解析与（32-02）编排 |
| 解析层 → 既有凭证化 client | 解析只产出**标识符**，绝不把原始用户 URL 当抓取目标 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-01 | Tampering / SSRF | `parse_board_url` / `aresolve_repo_and_mr` | mitigate | 解析仅抽取 (project_key,type,id) 与 (host,path,iid)，并强制把 MR 解析结果**匹配到已落库 Repository** 才放行；不存在 fetch 任意用户 URL 的路径——飞书走 32-02 项目加密凭证 client，MR diff 走匹配 Repository 的 git platform client |
| T-32-02 | Information Disclosure | `IngestRun.error` / `steps[*].error` | mitigate | 步级/编排级错误落库前在 32-02 经脱敏（复用 WorkItemService `_redact_secrets` 范式）；本 plan 模型层字段为纯文本载体，docstring 标注「写入侧负责脱敏」 |
| T-32-03 | Spoofing / Elevation | 一键摄取 REST（32-02 实装） | mitigate | 端点 `IsAuthenticated`（在 32-02 落地，本 plan 不暴露端点） |

无新增 npm/pip/cargo 依赖 → 供应链门（T-32-SC）不适用。
</threat_model>
