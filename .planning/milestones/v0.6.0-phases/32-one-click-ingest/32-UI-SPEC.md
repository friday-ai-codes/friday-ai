# Phase 32 — UI Design Contract（一键摄取编排）

> Visual and interaction contract for the minimal one-click ingest panel.
> Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
> 该 UI 是**编排既有能力**的运维/管理型工具面板，非营销页：优先清晰、状态完整、复用既有组件与令牌。

---

## Scope

输入两个 URL（看板/工作项 URL + MR URL）→ 提交触发后台编排 `ingest_from_urls` → 经 TanStack Query 轮询 run 状态 → 展示三步结果（工作项 / 文档 / MR diff，各自 ok/failed/skipped + 标识/链接 + error）。

沿用既有「派发 → 轮询」范式（参照 `ReconcilePanel.vue` + `web/src/api/reconcile.ts`）。best-effort 降级：任一步失败/跳过不阻断整体展示（部分摄取）。

非目标：容器型工作项 URL（out of scope）、批量摄取、人工凭证端到端 UAT、检索结果页（复用既有 `/knowledge` 搜索）。

## Color

60 / 30 / 10 拆分，全部取自 `main.css` `@theme`。

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-background` slate-50 `hsl(210 40% 98%)` | 页面背景（`PageContainer` 内）|
| Secondary (30%) | `--color-card` white `hsl(0 0% 100%)` | 表单卡片、结果卡片（`.card`）|
| Accent (10%) | `--color-primary` teal-500 `hsl(168 76% 42%)` | 见下方 reserved-for |
| Destructive | `--color-destructive` `hsl(0 72% 51%)` | 失败步骤 / 字段校验错误 / 派发失败 |

**Accent (teal-500) reserved for（仅限以下元素，禁止泛用）：**
- 主 CTA「开始摄取」按钮（`Button` 默认 primary 变体）
- 卡片标题前的引导图标（`icon-[lucide--download] text-primary`）
- 进行中步骤的 loading spinner（`icon-[lucide--loader-circle] animate-spin text-primary`）

**状态语义色（与 `ReconcilePanel` 一致，非品牌强调色，按状态严格映射）：**
- `ok` → emerald：`text-emerald-600 dark:text-emerald-400` + `icon-[lucide--check-circle-2]`
- `failed` → destructive：`text-destructive` + `icon-[lucide--alert-circle]`
- `skipped` → amber：`text-amber-700 dark:text-amber-400` + `icon-[lucide--minus-circle]`
- `pending/running` → muted/primary：`text-muted-foreground` / spinner

## API Contract (frontend ↔ backend)

> 端点形状属 CONTEXT「Claude's Discretion」；以下为前端契约，后端须对齐字段名/状态枚举。

```ts
// web/src/api/ingest.ts
export type StepStatus = 'ok' | 'failed' | 'skipped' | 'pending'
export type RunStatus = 'running' | 'completed' | 'failed'

export interface IngestStep {
  status: StepStatus
  identifier?: string   // work_item id / document id / archive id
  link?: string         // 可选外链（飞书 / MR / 知识实体详情）
  error?: string        // failed/skipped 时的原因
}

export interface IngestRun {
  run_id: string
  status: RunStatus
  steps: {
    work_item: IngestStep
    document: IngestStep
    mr_diff: IngestStep
  }
  started_at?: string
  completed_at?: string | null
}

export interface IngestDispatch {
  run_id: string
  dispatched: boolean
}

export const ingestApi = {
  // POST /delivery/ingest/ → 202 立即返回 run_id（后台执行）
  dispatch: (boardUrl: string, mrUrl: string) =>
    post<IngestDispatch>('/delivery/ingest/', { board_url: boardUrl, mr_url: mrUrl }),
  // GET /delivery/ingest/{run_id}/ → 拉取真实步骤结果
  getRun: (runId: string) =>
    get<IngestRun>(`/delivery/ingest/${runId}/`),
}
```

轮询：`useQuery` + `refetchInterval: q => q.state.data?.status === 'running' ? 2000 : false`（完成/失败停轮，沿用 reconcile 范式）。

## Component Breakdown

### `pages/knowledge/ingest.vue`（薄壳）
- `<PageContainer>` → `<div class="space-y-4 max-w-3xl">` → `<h1 class="text-xl font-semibold">{{ t('ingest.title') }}</h1>` → `<IngestPanel />`

### `components/knowledge/IngestPanel.vue`（核心）
两块区域，纵向 `space-y-8`：

1. **表单卡片**（`.card` → header + `p-5 space-y-4`）
   - header：`icon-[lucide--download] text-primary` + `text-sm font-semibold` 标题 + `text-xs text-muted-foreground` 副标题
   - 字段 1：`Label`（`for="ingest-board-url"`）+ `Input`（`v-model` boardUrl，`data-testid="ingest-board-url"`）+ 错误 `<p class="text-xs text-destructive">`
   - 字段 2：`Label`（`for="ingest-mr-url"`）+ `Input`（mrUrl，`data-testid="ingest-mr-url"`）+ 错误位
   - CTA：`Button`（默认 primary）`data-testid="ingest-submit"`，`:disabled="isDispatching"`，loading 时前置 spinner + 文案切换
2. **结果卡片 / 空态**
   - `isError`（getRun 失败）→ `text-xs text-destructive` 错误行
   - 无 run（`!runId`）→ `CompactEmptyState`（icon `lucide--inbox`，title/body 见 copy）
   - 有 run → 结果卡片：顶部 run 状态行（running spinner / completed 绿勾 / failed 红 + 部分成功提示）+ `StepRow` ×3

### `StepRow`（行内子结构，可内联实现）
单行：`flex items-start gap-2`
- 状态图标（按状态语义色映射）
- 步骤名 `text-sm font-medium`
- 状态徽标 `text-xs`（ok/failed/skipped/pending 文案 + 对应色）
- 标识 `code text-xs font-mono break-all`（存在时）
- 「查看」外链 `<a target="_blank" rel="noopener">`（`link` 存在时，`icon-[lucide--external-link]`）
- error `text-xs text-destructive`（failed/skipped 且有 error 时）

固定渲染顺序：工作项 → PRD/技术方案文档 → MR diff（始终三行，保证可预期布局，无值步骤显示 pending/skipped）。

## States (6-pillar coverage)

| State | 触发 | 渲染 |
|-------|------|------|
| Idle / Empty | 首次进入，无 run | 表单 + `CompactEmptyState`（尚未发起摄取）|
| Field invalid | 提交时 URL 为空或非 http(s) | 字段下方 `text-destructive` 内联错误，不派发，聚焦首个错误字段 |
| Dispatching | 点击 CTA → POST 进行中 | CTA disabled + spinner + 「摄取派发中…」；成功 toast，失败 toast + 不进入轮询 |
| Running | run.status==='running' | 结果卡片：顶部 running spinner；步骤按后端状态显示（未完成步骤 pending）；2s 轮询 |
| Partial success | completed 但存在 failed/skipped 步骤 | 顶部「部分步骤未完成…」amber 提示；逐步骤显示 ok/failed/skipped + error/链接 |
| Success (all ok) | completed 且三步 ok | 顶部绿色「摄取完成，相关内容已可检索」；三行绿勾 + 标识/链接 |
| Run load error | getRun 轮询失败 | `text-destructive`「加载摄取状态失败…」行（保留已有结果，不清空）|

**Loading：** 派发用按钮 spinner；轮询用步骤行 spinner（不整页 Skeleton，避免抖动）。
**Feedback：** `useToast` 派发成功/失败；`useErrorHandler` 处理派发异常。

## Accessibility

- 每个 `Input` 关联 `<Label :for>`；CTA 为原生可聚焦 `Button`。
- 结果区容器加 `aria-live="polite"`，轮询状态变化对屏幕阅读器可感知。
- 状态图标为装饰性，语义由相邻文本承载（ok/failed/skipped 有文字，不靠颜色单独区分 — WCAG 1.4.1）。
- 外链 `target="_blank"` 必带 `rel="noopener"`。
- 复用全局 focus 环（`--color-ring` teal）；遵守 `prefers-reduced-motion`（spinner 动画全局已降级）。
- 颜色对比：destructive/emerald/amber 文案均在白卡上达标（沿用既有面板配色）。

## Acceptance Criteria

实现完成且满足以下条件视为达标（供 executor / ui-checker / 守护测试使用）：

1. `/knowledge/ingest` 页可访问，侧边栏含「一键摄取」入口。
2. 表单含「看板 URL」「MR URL」两个带 `Label` 的输入框 + 「开始摄取」CTA。
3. 空 / 非 http(s) URL 提交触发内联校验错误，不发起请求。
4. 合法提交调用 `ingestApi.dispatch(boardUrl, mrUrl)`，返回 `run_id` 后开启 2s 轮询，弹出派发成功 toast。
5. 结果区始终渲染三步（工作项 / 文档 / MR diff），各自按 `ok/failed/skipped/pending` 显示对应语义色图标 + 文案；有 `identifier` 显示等宽标识、有 `link` 显示「查看」外链、失败/跳过显示 `error`。
6. `status==='completed'` 且存在非 ok 步骤 → 显示「部分步骤未完成」提示（partial-success 可见）。
7. `status==='completed'` 且三步全 ok → 显示「摄取完成，相关内容已可检索」。
8. `getRun` 失败显示加载错误行且不清空已有结果。
9. 全部可见文案来自 `zh-CN.json` `ingest.*`；守护测试以真实 `zh-CN.json` 断言关键文案（标题 / CTA / 三步骤名 / 三状态）。
10. 仅复用既有 `~/components/ui/*`、`.card`、状态语义色与设计令牌，无新增字体/颜色变量/第三方 registry。
11. 输入有 `<Label :for>` 关联，结果区 `aria-live="polite"`，外链带 `rel="noopener"`，状态不仅靠颜色区分。
