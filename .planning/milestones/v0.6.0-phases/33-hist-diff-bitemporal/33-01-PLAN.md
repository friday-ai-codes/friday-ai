<objective>
落地 HDIFF-01「历史 MR diff 冻结为 commit 锚定快照」：给 git platform client 增加拉取
MR/PR 元数据（`merge_commit_sha` / `target_branch` / `source_branch` / `merged_at`）的能力，
让一键摄取 MR 步用**真实 merge commit** 而非合成 `mr-{iid}` 锚定归档与 `MODIFIES_CHUNK`
边的 `valid_at`（修 Phase 32 遗留 WR-02），并在边 metadata 冻结当年 chunk 版本指纹
（`chunk_content_hash`），为 HDIFF-02 重索引对账提供「已被新版本取代」判定依据。

Purpose: 历史 diff 必须锚定到它真正合入的 commit 与目标分支（DOMAIN §1.5 实测 GitLab MR
`target_branch` 非 master），否则后续对账无法区分历史/当前、旧边永不失效（PF-08 根因）。
Output: `MRMetadataResult` + `get_merge_request_metadata`（双客户端）、`aresolve_mr_commit_anchor`
helper、`resolve_modified_chunks` 的 chunk 指纹戳记、改写后的 `_ingest_mr_diff` 与守护测试。
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| friday → 外部 git 平台（GitLab/GitHub API） | 经已落库 Repository 的加密凭证 client 拉取 MR 元数据；MR 由外部用户创建，元数据（target_branch/source_branch/merge_commit_sha）为不可信字符串 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-01 | Information Disclosure | aresolve_mr_commit_anchor / get_merge_request_metadata | mitigate | token 经 aresolve_git_token 取用，绝不入 structlog 事件/error/payload（复用 archive_code_change 既有纪律）；失败仅记 mr_id/repository_id |
| T-33-02 | Tampering | MR 元数据落 CodeChangeArchive.base_branch / branch_name / edge metadata | mitigate | target_branch/source_branch/merge_commit_sha 仅作字符串存储与 commit 锚定，绝不拼入 shell/作为新的 fetch 目标 URL（SSRF 边界由 Phase 32 aresolve_repo_and_mr 已守住，本 plan 不放行任意 URL） |
| T-33-03 | Spoofing/Integrity | 未合并 MR（merge_commit_sha 缺失）伪装为可归档 | accept→mitigate | anchor 缺 merge_commit_sha → 如实 skipped，不合成 commit 锚定（WR-02），避免伪历史快照污染 |

无新增 npm/pip/cargo 依赖安装（纯既有 SDK：python-gitlab / PyGithub 已在 STACK），故无 T-33-SC 供应链项。
