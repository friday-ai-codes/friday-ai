新建 `server/mcp_tools/learning_case_extraction.py`（中文 docstring：LOOP-03，锚点由 101-03 接线；镜像 memory_distill 范式）。模块常量 `_COMPONENT = "mcp_tools"`。

核心入口：

```
async def aextract_learning_case(
    *,
    session_id: str,                      # 幂等键 = SubAgentSession.session_id
    task_status: str,                     # 上游任务终态（completed/failed/cancelled...）
    requirement_text: str = "",           # 任务需求文本（plan 摘要/需求描述）
    text_output: str = "",                # TaskResult.text_output
    branch_name: str = "",
    pr_url: str = "",
    modified_files: list[str] | None = None,
    repositories: list[str] | None = None,
    work_item_type: str = "",
    work_item_id: int | None = None,
    plan_summary: str = "",
    initiated_by_user_id: str | None = None,
    source: str = "auto_extract",         # 事件与 source_links 标记（auto_extract / pr_review）
    idempotency_suffix: str = "",         # LOOP-05 复用时传 ":pr_review"
) -> "McpLearningCase | None"
```

管线顺序（每步不过即返回 None，全程 fail-soft 绝不上抛——外层再包一个兜底 try/except 记 `learning_case_extraction_failed`）：

1. **kill switch**：`await aget_bool_setting(SettingKeys.LEARNING_CASE_AUTO_EXTRACT, default=True)` 为 False → `logger.info("learning_case_extraction_skipped", reason="disabled", category="sampling", component=_COMPONENT)` → None。
2. **状态门**：`task_status` 不在成功集合（`{"completed"}`，与 `SubAgentSession.Status.COMPLETED` 对齐）→ skipped 事件 reason="status_gate" → None（失败/取消任务不产正向 case）。
3. **幂等**：`key = session_id + idempotency_suffix`；`await McpLearningCase.objects.filter(source_session_id=key).aexists()` → True 时 skipped 事件 reason="duplicate" → None。
4. **LLM 提炼** `_acall_llm(...)`：完整镜像 `memory_distill._acall_llm`（aresolve_or_error 缺凭证→None；`use_call_source(CallSource.LEARNING_CASE_EXTRACTION.value)`；`build_chat_model(resolved, model, max_output_tokens=1024, streaming=False)`；`arecord_llm_usage(call_source=..., source="mcp_tools", ...)` 成功/异常两路都记；`parse_upstream_status` 留痕）。prompt（Claude's Discretion，泛化性引导）：要求输出**一段 JSON**（title/problem/root_cause/solution/outcome 五键，各字段中文），明确指令"提炼可复用的工程经验而非复述任务日志/diff；problem 描述一类问题而非本次任务标题；solution 写做法与原因"；输入料 = requirement_text + plan_summary + text_output（截断至 ~6000 字符）+ branch/pr_url/modified_files 摘要。解析用 `json.loads`（剥 ```json 围栏），解析失败进 REJECT。
5. **质量门（与功能同 PR，P2 锁定）** `_admission_gate(parsed) -> str | None`（返回 reject reason 或 None）：
   - `problem`、`solution` 去空白后长度均 ≥ 30 字符；
   - `problem != solution`；
   - 去模板断言：`solution` 不落在占位废话集合（如以"暂无/无/N-A/TODO"开头、或与 prompt 示例逐字相同）；
   - 不过门 → `logger.warning("learning_case_rejected", reason=<gate reason>, session_id=key, category="caller", component=_COMPONENT, initiated_by_user_id=initiated_by_user_id or "system")` → None（**显式 REJECT 路径 + 事件计数，不入库**）。
6. **脱敏**：title/problem/root_cause/solution 全部过 `redact_secrets_in_text`。
7. **入库**：`await McpLearningCase.objects.acreate(run=None, source_session_id=key, title=..., problem=..., root_cause=..., solution=..., outcome=parsed.get("outcome") or "success", work_item_type=work_item_type, work_item_id=work_item_id, repositories=repositories or [], files=modified_files or [], branches=[branch_name] if branch_name else [], mr_urls=[pr_url] if pr_url else [], source_links={"session_id": session_id, "pr_url": pr_url, "source": source}, embedding_text=<title+problem+solution 拼接>)`。并发兜底：`IntegrityError`（unique 冲突）捕获视为 duplicate skipped → None。
8. **入图**：lazy import `knowledge.ingestion` → `await aschedule_ingestion(IngestionRequest("learning_case", str(case.id), "learning_case_auto_extracted"))`（Phase 100 通路，INV-6）。
9. **收尾事件**：`logger.info("learning_case_extraction_completed", session_id=key, case_id=str(case.id), duration_ms=<全程计时>, category="caller", component=_COMPONENT, initiated_by_user_id=initiated_by_user_id or "system")`；步骤 1–3 的 skipped 事件用 `category="sampling"`（高频跳过不刷 caller）。

新建 `server/tests/mcp_tools/test_learning_case_extraction.py`（django_db + asyncio；LLM 一律 patch `learning_case_extraction._acall_llm`；`aschedule_ingestion` 用 mock 断言投递）覆盖五路：
1. 开关关（aset_setting 或 patch aget_bool_setting=False）→ 返回 None、DB 零行、LLM 未调用。
2. `task_status="failed"` → None、LLM 未调用。
3. 幂等：mock LLM 返回合格 JSON，连续调两次同 session_id → 仅 1 条 McpLearningCase（第二次走 duplicate skip）。
4. REJECT：mock LLM 返回 `solution` 过短的 JSON → None、DB 零行、caplog/structlog 捕获 `learning_case_rejected` 事件。
5. 成功：合格 JSON → case 落库（run is None、source_session_id 正确、字段已脱敏——输入里埋 `token=abc123secret` 断言产物不含明文）+ `aschedule_ingestion` 被以 ("learning_case", case_id) 调用。
