## D1 — Team gate surface (TEAM)

**Choice: A-extended**

- Blueprint route + project repo association (feature list / Project context): `team_core` is a **hard gate**; `out_of_team` must not be primary.
- **MCP / tool routes also have a team gate:** either auto-detect team/Space from context, or **require the caller to select team** before routing proceeds. No silent full-library primary selection when a team gate is expected.
- Adjacent (`team_adjacent`) only with reuse/charter evidence.

## D2 — Phase 132 acceptance bar (INT-02)

**Choice: Accept recommended bar**

- Placement-unit / module-level evaluation (not 43 feature-point top1).
- Four baseline repos must each appear as **primary** of at least one placement unit: `frontend/onion-learning`, `frontend/onion-practice` (alias `onion-practice`), `backend/study-course` (alias `study-course`), `backend/study-user-status`.
- `out_of_team` primary count must be **0**.
- Eval path: Learning-tools Space + funnel (charter/history enabled), not bare `RepoRouterV2`.

## D3 — No-team failure (TEAM-03)

**Choice: A**

- When Project/Space is expected but missing/empty → `clarify` (offer bind Space), not silent full-library fallback.
- Align with D1 for MCP: if MCP call expects team and none provided/detected → `clarify` (ask user to pick team), not silent global primary.

## D4 — Publish gate (GATE-02)

**Choice: A**

- Feature-list funnel defaults to **confirmation gate** before downstream coding.
- `auto_selected` only when role map complete + all units high confidence + dual evidence (charter and/or history as defined in phase plans).

## D5 — Role taxonomy (ROLE)

**Choice: A**

- Fixed small enum (App shell / practice-reuse host / course config / learning state; may add 1–2 if needed).
- Charter domains **map into** the enum; unmappable → `clarify`.
- Consistency gates use the enum (e.g. state-domain writer ≠ arbitrary UI shell primary).

- Profile corpus: module overview/briefs; test cases **out** of main query.
