在 `server/mcp_tools/views.py` 紧邻 `ReverseLookupView` 之后新增两个 View，⛔ 壳内零算法。

① 模块级映射 `_GRAPH_ERROR_STATUS: dict[str, int]`（放在 `_MIRROR_ERROR_STATUS` 旁边，同款形态）：`repository_not_indexed` → 400 / `repository_access_denied` → 403 / `graph_build_timeout` → 504 / `graph_build_failed` → 500 / `graph_unavailable` → 400。配一个 `_graph_error_response(exc)`：调 `graph_error_to_tool_error(exc)` 拿 `(code, message)`，`error_response(code, message, status_code=_GRAPH_ERROR_STATUS.get(code, 400))`。🚨 只出映射表文案，⛔ 不把 `str(exc)` 或 `exc.details` 塞进 `detail`（T-122-错误细节泄漏：`details` 含 `estimated_bytes` / `max_graph_bytes`）。

② `class ImpactAnalysisView(McpToolView)`，`tool_name = "impact_analysis"`。步骤：
  1. `run, err = await self._begin(request)`（PAT fail-closed 由基类保证）→ `input_data, err = await self._validate(ImpactAnalysisRequestSerializer, request)` → `started_at = time.perf_counter()`。
  2. `repo, err = await self._get_indexed_repo(repository_id)`；`if err is not None: return err`（未索引 → 400 `repository_not_indexed`，🚨 ⛔ 绝不降级成空影响面——T-122-空图误导）。
  3. 函数体内延迟 import `from services.code_graph_tools import resolve_tool_graph_branch, run_impact, tool_trace_payload`（与 `ReverseLookupView` 的延迟 import 同款，避免 `mcp_tools` 模块级拉起 `services` 依赖树）。
  4. `graph_branch = await resolve_tool_graph_branch(repository_id, repo, input_data.get("branch"))`。
  5. `orch_started = time.perf_counter()`；`try: result = await run_impact(repository_id=…, repo=repo, graph_branch=graph_branch, user=request.user, symbol_id=…, symbol=…, file_path=…, symbol_type=…, max_depth=…, min_confidence=…, include_low_confidence=…, limit=…, max_cross_repo_hops=…, exclude_test_files=…)`；`except GraphError as exc: return _graph_error_response(exc)`（🚨 `GraphError` 是唯一从编排层冒泡的异常，翻译在这里完成——D-03）。`orchestration_ms = int((time.perf_counter() - orch_started) * 1000)`。
  6. `output_data = {**result, "run_id": str(run.run_id)}`。🚨 **信封原样透出、⛔ 一个键都不加工**——这是 D-21 的机械保证：对话壳把同一个 `result` 原样放进 `output["data"]`，两面的 `data` 段才可能逐字节相同（122-10 的 `test_two_surfaces_same_payload` 守这条）。
  7. **失败语义**（🚨 本相位在此**明确分叉**于 `search_delivery_knowledge` 的半先例）：`result["ok"] is False`（`symbol_not_found` / `ambiguous_symbol` / `symbol_not_in_graph`）一律返回 **HTTP 200 + 该信封**，⛔ 不转 4xx。理由写进 View 的 docstring：`ambiguous_symbol` 的候选列表是 agent 二选一的**唯一依据**（生产 19.3% 的名字不唯一，这是主路径不是兜底），转成 `{"error_code","detail"}` 的 4xx 会把候选列表整段丢掉；而 HTTP 码分叉一旦引入，对话面（没有 HTTP 概念）必然翻译成另一套语义——PATTERNS 记的第 2 条债（同一个故障，一面报「没有结果」、一面报「工具坏了」）就是这么长出来的。`ok=False` 只表示「这次查询没能定位到符号」，不是传输层错误。
  8. **留痕与观测**（`.cursor/rules/observability-logging.mdc`）：`duration_ms = int((time.perf_counter() - started_at) * 1000)`；`traces = [(RetrievalTrace.Kind.EDGE, tool_trace_payload(result, tool=self.tool_name, duration_ms=duration_ms, orchestration_ms=orchestration_ms))]`——🚨 **恰一条**汇总 trace，⛔ 不逐条影响面写 trace（agent 单任务可能调数百次 impact，逐条会撑爆留痕表，Pitfall 8）。`await self._record(run, input_data=input_data, output_data=output_data, traces=traces, started_at=started_at)`（基类顺带写 `RequestMetric(route="mcp:impact_analysis")`，QPS/错误率/时长自动纳入，⛔ 不要再自己记一遍）。再发一条 `caller` 事件：`logger.info("mcp_impact_analysis_completed", tool_name=self.tool_name, component="mcp_tools", category="caller", initiated_by_user_id=str(getattr(request.user, "id", "") or "system"), repository_id=repository_id, ok=bool(result.get("ok")), error_code=str(result.get("error_code") or ""), result_count=…, total_found=…, degraded=…, resolution_rate=…, duration_ms=duration_ms)`——⛔ 事件里不记符号名与文件路径。整段留痕/埋点用 `try/except Exception: pass` 包住？⛔ **不要**——`_record` 是基类既有路径（既有 40+ 工具都不包），只对**额外**的 `logger.info` 做 best-effort 处理即可（观测失败绝不反噬业务）。
