# Requirements: Friday AI

**Defined:** 2026-07-01
**Milestone:** v0.16.3 外部依赖接入知识体系（可检索 + 知识树 + 关联图谱）
**Core Value:** 把「项目外部依赖」（PRD / 需求文档、埋点评审、UI 文档、研发 Spec 等 = `initiatives.Artifact`）完整接入「知识」体系——可在 `/knowledge` 总览与搜索里发现、在知识树里浏览，并与关键词、业务能力、代码仓库互相建立关联，形成「文档 ↔ 能力 ↔ 仓库」可检索、可导航的交付知识网。

> 设计基线见 [`.planning/research/v0.16.3-external-deps-knowledge.md`](./research/v0.16.3-external-deps-knowledge.md)（现状探查 + 架构决策）。
> **复用而非新建**：外部依赖 = 现有 `initiatives.Artifact` + `ArtifactType`（8 内置类型），已有 delivery_knowledge 向量摄取（ragable 文字工件）与「工件→项目」`REFERENCES` 边。本里程碑补齐「进总览/进搜索呈现、进知识树浏览、与关键词/能力/仓库建关联、关联可视化」四块缺口。

## 关键设计决策（plan-phase / discuss-phase 必读）

- **外部依赖 = `initiatives.Artifact`**，不新建 `ExternalDependency` 模型；类型来自 `ArtifactType`（requirement_doc / feature_list / dev_spec / ui_design / ui_review / tracking_doc / tracking_review / retrospective）。
- **「总览」= 知识页总览 `KnowledgeDashboard`**（`/knowledge?tab=overview`），非项目作战室健康总览。
- **知识树接入方式 = 并行「交付文档」树视图**（项目 → 工件类型 → 工件），与代码派生的 PageIndex 能力树并列/切换，**不把外部文档塞进能力树**（能力树是代码语义，文档是项目交付语义，混用会污染两者）。
- **关联落地方式 = 复用 `RepoRouterV2` 对工件正文路由**（得 matched 仓库 + `matched_node_paths` 能力路径 + 关键词）+ 同步 verified `RepoAssociation`；关键词/业务能力**不建独立实体表**（它们是 `Repository.ai_summary_tree` 节点属性），用 `KnowledgeEdge(RELATES_TO)` + `metadata` 承载关联，避免大改 uuid5/migration。
- **可检索性优先 + 优雅好用**：非 ragable 类型（UI 稿 external_link）无正文可 embed，至少登记标题/类型/链接进关键词可搜索层，不遗漏任何类型。
- **约束沿用**：写入收口 INV-6；async ORM 走 `sync_to_async`；新增 LLM 调用赋 `call_source` 并上报请求/token/TTFT/上游错误码；新增召回写 `RetrievalTrace`；脱敏不可绕过；观测/关联代码 best-effort 绝不反噬业务；i18n 默认中文。

## v1 Requirements

里程碑 v0.16.3。每条映射到一个 Phase（见 Traceability）。Phases 96+ 续号。

### 进搜索与总览（DEP → 知识呈现，KDEP-01~03）

- [ ] **KDEP-01**: 所有「外部依赖」工件在知识体系中登记为可发现条目——ragable 文字工件走既有 `delivery_knowledge` 向量摄取（保持）；非 ragable 类型（如 UI 稿 external_link）至少登记标题/类型/链接元数据进关键词可搜索层，覆盖全部 `ArtifactType`，不遗漏。
- [ ] **KDEP-02**: `/knowledge` 搜索 Tab 命中外部依赖工件时，结果项标注工件类型（PRD / 埋点评审 / UI…）并可一键跳转到工件查看（复用 `ArtifactViewView` 的 markdown 渲染 / 飞书打开），跨项目按用户可见范围（`access_scope`）过滤。
- [ ] **KDEP-03**: 知识总览 `KnowledgeDashboard` 增加「交付文档 / 外部依赖」区块——按类型统计计数 + 入口 + 即时搜索，纳入总览大盘（与现有仓库/域指标并列，风格一致）。

### 进知识树浏览（TREE，KDEP-04~06）

- [ ] **KDEP-04**: `/knowledge` 知识树页新增并行「交付文档」树视图（项目 → 工件类型 → 工件），与代码能力树切换/并列展示，不改动 PageIndex 能力树数据。
- [ ] **KDEP-05**: 交付文档树支持树内搜索/过滤 + 点击叶子节点查看工件（复用查看弹窗，markdown / 飞书 / 外链），空态优雅、层级清晰。
- [ ] **KDEP-06**: 后端提供交付文档树数据 API（按用户可见 project 聚合 `Artifact`，分组为 项目→类型→工件），带权限过滤与节点上限保护。

### 建关联（LINK，KDEP-07~09）

- [ ] **KDEP-07**: 对 ragable 文字工件在摄取/更新时经 `RepoRouterV2` 路由其正文，得到匹配仓库 + `matched_node_paths`（能力树节点路径）+ 关键词，落为结构化关联（`KnowledgeEdge(RELATES_TO)` + `metadata={source:artifact, artifact_id, node_paths, keywords, score}`），单一写入入口、`call_source` 观测、fail-soft 绝不反噬。
- [ ] **KDEP-08**: 项目已确认的仓库关联（`RepoAssociation status=verified`）同步为项目/工件 ↔ 仓库的知识图谱边（扩展 `sync_relations_from_operational` / `link_repository`），复用 `RepoAssociation` 作为唯一真相源、图谱边单向派生，不新建重复真相源。
- [ ] **KDEP-09**: 工件 ↔ 关键词/业务能力/仓库关联可查询——给定工件列出相关仓库/能力/关键词；给定能力/关键词/仓库反查相关文档；查询走既有图谱遍历收口（`graph_store`）。

### 关联可视化与交叉入口（VIZ，KDEP-10~12）

- [ ] **KDEP-10**: 项目关系星图 `_build_project_galaxy` 扩展纳入 `artifact` 节点与边（`HAS_ARTIFACT` / `ARTIFACT_REPO` / `ARTIFACT_CAPABILITY`）；关联仓库来源并入 `RepoAssociation`（不再仅来自 MR）。
- [ ] **KDEP-11**: 知识实体图 / 实体详情页展示工件 ↔ 仓库/能力/关键词关联；仓库/能力视角反向展示相关交付文档（交叉入口，双向可导航）。
- [ ] **KDEP-12**: 作战室「外部依赖」区与知识体系打通——查看工件处可跳转到其知识实体 / 关联视图，形成「作战室 ↔ 知识」闭环。

- **KDEPX-01**: 业务能力/关键词升级为一等知识实体（新增 `EntityKind` + uuid5 规则 + migration），支持能力级别的独立详情页与跨项目聚合（成本高，先用 `ai_summary_tree` + 边 metadata 承载）。

## Out of Scope

| Feature | Reason |
|---------|--------|
| 新建 `ExternalDependency` / `Keyword` / `Capability` ORM 模型 | 外部依赖复用 `Artifact`；关键词/能力是能力树节点属性，用边 metadata 承载，避免重复建模与 migration 成本 |
| 把外部文档塞进代码 PageIndex 能力树 | 能力树是代码派生语义，文档是项目交付语义，混用污染两者；改为并行「交付文档」树 |
| 飞书文档正文的实时双向同步改造 | 沿用现有 artifact 摄取（拉取快照）；实时同步是独立能力 |
| 重写 delivery_knowledge 向量库 schema | 复用现有 `delivery_knowledge` collection 与 payload；仅新增 metadata/边，不改索引字段 |
