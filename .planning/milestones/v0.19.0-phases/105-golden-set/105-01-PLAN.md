    常量（模块级）：
    - `SIGNAL_TEXT = "text"`、`SIGNAL_BREADTH = "breadth"`、`SIGNAL_ACTIVITY = "activity"`（breakdown 字典 key，前端映射表与之对齐，禁止改名）

    - `WEIGHT_SET_VERSION = "phase105-v1"`（版本绑定四元组之一，快照与 baseline 都要记）
    - `ACTIVITY_ENUM_MAP = {"活跃开发": 0.9, "维护中": 0.6, "低频": 0.3, "疑似废弃": 0.1}`（ROUTING-RANKING §4 活跃度枚举映射；连续衰减归 Phase 106）
    - `DEPRECATED_ACTIVITY_CAP = 0.10`（CONTEXT：废弃惩罚从乘性 `score *= 0.5` 改为对活跃度项封顶 `min(A, 0.10)`）

    `@dataclass ScoredCandidate`：字段 `repo_id: str, repo_name: str, score: float, breakdown: dict[str, float], facets: dict, hits: list[dict]`（hits 透传供 Stage 1 组 prompt / finalize 取 node_path）。**repo_name 容错契约**：`repo_name = payload.get("repo_name") or repo_id`——replay 从最小字段集快照重建的 hit（105-03 快照 node_hits 不存 repo_name）与缺失 repo_name 的历史快照走同一路径，缺失时确定性回退 repo_id，且分数/breakdown/排序不受 repo_name 有无影响（tie-break 第二键本就是 repo_id）。

    `aggregate_and_score(node_hits: list[dict], *, weights: dict[str, float] | None = None) -> list[ScoredCandidate]`：
    1. 按 `payload.repository_id` 分桶（空 rid 跳过，与现行 `_aggregate_by_repo` 语义一致）；桶内按 `(-round(score, 6), str(payload.node_id))` 排序（消除 Qdrant 返回序依赖，CONTEXT 锁定「先量化再比较 + node_id 第二键」）。
    2. query-local max 归一：`rrf_max = max(所有 hit score)`；`s_hat = score / rrf_max`（rrf_max <= 0 时全部 s_hat=0，防除零）。
    3. 每桶三信号（全部 ∈ [0,1]）：
       - `text = max(s_hat of 桶内 hits)`
       - `breadth = min(len(hits) - 1, 5) / 5.0`（现有命中广度信号的加性重构，**不引入 pivoted size normalization**——归 Phase 106，per CONTEXT deferred）
       - `activity`：解析 top hit payload.facets（JSON str 时 `json.loads` 容错，沿用 `_parse_json_field` 语义但本模块内实现私有 helper）→ 取 `facets["活跃度"]` 经 `ACTIVITY_ENUM_MAP` 映射；值为「疑似废弃」时再 `min(A, DEPRECATED_ACTIVITY_CAP)`；**facet 缺失或值不在映射表 → 该信号标为不可用**（不是补 0——「未知≠确认不匹配」，ROUTING-RANKING §3.4）。
    4. 加性合成 + 缺失重归一化：`available` = 有值信号集合；`score = fsum(w[j]*M[j] for j in available) / fsum(w[j] for j in available)`；`breakdown[j] = w[j]*M[j] / fsum(w[j] for available)`（即有效贡献，保证 Σbreakdown == score 在重归一化后仍成立，INV-R3）。求和一律 `math.fsum`（消除浮点顺序依赖）。
    5. 候选列表排序：`key=lambda c: (-round(c.score, 6), c.repo_id)`（第二键不可变 repo_id，禁止 name/path）。
    6. **不做任何 `min(score, 1.0)` 截断**——归一化设计已保证 S∈[0,1]（各信号∈[0,1] 且权重凸组合）。

    `derive_confidence(sorted_scores: list[float], *, theta_abs: float, theta_margin: float, theta_med: float) -> Confidence`：照 ROUTING-RANKING §1.3a / RESEARCH「Code Examples」实现——空列表 → "low"；`margin = s1 - s2`（无 s2 时 s2=0.0）；`s1 >= theta_abs and margin >= theta_margin → "high"`；`s1 >= theta_med → "medium"`；否则 `"low"`。

    `apply_llm_adjustment(deterministic: Confidence, llm: Confidence | None) -> Confidence`：order={"low":0,"medium":1,"high":2}；llm 为 None 或非法值 → 返回 deterministic；否则 `min` 语义（只降不升，per CONTEXT RELY-04）。

    `Confidence = Literal["high", "medium", "low"]`（本模块自定义，不 import repo_router_v2 防循环依赖）。

    settings 外置（`server/friday/settings.py`，紧跟 REPO_ROUTER_STAGE1_* 段落，同注释风格）：
    - `REPO_ROUTER_CONF_THETA_ABS = env.float("REPO_ROUTER_CONF_THETA_ABS", default=0.55)`
    - `REPO_ROUTER_CONF_THETA_MARGIN = env.float("REPO_ROUTER_CONF_THETA_MARGIN", default=0.08)`
    - `REPO_ROUTER_CONF_THETA_MED = env.float("REPO_ROUTER_CONF_THETA_MED", default=0.35)`
    注释说明：确定性 confidence 阈值（RELY-04），初值来自 ROUTING-RANKING §1.3a，golden set 校准后可经环境变量调整不发版。`.env.example` 补三个变量与一行中文说明。
