<objective>
把降级与分组事实**持久化并送出 API 边界**：`RepositoryRoutingTrace` 加 `degrade_reason` 列（additive 迁移，可 SQL 聚合降级原因分布）；写入侧（chat 工具落 trace 处）填该列；会话 detail 的 `routing_trace` payload 从当前 5 键补到 9 键（补 `router_version` / `degraded` / `degrade_reason` / `block_order`）——不补这一处，**刷新页面后降级提示就消失**；manual override 新 trace 继承这些事实并在响应里回传（Pitfall 3 的后端半边，前端半边在 107-09）。

`degraded` 由后端派生（`router_version ∈ {v2_stage0_only, v1_fallback}`）而非新增一列：CONTEXT 要求「前端不自行推断」，推断放在后端即满足契约，且避免与 `router_version` 冗余。

Purpose: RELY-03 的事实要能跨刷新与跨 override 存活；ROUTE-01/02 的 `block_order` 契约在 API 边界成立。
Output: 1 个迁移 + 1 个模型列 + payload 两处补键 + 两个测试文件补用例。
</objective>
