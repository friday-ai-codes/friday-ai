  新建 `server/services/plan_orchestration/plan_validator.py`（zh-CN docstring，逐项对齐 DOMAIN §7 PlanValidator 校验项 + MERGE-02 拦截语义）。核心 `def validate_plan(merged: Any) -> dict`——**纯函数**（无 IO/无 ORM/无 LLM），返回 `{"valid": bool, "errors": list[dict], "warnings": list[dict]}`，每个 error/warning 形如 `{"check": <check_name>, "message": <定位串>}`。半可信输入：逐字段 `isinstance` + `.get` 防御，缺字段当空集/空 list 处理，**绝不抛异常**（对齐 verify_plan fail-safe 范式，T-40-01-01）。
  约定数据形状（Claude's Discretion，写入 docstring 固化，供 40-02 synthesizer prompt 对齐）：`dependency_dag` 为邻接表 `{repo_id: [depended_repo_id, ...]}`（repo_id→其依赖的仓）；`execution_plan[].dependencies` 为 task id 列表；`release_order` 为 repo_id 列表；`data_migrations[]` 项含 `{repository_id, ...}`；`rollback_plan` 为 dict/非空文本。
  5 项校验（各自独立函数，`validate_plan` 汇总 errors）：
  1. **契约一致性** `_check_contract_consistency`：汇总所有仓 `api_contracts[]`（顶层跨仓汇总）∪ 各 execution_plan/partial 派生的 `api_contracts_exposed` 为「暴露集」（按契约 name/id 归一化字符串）；遍历 `dependency_dag` 的依赖边引用 + 任意 `dependencies_on_other_repos` 引用，若引用的契约不在暴露集 → 记 error（指出 from_repo / 缺失契约）。
  2. **依赖 DAG 无环** `_check_acyclic`：合并 `dependency_dag` 邻接 + `execution_plan[].dependencies`（task 维度映射到 repo 维度或独立 task 图均可，统一成有向图）；Kahn 拓扑（入度归零队列）或 DFS 三色检测环；有环 → error 列出环上节点。注意自环、重复边去重。
  3. **迁移顺序合理** `_check_migration_order`：按 `data_migrations[]` 出现顺序建立 index；对每条依赖关系（被依赖仓 must-before 依赖仓），若被依赖仓的迁移 index 大于依赖仓 → error。无迁移项时跳过（不报错）。
  4. **发布顺序与依赖一致** `_check_release_order`：按 `release_order[]` 建 index；对 dependency_dag 每条边 (X 依赖 Y)，要求 Y 的 release index < X 的 release index，否则 error。release_order 缺失某依赖节点 → warning（不阻断）。
  5. **回滚完整** `_check_rollback_completeness`：`rollback_plan` 为空（None/""/{}/[]）→ error；非空但未覆盖 execution_plan 涉及的某 repository_id（约定 rollback_plan 为 `{repo_id: <步骤>}` 或含 `repositories`/`steps` 列表，按可解析形状检查覆盖）→ error 列出未覆盖仓。
  curated re-export `validate_plan`（+ 可选 check 名常量）到 `__init__.py` import 块与 `__all__`。ruff 行宽 100。
