      - `clarifying`：`{"clarified": "researching", "needs_clarification": "clarifying"}`（有待澄清→自挂起 clarifying）
      - `researching`：`{"research_dispatched": "researching", "research_complete": "merging"}`（fan-out 等待→自留 researching；barrier 通过→merging）
      - `merging`：`{"merged": "done", "validation_failed_reclarify": "clarifying", "validation_failed_rereresearch": "researching"}`（§14：PlanValidator 失败按报告回退 clarifying 或 researching）
      - 在 docstring/注释逐条标注对应 §14 表行。`fail` 事件**不进 _ALLOWED**，由 transition 特判（任意状态 → failed）。
    - `transition(self, session, event, **payload) -> PlanSession`（async，唯一 status 变更入口）：
      - `event == "fail"`：set `session.status = FAILED`，把 `payload.get("error")` 结构化写入 `session.error`（dict；非 dict 包成 `{"message": str(error)}`），`save`（update_fields 含 status/error/updated_at），调 `await self._emit_event("plan.session.failed", session, payload)`，返回 session。
      - 否则：查 `_ALLOWED.get(session.status, {})`；event 不在其中 → `raise ValueError`（消息含 from_status + event + 该状态合法 event 集）。合法 → set `session.status = to_status`；按 payload 持久化中间产物（如 event=="decomposed" 时把 `payload.get("decomposition")` 写入 `session.decomposition`；通用：payload 中与模型字段同名的键 decomposition/current_plan_version/event_time 落字段），`save`，调 `await self._emit_event(event, session, payload)`，返回 session。
      - ORM 写经 `sync_to_async`（沿用 comment_event_service 的 `@sync_to_async def _xxx_sync` 范式）。
    - `_emit_event(self, event_name, session, payload) -> None`（async，**钩子占位**）：best-effort no-op + `logger.info("plan_session_event", event=event_name, session_id=str(session.id))`；docstring 注明事件 taxonomy 真实发射在 Phase 41（§15），本 phase 仅钩子点，绝不抛出影响转移。
