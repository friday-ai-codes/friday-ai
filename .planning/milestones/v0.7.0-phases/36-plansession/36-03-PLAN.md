    - `class PlanOrchestrationEngine`：`__init__(self, *, session_service=None, router=None, recall=None, research=None, merge=None)` —— 依赖注入（入口无关）。默认值：`session_service = session_service or PlanSessionService()`；router/recall/research/merge 缺省用 Task 1 的 `Skeleton*` 实例。engine **不**接收任何 workflow/chat IO 对象（保持入口无关，per CONTEXT）。
    - `async def advance(self, session) -> PlanSession`：状态驱动 step 推进器。读 `session.status` 分派到对应 stage handler；handler 完成后**经 `self.session_service.transition(session, event, **payload)` 驱动转移**（engine 绝不直接写 `session.status`，守 36-02 INV-6 守护）。分派映射（按 PlanSessionStatus）：
      - `decomposing` → `await self._decompose(session)`
      - `routing` → `await self._route(session)`
      - `recalling` → `await self._recall(session)`
      - `clarifying` → `await self._clarify(session)`
      - `researching` → `await self._research(session)`
      - `merging` → `await self._merge(session)`
      - `done` / `failed` → 终态：直接返回 session（no-op，不转移）。
      整段包 try/except：stage 内不可恢复异常 → `await self.session_service.transition(session, "fail", error={...})` 落 failed（结构化 error 含 stage/exception 类型/消息），再返回 session（不向上抛 raw 异常）。**例外**：骨架 stage 主动抛的 `NotImplementedError` 应原样上抛（便于 38-41 开发期暴露未接入，不被吞成 failed）——在 except 中 `except NotImplementedError: raise` 先行。
    - stage handlers：
      - `async def _decompose(self, session)` —— **最小真实实现**：从 session 关联需求文本（本 phase 取 `session.decomposition` 既有输入或 work_item.title/占位；若无文本源，按 session.decomposition.get("requirement_text","")）+ include_repos（session.decomposition.get("include_repos", [])）拆成结构化 decomposition（如 `{"requirement_text":..., "include_repos":[...], "segments":[...]}`，segments 可为最小切分如按行/按仓）。然后 `await self.session_service.transition(session, "decomposed", decomposition=<新 decomposition>)`（→ routing）。
      - `_route/_recall/_research/_merge` —— 骨架：调注入依赖（`await self.router.route(session)` 等）。骨架默认实现会抛 NotImplementedError（带 phase TODO）；当注入真实/mock 依赖时，handler 取其返回并经 `transition` 推进对应 event（_route→"routed"→recalling；_recall→"recalled"→clarifying；_research 本 phase 简化为调 research.dispatch 后 transition "research_complete"→merging（真实 fan-out/barrier 留 39）；_merge→调 merge.merge 后 transition "merged"→done）。每个 handler 顶部 TODO 注释标注真实实现接入 phase。
      - `async def _clarify(self, session)` —— 骨架：本 phase 无澄清逻辑（留 41），最小 pass-through：`await self.session_service.transition(session, "clarified")`（→ researching）+ TODO 注释「Phase 41 Clarification 回路」。
