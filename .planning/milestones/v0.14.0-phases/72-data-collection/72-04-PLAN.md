在 `search_rag`（单一 chokepoint）出口落召回指标，**绝不改既有行为契约**（zero-drift：步骤顺序/去重/排序/返回结构逐字不变，仅旁路加计时与一次指标写入）：
- 用 `time.perf_counter()` 包裹各阶段，得分层耗时：`stage_embedding_ms`（`EmbeddingService.generate_embedding`）、`stage_sparse_ms`（`SparseEncoderService.encode`）、`stage_qdrant_ms`（`asyncio.gather(_search_one...)` 整段，即逐仓 qdrant 混合检索）、`stage_rerank_ms`（`reorder(...)`）。
- 在函数返回前（含 error 早退路径也尽量记一行 status 标签）调 `record_request_metric(source="rag", route="search_rag", method="RAG", status_code=200, duration_ms=<总耗时>, user_id=<contextvars>, labels={...})`，labels 取受控键：`call_source=get_call_source() or ""`（来源 MCP/对话/workflow 区分，由各调用方经 contextvar 设；缺省读不到则空）、`recall_count=len(all_results)`、`top_score=round(all_results[0].score,4) if all_results else 0`、`stage_embedding_ms`/`stage_sparse_ms`/`stage_qdrant_ms`/`stage_rerank_ms`。embedding 失败早退（status="error"）记 `labels={"call_source":..., "stage_embedding_ms":..., "rag_status":"error"}`（rag_status 需加入 _ALLOWED_LABEL_KEYS——若 72-01 未含则在 record_request_metric 白名单补该键）。
- 整段指标代码 `try/except: pass`（best-effort），绝不让计时/写入异常影响召回返回；**不**按 chunk 写指标（仅一行聚合，§A.4 基数控制）。
- 高频纪律：召回是高频内部步骤，指标行用聚合一行；structlog 若加事件用 `category=sampling, component=rag`（不在循环内逐条 INFO 刷屏，per 观测规范）。

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 用户 query（非可信） → RetrievalTrace.payload | query 原文 + 召回 chunk 内容入库 |
| 召回结果 → 指标 labels | 召回条数/耗时/score 进受控 labels |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-72-04-01 | Information Disclosure | query/chunk 内容含凭证经 RetrievalTrace 泄漏 | mitigate | payload 写库前必经 `redact_for_ledger`（既有契约）；测试注入假凭证断言被脱敏 |
| T-72-04-02 | Information Disclosure | 召回内容/query 原文当 metric label 致基数失控+泄漏 | mitigate | 指标 labels 仅受控键（recall_count/top_score/stage_*_ms/call_source）；query/chunk **绝不**进 labels，只进 RetrievalTrace（留痕，按需采样） |
| T-72-04-03 | Spoofing | user/conversation 归因伪造 | accept | user_id 取服务端 Phase 71 contextvars；conversation_id 取工具注入的服务端值（非 LLM 自填） |
| T-72-04-04 | Denial of Service | 每 chunk 一行 trace 撑爆留痕表 | mitigate | 召回内容按 top-N 采样写 trace（§A.4），指标只一行聚合；高频不 INFO 刷屏（category=sampling） |
| T-72-04-05 | Denial of Service | 留痕/指标写入拖慢召回 | mitigate | 全 best-effort try/except + 不在召回主路径阻塞；zero-drift 行为契约保持 |
| T-72-04-SC | Tampering | npm/pip/cargo 安装 | accept | 本 plan 不新增依赖（复用 72-01/72-02 helper + 既有 redact_for_ledger） |
