新建 `server/system/alert_evaluator.py`（中文 docstring，ruff-100，`from __future__ import annotations`；全程 best-effort 单规则隔离绝不反噬）：

1. **metric→源分派 `async def _resolve_current_value(rule) -> float | None`**：把 `rule.metric` 映射到当前值来源（取不到返回 None → 本轮该规则跳过，不臆造）：
   - **时序类**（`qps`/`error_rate`/`ttft`）：经 `sync_to_async(metrics_query.query_timeseries, thread_sensitive=True)` 查 `start=now-window`/`end=now`/`step=window`（**单桶聚合得窗口当前值**）；
     - `qps` → `metric="qps"`，取最近桶 `value`（计数/window 折算或直接计数，注释明确口径）；
     - `error_rate` → 用 `metric="sla"` 的 series 派生（`failures/eligible`）或 `metric="error"` 计数比；倾向用 sla series 的 `failures`+`eligible` 算 `failures/eligible` 作错误率（与 SLA-01 口径一致：排除 business）；series 空 → None。
     - `ttft` → `metric="ttft"`, `agg=rule.dimension.get("agg","p95")` 受控（默认 p95），取最近桶 value（ms）。
     - dimension：把 `rule.dimension`（如 provider）透传给 query_timeseries 的 `dimension` 参数（受控，已在 74-01 serializer 限定）；多 dim 时取匹配 target 的桶。
   - **快照类**（`cpu`/`memory`/`db_connections`/`redis_clients`/`qdrant`/`queue_depth`）：调 `await snapshot_service.collect_snapshot()` 一次，按 metric 取值：
     - `cpu` → `host.cpu_percent`；`memory` → `host.mem_percent`；
     - `db_connections` → `db.connections.total`（available=false → None）；
     - `redis_clients` → `redis.clients.*.connected_clients` 求和或取主路（available 判定）；
     - `qdrant` → `qdrant.collection_count`（或可用性布尔转 0/1，注释明确）；
     - `queue_depth` → `concurrency.durable_queues` 的 doing+todo 汇总（按 rule.dimension.queue 过滤，缺省汇总）。
   - **趋势类 gauge:*（RATE-03）显式不参与**：`rule.metric` 不在受控集合 → 返回 None + warning `alert_metric_unsupported`（默认不告警，per 74-CONTEXT）。
   - 整函数 try/except——取值异常返回 None（单规则隔离，绝不抛）。
2. **阈值比较 `def _breached(op: str, current: float, threshold: float) -> bool`**：`gt/gte/lt/lte` 纯函数比较。
3. **target/rule_info 构造**：
   - `def _target_for(rule) -> tuple[dict, str]`：target = `rule.dimension or {}`；`target_key = json.dumps(target, sort_keys=True, ensure_ascii=False)`（规范化，喂 74-01 去重约束）。
   - `def _build_rule_info(rule, current) -> dict`：`expr = f"{rule.metric} {OP_SYMBOL[op]} {threshold:.2f} (current {current:.2f}) over last {window_human} ({dim_label})"`（REFERENCE-UI §1.4 同款；`window_human` 如 `5m`，`dim_label` overall 或 `provider=anthropic`）；返回 `{"metric","op","threshold","current","window_s","dimension","expr"}`（机器可读 + expr 字符串）。
   - `def _render_title(rule, current) -> str`：按 `rule.title_template` 渲染（`{metric}/{current}/{value}` 占位）；空模板 → 默认 `f"{rule.metric} {op} {threshold}（当前 {current}）"`（中文）。
4. **去重/恢复收口**（服务层，配合 74-01 DB 条件唯一约束）：
   - `async def _open_or_update_firing(rule, current) -> tuple[AlertEvent, bool]`：`target, target_key = _target_for(rule)`；用 `AlertEvent.objects.aget_or_create(rule=rule, target_key=target_key, status="firing", defaults={...started_at=now, severity, title_zh, rule_info, target, current_value, last_seen_at})`（aget_or_create 幂等避免并发双开；DB 条件唯一约束兜底 IntegrityError → 退化为取已存在 firing 更新）。已存在（created=False）→ 仅更新 `current_value/last_seen_at/rule_info`（**不刷屏、不新建**）`asave(update_fields=...)`。返回 `(event, created)`。
   - `async def _resolve_firing(rule, target_key) -> AlertEvent | None`：取该 (rule,target_key) 的 firing；存在 → `status="resolved"`, `ended_at=now`, `duration_s=int((ended-started).total_seconds())`，`asave`；返回 resolved event；无 → None。
5. **`async def evaluate_system_alerts() -> dict[str, int]`**（评估循环主体）：
   - `rules = [r async for r in SystemAlertRule.objects.filter(enabled=True)]`；逐规则 **独立 try/except**（单规则失败只 warning `alert_rule_eval_failed`(rule_id) 跳过，绝不连累其它规则/不反噬）：
     - `current = await _resolve_current_value(rule)`；`current is None` → 跳过（取不到值不评估）。
     - `breached = _breached(rule.op, current, rule.value)`。
     - breached → `event, created = await _open_or_update_firing(rule, current)`；`created` 为真（**新 firing**）→ `await _maybe_notify(rule, event)`（见下）；非新建（重复超阈）→ 仅更新值，不通知（cooldown 见下）。
     - not breached → `resolved = await _resolve_firing(rule, target_key)`；`resolved` 非 None → 记 `firing→resolved` + 可选 `await _maybe_notify(rule, resolved)`（恢复通知 best-effort）。
   - `_maybe_notify(rule, event)`：**cooldown 防抖**——若 `event` 距上次通知（用 `last_seen_at`/单独跟踪或简单按 created 首次通知）在 `rule.cooldown` 内则跳过（首次 firing 必通知，重复在 cooldown 内不再通知）；`from system.alert_notifier import notify_channels`；`await notify_channels(event, rule.channels or [])`（74-03，已 best-effort 绝不反噬，本处再 try/except 兜底）。
   - 汇总返回 `{"evaluated": n, "firing": x, "resolved": y}`。
   - 日志：循环入口 `logger.info("alert_eval_cycle", category="sampling", component="alerting", evaluated=n, ...)`（**评估周期高频→sampling**，不刷 caller）；每次新 firing/resolved `logger.info("alert_firing"/"alert_resolved", category="caller", component="alerting", rule_id=..., metric=..., current=..., severity=..., duration_ms=...)`（caller，可归因）。
   - 整函数最外层 try/except 兜底返回 `{"evaluated":0}`（绝不抛回 job wrapper）。
6. **`server/tests/test_alert_evaluator.py`（新建）** `@pytest.mark.django_db(transaction=True)`：
   - (a) 快照类规则 `metric="cpu", op="gt", value=80` + monkeypatch `collect_snapshot` 返回 `host.cpu_percent=95` → `evaluate_system_alerts()` 后 DB 有 1 条 firing（severity/title_zh/rule_info.expr 含 `current 95`），且 `notify_channels` 被调一次（monkeypatch 记录）；
   - (b) 再跑一轮（仍 cpu=95）→ **不新建**第二条 firing（仍 1 条，current_value/last_seen_at 更新），cooldown 内 notify 不再调；
   - (c) 第三轮 monkeypatch cpu=10（不超阈）→ 该 firing 转 resolved（ended_at/duration_s 非空），firing 计数归零；

   - (e) `metric="gauge:queue.durable_doing"`（趋势类）→ `_resolve_current_value` 返回 None + 不评估（RATE-03 默认不参与）；
   - (f) monkeypatch 某规则 `collect_snapshot` 抛错 → 该规则跳过、其它规则正常评估（单规则隔离，evaluate_system_alerts 不冒泡）。
