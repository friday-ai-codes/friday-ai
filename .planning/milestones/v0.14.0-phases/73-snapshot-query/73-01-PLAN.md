补齐快照采集器剩余三源，全部 best-effort（envelope 同 Task 1，整函数兜底不抛）：

1. **`async def collect_redis_snapshot() -> dict`（SNAP-03）**：覆盖三路客户端 URL——`cache`(`settings.CACHE_REDIS_URL`)、`channels`(`settings.REDIS_CHANNEL_LAYER_URL` 当 `USE_REDIS_CHANNEL_LAYER`)、`llm`(`settings.LLM_CONCURRENCY_REDIS_URL`)。**去重相同 URL**（多路常指同一 Redis，按 url 聚合避免重复 INFO）。每路用 `redis.asyncio.from_url(url, decode_responses=True)` 在 `SOURCE_TIMEOUT_FAST` 内 `await client.info()`，取 `connected_clients`/`maxclients`(无则 `maxclients` 从 `CONFIG GET maxclients` 兜底或标 None)/`used_memory`/`used_memory_human`/`keyspace_hits`/`keyspace_misses` → 命中率 `hits/(hits+misses)`（分母 0 记 None）。未配置某路（url 空）→ 该路 `{"available": False, "error": "not_configured"}`，不算整源失败。返回 `{available, clients: {cache: {...}, channels: {...}, llm: {...}}}`（available=任一路成功）。逐路独立 try/except，单路失败不拖垮其它路。**绝不**把 redis client 缓存进模块全局长持（按需创建 + `await client.aclose()` 释放，避免连接泄漏）。
2. **`async def collect_qdrant_snapshot() -> dict`（SNAP-04，缓存+长超时硬约束）**：分两层——
   - **可用性（快）**：`sync_to_async(QdrantService.ping_liveness, thread_sensitive=False)` 在 `SOURCE_TIMEOUT_FAST` 内（GET /healthz，毫秒级）；失败 → `{"available": False, "error": ...}` 直接返回（不再枚举 collection）。
   - **collection 数 + 占用（重，带缓存 TTL~60s + 长超时）**：先读 `django.core.cache` key `system:qdrant:snapshot:v1`（命中直接用，避免高频枚举拖垮 Qdrant——硬约束）；未命中则 `sync_to_async(_enumerate_qdrant, thread_sensitive=False)` 在 `SOURCE_TIMEOUT_SLOW` 内枚举：`_enumerate_qdrant` 复用 `QdrantService` 缓存 client（**绝不** reset client，per qdrant_service.health_check 不变量注释）调 `get_collections()` 取 collection 数；占用空间 best-effort（遍历 collection 累加 `points_count`/`vectors_count` 或读 `client.get_collection(name)`，**为避免拖垮限制只采样前 N 个 collection 或仅取总数**——占用取不到记 None，不强求精确）。结果 `cache.aset(key, data, 60)`。区分 `liveness`(ping 结果) 与 `enumerated`(collection 详情) 两段，任一段失败另一段仍返回。返回 `{available, liveness: true, collection_count, approx_size: {...|null}, cached: bool}`。
   - **超时纪律**：枚举段用 `SOURCE_TIMEOUT_SLOW`（长超时），ping 段用 fast；整源 `asyncio.wait_for` 包裹防永久挂起。
3. **`async def collect_concurrency_snapshot() -> dict`（SNAP-05）**：四块，逐块独立 try/except：
   - **provider 槽位占用**：枚举活跃 `ProviderCredential`（`is_active=True, max_concurrency>0`）经 `sync_to_async`；若 `settings.LLM_CONCURRENCY_REDIS_URL` 非空 → 用 `llm_concurrency._get_redis_client(url)` 对每凭证 `_slot_key(cred_id)` 先 `ZREMRANGEBYSCORE ... now-ttl` 清过期再 `ZCARD` 得当前占用（per llm_concurrency Lua 语义）；否则读 `llm_concurrency._inprocess_semaphores`（`capacity - sem._value` = 占用，best-effort 内省）。返回 `[{credential_id, provider, max, in_use}]`。
   - **durable 队列 todo/doing**：复用 `observability_views._durable_queue_stats()`（procrastinate_jobs by queue×status，SQLite/未启用 durable 降级空）经 `sync_to_async`。
   - **runner 待派发/本地队列**：`RunnerTaskAssignment` 按 status 计数（pending/dispatched）+ `Runner.objects.filter(is_active=True)` 的 `current_tasks`/`max_concurrent` 汇总（per runners/consumers）。
   - **RAG 并发**：若存在 RAG 并发信号量/槽位（grep `search_rag`/embedding 并发控制；无显式信号量则记 `{"available": False, "error": "n/a"}`，不臆造）。
   返回 `{available, provider_slots, durable_queues, runner, rag}`。
4. **`async def collect_snapshot() -> dict`（聚合器）**：`asyncio.gather(collect_host_snapshot(), collect_db_snapshot(), collect_redis_snapshot(), collect_qdrant_snapshot(), collect_concurrency_snapshot(), return_exceptions=True)`；对 gather 返回的异常项兜底成 `{"available": False, "error": str(exc)}`（双保险，单源即便抛也不拖垮聚合）。返回 `{"host": ..., "db": ..., "redis": ..., "qdrant": ..., "concurrency": ..., "generated_at": timezone.now().isoformat()}`。
