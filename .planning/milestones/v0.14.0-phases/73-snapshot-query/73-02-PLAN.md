新建 `server/system/metrics_query.py`（时序聚合单一服务，中文 docstring，ruff-100，`from __future__ import annotations`；async ORM/raw SQL 经 `sync_to_async(thread_sensitive=True)` 桥接）：

1. **受控枚举常量**（禁任意字符串污染/SQL 注入面）：
   - `_METRICS = frozenset({"qps","tps","sla","error","duration","ttft"})` + gauge 前缀 `gauge:` 特例（name 受控见 73-01 GaugeSample 命名）。
   - `_AGGS = frozenset({"p95","p90","p50","avg","max"})`。
   - `_DIMENSIONS = frozenset({"source","provider","call_source","error_class","route","model"})`（白名单列名，**仅这些**可进 GROUP BY，杜绝任意列注入）。
   - `_PERCENTILE = {"p95":0.95,"p90":0.90,"p50":0.50}`。
2. **参数解析 helper**：
   - `def _parse_step(step: str) -> int`：解析 `30s/1m/5m/1h/1d` → 秒（默认 60s，最小 10s，最大 1d）。非法回默认。
   - `def _parse_range(start, end) -> tuple[datetime, datetime]`：ISO8601 解析，缺省 end=now / start=end-1h；**上限保护**：跨度 / step 的桶数超过 `_MAX_BUCKETS=2000` 时按比例抬高 step（防超大返回拖垮 DB，per §A.4 原始行无限增长缓解）。
   - `def _validate(metric, agg, dimension)`：metric∉_METRICS 且非 gauge: → ValueError(中文)；agg∉_AGGS → 默认 p95；dimension 非空且∉_DIMENSIONS → ValueError。校验失败由 view 转 400。
3. **任意 step 时间桶（双后端）** `_bucket_expr(time_col, step_seconds, vendor)`：
   - Postgres：`to_timestamp(floor(extract(epoch from {time_col})/{step})*{step})`（epoch-floor 分桶，支持任意 step，比 date_trunc 更通用）。
   - SQLite：`datetime((strftime('%s',{time_col})/{step})*{step},'unixepoch')`（整数除法分桶）。
   step_seconds 经 `int()` 收口（非用户原文拼接，注入安全）。
4. **QPS / 错误计数 metric**（基于 `request_metrics` 表，时间列 `ts`）：
   - `def _query_count(*, table, time_col, start, end, step, vendor, dimension, where_extra) -> list[dict]`：`SELECT {bucket} AS bucket, {dim_col|'__all__'} AS dim, COUNT(*) AS value FROM {table} WHERE {time_col} >= %s AND {time_col} < %s {where_extra} GROUP BY bucket, dim ORDER BY bucket`（参数化 start/end；table/列名取自白名单常量，不拼用户原文）。
   - **qps**：table=request_metrics，`where_extra` 默认排除 synthetic（`labels` jsonb：Postgres `(labels->>'synthetic') IS DISTINCT FROM 'true'`；SQLite `json_extract(labels,'$.synthetic') IS NOT 1`），按 dimension(source/route…) 分组；value=count（前端按 step 折算速率）。
   - **error**：同 request_metrics，按 `error_class` 分组（含 none/system/business/upstream），synthetic 排除；支撑错误率（系统/业务/上游三口径）。
5. **`tests/test_metrics_query.py`（新建）**：`@pytest.mark.django_db(transaction=True)`（async 写读不跨连接泄漏，per 73-CONTEXT）。(a) `_parse_step`/`_parse_range`/`_validate` 单测（含非法→默认/ValueError + 桶数上限抬 step）；(b) 造若干 RequestMetric（跨两个时间桶 + 含 synthetic 行 + 不同 source/error_class）→ qps 查询返回正确桶计数且 **synthetic 行被排除**；(c) error 查询按 error_class 分组计数正确（business 单列）。事件名 snake_case。

补齐分位、TPS、趋势三类 metric（同文件，双后端分支）：

1. **分位时长/TTFT**（duration/ttft，基于 `request_metrics`，列 `duration_ms`/`ttft_ms`）：
   - `def _query_percentile(*, value_col, agg, start, end, step, vendor, dimension, where_extra) -> list[dict]`：
     - **Postgres（精确）**：agg∈{p95/p90/p50} → `percentile_cont({frac}) WITHIN GROUP (ORDER BY {value_col})`；agg=avg → `AVG`；agg=max → `MAX`。SELECT bucket + dim + 该聚合 AS value，`WHERE {value_col} IS NOT NULL` + synthetic 排除 + 时间窗，GROUP BY bucket,dim。
     - **SQLite（降级，per §A.4）**：无 `percentile_cont` → 分位请求降级：p95/p90 → `MAX`、p50 → `AVG`（近似兜底），avg→AVG、max→MAX；返回结果附 `degraded: true` + `note:"sqlite_percentile_approx"` 让前端/调用方知悉非精确。**功能不阻塞**（绝不因 dev 无分位而 500）。
   - frac 取自 `_PERCENTILE`（受控 float，不拼用户原文）。
2. **TPS**（基于 `model_usage_records`，**时间列 `created_at`**，注意非 ts）：
   - `_query_sum(*, table=model_usage_records, value_col=total_tokens, time_col=created_at, ...)`：`SUM(total_tokens)` per bucket，按 dimension(provider/call_source/model) 分组（无 synthetic 概念，不排除）。返回桶内 token 总量（前端按 step 折算 TPS，单位 K per RATE-03）。同理可支持上游错误码维度（dimension=call_source + where upstream_status_code in (429,529) 由后续 Phase/前端按需，本 plan 至少提供 token 求和 + provider/call_source 分组）。
3. **gauge 趋势**（metric=`gauge:<name>`，基于 `gauge_samples`，列 `value`、时间列 `ts`）：
   - 校验 `<name>` 经 `_validate_gauge_name`（仅允许 73-01 GaugeSample 写入的受控前缀如 `concurrency.`/`queue.`/`backlog.`，未知名 → ValueError）。
   - agg=avg/max → AVG/MAX(value)；p50 → AVG 近似（gauge 分位意义弱）。返回桶序列。RATE-03 并发/队列深/积压趋势消费此路。
4. **统一出口** `def query_timeseries(*, metric, start, end, step, dimension="", agg="p95") -> dict`：校验 + 解析 + 按 metric 分派到 `_query_count`(qps/error) / `_query_percentile`(duration/ttft) / `_query_sum`(tps) / gauge 分支；返回 `{"metric","agg","step_seconds","start","end","vendor","degraded","series":[{"bucket","dim","value"}...]}`。整体经 `sync_to_async` 在视图调用。
扩 `tests/test_metrics_query.py`：(a) 造 RequestMetric duration_ms 跨桶 → duration agg=p95 在 Postgres CI(若 PG)精确、SQLite 返回 degraded=true 且 value=MAX 兜底（用 `connection.vendor` 分支断言，不强求真 PG）；(b) 造 ModelUsageRecord total_tokens 多行 → tps 按 provider 分组 SUM 正确（注意 created_at 时间列）；(c) 造 GaugeSample 两桶 → `gauge:concurrency.provider_slots` avg 正确；未知 gauge name → ValueError；(d) duration 查询 value_col 为 null 的行被 WHERE 排除。
