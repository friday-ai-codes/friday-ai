<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| runner SA → k8s API（RBAC） | runner Pod 经 SA token 调 k8s API，权限由 namespaced Role 约束 |
| 多副本 runner 共享 namespace | 同 namespace 多 runner 的 Job 清理/扫描需隔离 |
| helm 模板 → 集群部署形态 | docker.sock hostPath 挂载是宿主逃逸面 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-64-04 | Elevation of Privilege | runner RBAC | mitigate | namespaced `Role`（非 ClusterRole）+ 精确 verbs（jobs create/get/list/watch/delete、pods get/list/watch、pods/log get）；values-gated 仅 k8s 模式创建 |
| T-64-05 | Denial of Service | StartupCleanup/ZombieScan 跨副本 | mitigate | `friday.runner=<name>` label selector 隔离，只清本 runner 残留（Pitfall 3） |
| T-64-06 | Elevation of Privilege | docker.sock 残留挂载（k8s 模式） | mitigate | k8s 分支 helm 不渲染 docker.sock volume/mount，消除宿主逃逸面 |
| T-64-07 | Spoofing/InfoDisc | answerEndpoint / HITL（k8s） | accept | HITL answer 端到端在 k8s 为已知限制（需 task HTTP server 或 RWX 共享卷，均 out-of-scope）；核心 dispatch/logs/wait/cleanup 不依赖它，文档化 + 真机 manual 验收 |
</threat_model>
