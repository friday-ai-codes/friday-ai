    新建 `server/chat/session_store.py`，`class SessionStore`：
    - `async def mirror(self, *, coding_session) -> None`：把 `coding_session.sdk_session_id` + `sdk_transcript`（+ cwd、saved_at）写一份到 Redis（key 形如 `friday:sdk_session:{coding_session_id}`，value JSON，带 TTL，例如 7 天与「7 天内 resume」一致）。Redis 不可用 → 吞异常（best-effort，DB 仍是真相源）。
    - `async def load(self, *, coding_session) -> dict | None`：优先读 Redis（命中返回 `{sdk_session_id, sdk_transcript, cwd}`），未命中/Redis 故障 → 降级读 DB（`coding_session.sdk_session_id`/`sdk_transcript`）。两者皆空 → None（调用方走「用应用态重灌新 session」兜底，§9）。
    - `def assert_cwd_consistent(self, *, stored_cwd, dispatch_cwd) -> bool`：transcript 目录按 cwd realpath 派生（见 sdk_sessions），dispatch 的容器 workspace cwd 必须与首跑一致才可 resume；不一致返回 False（调用方放弃 transcript resume，回退新 session，绝不静默错配）。
    - 全模块 best-effort：任何 Redis/序列化异常都吞掉 + structlog warning（category=sampling, component=chat），绝不反噬派发/回调主流程。

    接线：
    - `sdk_resume.build_resume_dispatch_env` 改为先 `SessionStore().load(coding_session=...)` 取 transcript（Redis→DB），并经 `assert_cwd_consistent` 校验；命中且 cwd 一致才注入 resume env，否则返回 {}（与现状默认安全一致）。**保持函数签名与返回 env 键不变**（dispatch 消费契约不破）。

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server dispatch → 容器 env/prompt 注入 | 项目上下文跨进程注入容器，须脱敏 + visibility fail-closed |
| 容器回调 → SessionStore(Redis) 镜像 | 半可信 runner 上报 transcript 镜像，须 best-effort 不反噬 + cwd 一致校验 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-86-02-01 | Information Disclosure | 项目上下文注入容器 env/prompt | mitigate | `pack_project_context` 内置 visibility fail-closed（非成员零召回）+ 注入前 `redact_secrets_in_text` 脱敏；RetrievalTrace 经 redact_for_ledger |
| T-86-02-02 | Tampering | 跨容器 resume transcript 错配 | mitigate | `assert_cwd_consistent` 校验 cwd 一致才 resume，不一致回退新 session（绝不静默错配他容器 transcript） |
| T-86-02-03 | Denial of Service | Redis 故障 / 镜像失败反噬派发 | mitigate | SessionStore 全 best-effort（Redis 故障降级 DB，镜像失败吞异常）；dispatch 召回空/异常 fail-soft 回退现状 |
| T-86-02-04 | Repudiation | dispatch 召回无归因 | mitigate | 召回带触发用户 + `initiated_by_user_id`（无则 system），RetrievalTrace 留痕 |
</threat_model>
