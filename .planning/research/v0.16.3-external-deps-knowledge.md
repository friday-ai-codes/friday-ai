## 1. 现状：核心事实（带落点）

### 1.1 「外部依赖」= `initiatives.Artifact`

- 模型：`server/initiatives/models/artifact.py` — `ArtifactType`（key/name/carrier/**ragable**/enabled）+ `Artifact`（**project** FK / type FK / carrier / title / **url** 飞书外链 / **content_ref** markdown 或仓库文件引用 / version / contributor）。
- 载体 `ArtifactCarrier`：`feishu_doc` / `feishu_bitable` / `external_link` / `markdown` / `repo_file`。
- 内置 8 类（`migrations/0004_seed_artifact_types.py`）：需求文档、feature list、研发 Spec、UI 稿（external_link，**ragable=False**）、UI 评审、埋点文档、埋点评审、复盘。
- 写入唯一入口：`services/artifact_service.py`（INV-6）。
- REST：`/api/projects/{id}/artifacts/`（List/Create/Detail）+ `.../artifacts/{id}/view/`（在线查看 → `artifact_view.py`：feishu_doc 拉正文转 markdown / markdown 直返 / external_link 仅跳转）。
- 前端：`web/src/api/artifacts.ts`；展示在 `web/src/components/project/workbench/DependenciesSection.vue`（作战室 `ProjectMaterialsPanel` 复用），已有「查看（markdown 弹窗）」「飞书打开」按钮。

### 1.2 「知识」区 = `/knowledge` 页（4 Tab）

- 路由/页面：`web/src/pages/knowledge/index.vue`，Tab = `overview | tree | ingest | search`；侧栏入口 `AppSidebar.vue`（label「知识」）。
- **overview** → `KnowledgeDashboard.vue`：仓库/域指标、3D 星图、词云、Fuse.js 即时搜索（前端聚合各仓 `ai_summary_tree`）。
- **tree** → `KnowledgeTreePanel.vue`：**PageIndex 能力树**（业务域 `DomainNode` → 仓库 → `sub_app/module/capability`），来自 `Repository.ai_summary_tree` + `CorpusTreeSnapshot`；节点向量在 Qdrant `repo_index_nodes`。
- **search**（内联）→ `knowledgeApi.searchDeliveryKnowledge` → `GET /api/knowledge/search/` → `DeliveryKnowledgeSearchService`（Qdrant `delivery_knowledge` hybrid 向量）。
- 实体详情：`pages/knowledge/entities/[id].vue`（`KnowledgeEntity` 元数据/版本时间线/关联图）。

### 1.3 两套「图」（勿混）

| 名称 | 入口 | 持久化 | 用途 |
|------|------|--------|------|
| 项目关系星图 ProjectGalaxy | `_build_project_galaxy` / `ProjectGalaxyView` | 否（读时聚合） | 作战室：project↔feature↔work_item↔MR↔repo |
| 交付知识图谱 | `ProjectKnowledgeGraphService` + `knowledge/graph_store.py` | 是（`KnowledgeEntity`+`KnowledgeEdge`） | project↔知识实体↔repo/space |
| 代码 Galaxy | `codegraph/galaxy` | 是 | 符号/API/调用关系 |

- `KnowledgeEntity.kind`：work_item / tech_plan / code_change / **document** / project / repository / space。
- `KnowledgeEdge.relation`：HAS_PLAN / IMPLEMENTED_BY / **REFERENCES** / **RELATES_TO** / DUPLICATE_OF / MODIFIES_CHUNK（bi-temporal 边，带 `metadata` JSON）。

### 1.4 关键词 / 业务能力（无独立实体）

- **关键词** = 能力树节点 JSON 字段 `keywords: string[]`（`Repository.ai_summary_tree`，`tree_schema.py`）；由 AI 仓库摘要任务产生（`repositories/summary_service.py` → `subagent/api/callbacks.py`）；进 Qdrant `repo_index_nodes` embedding 文本。另有 `FacetVocabulary` 仓库级分面标签。
- **业务能力** = 能力树 `node_type=capability` 叶子（`sub_app→module→capability`），存 `ai_summary_tree`；选仓时 `RepoAssociation.matched_node_paths` 记命中路径。
- **无 `Keyword` / `Capability` 表**。

### 1.5 关联现状

- 项目↔仓库：`RepoAssociation`（AI 选仓 `RepoRouterV2` + 确认/验证，状态 proposed→confirmed→verifying→verified|rejected；带 score/confidence/`matched_node_paths`）；`ProjectBranch`（分支绑定）。
- 工件↔项目：`Artifact.project` FK + 摄取时建 `KnowledgeEdge(REFERENCES → project 节点)`（`knowledge/sources/artifact.py`）。
- **缺口**：工件↔仓库无边；工件↔能力/关键词零关联；`_build_project_galaxy` 不含 artifact、关联仓库仅来自 MR（不读 RepoAssociation）；`link_repository` 有方法但未被业务调用。

### 1.6 摄取与检索链路（复用点）

- 摄取：`ArtifactService._maybe_schedule_ingestion`（ragable + 文字载体）→ `aschedule_ingestion(source_kind="artifact")` → `knowledge/sources/artifact.py` normalizer → `KnowledgeEntity(document)` + chunk/embed → PG + Qdrant `delivery_knowledge`。
- Normalizer 注册表：`knowledge/sources/__init__.py`（已含 `artifact`）。
- 向量 payload 索引字段：`entity_kind/entity_id/version/is_latest/project_id/repository_id/source_kind/event_time`（`collection.py`）。
- 检索收口：`DeliveryKnowledgeSearchService`（`retrieval.py`）+ `vector_recall.py`（hybrid dense+sparse RRF，强制 is_latest + 权限 filter）。
- 项目内关键词搜索：`ProjectSearchService._keyword_search`（已 grep `Artifact.title/content_ref`）+ 向量兜底。

## 2. 架构决策（本里程碑锁定）

1. **外部依赖复用 `Artifact`**，不新建模型。
2. **「总览」指知识页 `KnowledgeDashboard`**（用户已确认）。
3. **知识树接入 = 并行「交付文档」树**（项目→类型→工件），不进 PageIndex 能力树。理由：能力树代码派生、语义是「仓库能做什么」；外部文档是「项目交付了什么」，两者混用会互相污染，且能力树重建会冲掉外部节点。
4. **关联复用 `RepoRouterV2` + `RepoAssociation`**：
   - 工件↔仓库/能力：对 ragable 工件正文跑 `RepoRouterV2.route()` → matched repo + `matched_node_paths` + keywords，落 `KnowledgeEdge(RELATES_TO)` + `metadata`。
   - 项目↔仓库：verified `RepoAssociation` 同步为图谱边（扩展 `sync_relations_from_operational`），单向派生、`RepoAssociation` 仍是真相源。
   - 关键词/能力**不建实体表**，用边 metadata 承载（v2 再评估升级为一等实体 KDEPX-01）。
5. **可检索性无遗漏**：非 ragable 类型（UI 稿）无正文可 embed → 至少登记标题/类型/链接进关键词层，保证搜索/总览/树都能看到全部类型。
6. **展示层**：`_build_project_galaxy` + 知识实体图 + 实体详情 + 作战室外部依赖区 打通双向交叉入口。

## 4. 风险 / 待 discuss-phase 细化

- 跨项目聚合的知识树/搜索**权限过滤**必须走 `knowledge/access_scope.py`，避免越权可见他项目文档。
- `RepoRouterV2` 对「文档正文」（非需求短文本）路由的召回质量需实测；fail-soft 回退（无匹配则只建 project 边）。
- 非 ragable（UI 稿）无正文 → 关键词层仅 title/type/url，搜索命中弱，属预期。
- delivery_knowledge 已有 artifact 文档实体；本里程碑主要**加边 + 加视图 + 加呈现**，尽量不改向量 schema（只用 `metadata`/edge）。
- 星图/树节点上限保护（`max_nodes`）沿用，跨项目聚合需分页/截断。
